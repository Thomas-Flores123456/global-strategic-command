# （必看）编写世界书时的优化技巧

> 一句话总纲：**世界书的敌人不是"内容多"，而是"递归失控"。**
> 目标是让世界书做到"**讨论什么，就注入什么**"——玩家/叙事提到的对象精确出场，无关内容全程沉默。
>
> 本文把一套经本项目实测验证的技巧沉淀下来，供后续编写任何世界书（新阵营、新世界、新战役）时直接复用。宿主基准：**SillyTavern 1.18.0**。

---

## 〇、先建立三个正确认知

1. **仓库容量 ≠ 单轮开销。**
   "全库有多少 token" 是磁盘/加载概念；"每轮实际注入多少 token" 才是影响体验和费用的数。一本 300K 的大书，配置得当，单轮可能只注入 20K。**永远盯单轮开销，不要被总容量吓到。**

2. **递归瀑布是头号杀手。**
   世界书条目可以通过"正文里出现另一条目的关键词"来互相激活（递归）。若不加约束，一个种子能在 6~8 轮内点亮几乎整个库——这就是"瀑布"。本项目未优化时，任意一句话能激活 234 条、烧 64K+ token。

3. **信息完整性 ≠ 全部塞进去。**
   决策所需的信息（"造这个要什么前置"）应当**内联写进条目正文**，而不是依赖递归去别处拼。递归只负责补充"额外背景"。把依赖内联，就能在极浅的递归深度下达到信息完整，同时大幅省 token。

## 一、SillyTavern 激活机制速查（原理层）

| 机制 | 作用 | 关键坑 / 要点 |
| --- | --- | --- |
| **Recursive Scan（全局开关）** | 是否允许条目互相激活 | 关掉则跨条目联动全断，世界失去连接感；一般保持开 |
| **Max Recursion Steps（全局）** | 限制递归轮数。**实际递归轮数 = N−1** | `0`=只受 budget 限制（近乎无限，瀑布根源）；`1`=关递归；`2`=递归1轮；`3`=递归2轮。与 Min Activations **互斥** |
| **excludeRecursion（条目·"不可被递归"/Non-recursable）** | 该条目**不会被其他条目勾出**，但仍能被聊天正文直接命中 | ★最有用的降瀑布开关。让"名词类"条目只由点名激活 |
| **preventRecursion（条目·"阻止继续递归"）** | 该条目被激活后**不再去勾别的** | 掐断链式传播；总则/科技树类适用 |
| **delayUntilRecursion + Recursion Level（条目）** | 该条目只在递归阶段才可能激活；Level 分层揭示 | 适合"背景色/深层细节"分层放出；配置较复杂 |
| **constant（条目·常驻/蓝灯）** | 每轮固定注入（受 budget 限制） | 每条常驻都是"每轮固定开销"，**严格控量**，只放全局铁律 |
| **order（插入顺序/优先级）** | 决定注入顺序；**budget 触顶时 order 大者优先存活** | 用来做"存活分诊"：核心法则给高 order，边缘型号给低 order |
| **budget（token 预算上限）** | 世界书总注入的 token 天花板，触顶后停止 | **最终硬闸门**。单位可能是 Context% 或固定 token，务必真机确认 |
| **matchWholeWords / caseSensitive（条目）** | 全词匹配 / 大小写敏感 | 默认继承全局，易漂移；建议每条**显式钉死为 false** |
| **Inclusion Group（包含组）** | 同组内按优先级只保留一个 | 适合"多个互斥变体只出其一"的场景 |
| **Scan Depth（全局）** | 扫描最近几条聊天消息找关键词 | 越大命中面越大；与递归是两回事 |

### 匹配陷阱（ST 1.18.0 源码实证，务必牢记）

- **`matchWholeWords` 的实现是 `(?:^|\W)key(?:$|\W)`，不是 `\b`。**
- **纯中文 key 勾选"全词匹配"≈ 子串匹配**（中文字符对 `\W` 的行为所致）——所以中文 key 不必纠结这个开关。
- **中文 key 紧邻英数字符时，勾选全词匹配反而会 MISS。**
- **裸单字母 / 极短 ASCII key 是灾难**：key = `"R"` 会子串命中所有含大写 R 的英文 key/正文；`M3` 会命中 `XM30`。本项目真出现过 B-21 条目 key 混入裸 `"R"`，是全库最脏的瀑布导线。
- **正则形式 key `"/.../"` 无视条目级匹配开关**，是唯一的 key 级精确通道。需要"M3 但不含 XM30"时，用 `"/\\bM3\\b/i"`。
- **budget 触顶时，`order` 大者优先存活**（这就是 order 分带的依据）。

## 二、怎么诊断（先看清病灶，再下刀）

不要凭感觉优化。先用脚本量出以下几张"体检表"（可复用脚本见第六节）：

1. **分层激活模拟**：给一个种子，模拟层0/层1/层2… 的累计激活条数，找"拐点"——哪一层之后新增的都是无关条目。
2. **token 分层曲线**：每个 `Max Recursion Steps` 值对应多少 token，直接看哪档达标。
3. **扇出分析（谁带头刷屏）**：哪些条目一激活就勾出一大片（通常是科技树、总览、总则）。
4. **扇入分析（谁是黑洞）**：哪些条目被反复勾中（通常是"总则#0""机娘法则"这类被到处引用的）。
5. **各书体量 + 书内耦合度**：哪本书最大、哪本书内部条目互相勾得最凶（耦合度高=一激活就整本炸）。
6. **组合式场景测试（关键）**：**别用"生产一辆X"这种单点种子**——实战里一段话会同时点名一堆对象（且 ST 扫最近数条消息）。要造"装甲突击规划""全域总攻"这类多对象文段，才测得出真实峰值。

> 本项目经验：单点种子 s=3 约 30–39K，但换成组合文段直接 38–57K。**必须按组合场景判断。**

## 三、优化技巧库（按威力排序，★越多越关键）

### 技巧 1 ★★★★★ 名词类条目"叶子化"（excludeRecursion=true）

**最大杀器。** 把所有"精确名词类"条目（武器型号、装备、角色个体、建筑设施）设为 `excludeRecursion=true`，含义是"**只由聊天正文直接点名激活，不被其他条目递归勾出**"。

- **原理**：型号/角色是精确名词，玩家提到哪个就该出哪个。它们之间的"血脉链"（M1E3 提到"灰熊"→勾出灰熊→灰熊再勾别的）是纯背景噪音，应当掐断。
- **前提**：把依赖内联（见技巧 5），这样掐断递归也不丢决策信息。
- **实测**：本项目给武备书 129 型号 + 8 机娘个体叶子化后，极限总攻场景 **56.8K → 25.6K（−55%）**，全场景 ≤26K。
- **两档选择**：
  - `exclude` 不加 prevent（**推荐**）：型号仍能"向上"勾出核心法则/通则（保留世界观锚定），损失最小。
  - `exclude + prevent`（完全叶子）：更省，但型号出场时连核心法则都不带，信息略孤立。

### 技巧 2 ★★★★ 参考手册/科技树/总则设 exclude 或 prevent

"科技树总览""XX线总则""设定手册"这类**长条目**是扇出重灾区。

- 设 `excludeRecursion`：它们只在玩家**专门问起**（直接命中）时出现，不会因为提一句型号就被拖出来。
- 或设 `preventRecursion`：允许被勾出，但它自己不再往下勾。
- 判断：这条目是"被查阅的手册"还是"必须随型号出场的说明"？前者 exclude，后者留着但可 prevent。

### 技巧 3 ★★★ 核心法则"保留可被勾出"（反向操作）

少数几条真正的全局铁律（如"首台机娘法则""机娘通则"），**故意不隔离**（exclude=false），让型号提到相关词时能把它带出来——这是有意义的世界观锚定。配合技巧 1 的"exclude 不加 prevent"，型号→法则的向上链路得以保留。
> 原则：**隔离"手册"，保留"宪法"。**

### 技巧 4 ★★★★ 清除泛词短 key 与裸字母

逐条审查 key，删掉/收紧这些：

- **功能泛词**（防御/侦察/压制/态势/口径/两栖…）——会被大量正文子串命中，制造瀑布。
- **裸单字母 / 极短 ASCII**（R / M3 / M6…）——见"匹配陷阱"。裸字母直接删；`M3` 这类改正则 `"/\\bM3\\b/i"`。
- **保留**：人名、型号专名/昵称（伯克、黑鹰）、够独特的设定词、铁律核心词（首台、舰娘）。

### 技巧 5 ★★★★ 内容局部性——把依赖"内联"进正文

每个条目的正文应当**自包含**决策所需信息：

- 型号条目里直接写清"前置：XX工学（前置YY工学）+ ZZ已产"。
- 这样即使递归被掐断（技巧 1/2），LLM 读单条就知道完整前置链，**信息完整性不依赖递归**。
- 反例：把前置拆去别的条目、靠递归拼——既脆弱又费 token。

### 技巧 6 ★★★ order 分带（存活分诊）

给不同层级的条目分配"千位分带"的 order，让 budget 触顶时**核心优先存活**：

```txt
90000 核心法则   80000 角色模板   70000 角色个体
60000 武备型号   50000 科技/总则   40000 建筑设施   30000 剧情
```

同带内用 ±10 步进微调。这样极端场景被截断时，砍掉的是边缘型号，保住的是法则和当前主角。

### 技巧 7 ★★★ budget 硬顶（最终闸门）

无论前面做得多好，都要设一个明确的 budget 上限兜底。它配合 order 分带，构成"belt-and-suspenders"。

- 参考值：128K 上下文模型 → budget ~40K；32K 模型 → ~15–20K。
- **budget 才是真正决定每轮注入量的旋钮，比 recursion steps 更硬。**

### 技巧 8 ★★★ Max Recursion Steps = 3（护栏）

在条目级控制（技巧 1–2）已到位的前提下，全局设 `3`（递归2轮）作为护栏：

- 覆盖最深的真实依赖链（如 F-47→F-22→F-16 三跳）的因果邻域。
- 挡住任何漏网 key 碰撞的深层扩散。
- 别用 `0`（无限=瀑布），一般也别用 `1`（全关=断联动）。

### 技巧 9 ★★ 显式钉死 matchWholeWords / caseSensitive = false

全库每条显式写死，消除对"全局设置"的隐式依赖，避免换环境时行为漂移。中文 key 保持子串匹配（见匹配陷阱）。

### 技巧 10 ★★ 高耦合书降瀑布

若某本书"内部条目互相勾得极凶"（书内耦合度高，一激活就整本亮），针对性给其内部条目加 `preventRecursion`，或考虑拆书/降低互相引用。

### 技巧 11 ★（可选）背景色分离

把"纯背景描写"（伪装辞典、角色人设色）拆成独立的 `delayUntilRecursion` 条目，深层才放出。
> 注意：本项目实测这类"背景行"只占正文 ~3%，**单独做性价比低**；除非它本就要为"多世界/多阵营解耦"而迁走（那时顺手做），否则不必专门为省 token 去拆。

## 四、本项目实测数据（实证参考）

**递归瀑布（未优化）**：任意种子 6–8 轮点亮 234 条 ≈ 64K+ token；`Max Recursion Steps=0`。

**E7 结构化四批的收益**：

- a 批（37 条 prevent + 37 条手册 exclude + 补齐缺失字段）：瀑布 234 → 170（−27%）
- b 批（全库 mww/cs 钉死 false）：消除全局漂移
- d 批（删 ~52 泛词 key + 裸 R + M3/M6 正则化）：清除病态命中，累计 −29.5%
- c 批（243 条 order 分带）：建立存活分诊

**E7e 型号叶子化（决定性一招）**：

| 组合场景 s=3 | 叶子化前 | 叶子化后 |
| --- | --- | --- |
| 装甲突击规划 | 39.7K | **14.1K** |
| 陆海空协同 | 46.1K | **18.6K** |
| 多机娘剧情 | 45.0K | **18.2K** |
| 全域总攻(极限) | 56.8K | **25.6K** |

**递归深度对照（叶子化后现状）**：s=2 约 11–21K；s=3 约 14–26K；全场景稳定 ≤35K。

**多阵营外推（叶子化把成本从"乘法"降成"加法"）**：

- 仓库总容量：5 阵营 ≈ 300K（静态，非每轮开销）。
- 单轮开销按"参战阵营数"计费：**单阵营战役 ~25K（其他阵营存在不影响）／双阵营交战 ~36K／三方混战 ~48K**。
- 若无叶子化，5 阵营型号互相递归会朝 300K 全库狂奔，多阵营根本无法运行。

## 五、推荐配置组合（拿来即用）

**条目级：**

- [ ] 名词类（型号/装备/角色/设施）→ `excludeRecursion=true`（叶子化）
- [ ] 手册/科技树/总览 → `excludeRecursion` 或 `preventRecursion`
- [ ] 核心法则/通则 → **保留不隔离**（可被勾出）
- [ ] 全库 `matchWholeWords=false`、`caseSensitive=false` 显式钉死
- [ ] 清除泛词短 key、裸字母；`M3/M6` 类改正则
- [ ] order 千位分带（法则 90000 → 剧情 30000）
- [ ] constant 严格控量（只放全局铁律）
- [ ] 依赖内联进正文（信息局部性）

**全局级：**

- [ ] Recursive Scan：ON
- [ ] Max Recursion Steps：**3**
- [ ] Budget：按上下文定硬顶（128K→~40K；32K→~15–20K）
- [ ] Scan Depth：适中（如 2–4）

## 六、可复用诊断脚本（分层激活 + token 模拟）

放到世界书目录下 `node 该脚本.mjs` 即可。按需改 `seeds` 为你的组合场景文段。

```js
import fs from 'node:fs';
import path from 'node:path';
const dir = process.argv[2] || '.';
const files = fs.readdirSync(dir).filter(f => f.endsWith('_世界书.json')); // 按需排除排他世界适配书
const estTokens = s => { let t = 0; for (const ch of s) t += /[\u4e00-\u9fff\u3000-\u303f\uff00-\uffef\u3040-\u30ff]/.test(ch) ? 1 : 0.3; return t; };
// 酒馆环境中 <数据> 块与 *系统映射* 行会被正则精准拦截，不进入最终组装的 LLM Prompt，故计算 Prompt 净 Token 时予以剥离
const stripIntercepted = s => (s || '').replace(/<数据>[\s\S]*?<\/数据>/g, '').replace(/^\s*\*?系统映射[：:][^\r\n]*$/gm, '').trim();
const E = [];
for (const f of files) {
  const data = JSON.parse(fs.readFileSync(path.join(dir, f), 'utf8').replace(/^\uFEFF/, ''));
  for (const e of Object.values(data.entries)) {
    if (e.disable) continue;
    const netText = stripIntercepted(e.content || '');
    E.push({
      id: f.replace('_世界书.json', '') + '#' + e.uid, keys: e.key || [], raw: netText,
      lc: netText.toLowerCase(), constant: !!e.constant, prevent: !!e.preventRecursion,
      exclude: !!e.excludeRecursion, tok: estTokens(netText),
    });
  }
}
const hit = (e, raw, lc) => e.keys.some(k => {
  if (k.length > 2 && k.startsWith('/')) { const m = k.match(/^\/(.*)\/([a-z]*)$/); if (m) { try { return new RegExp(m[1], m[2]).test(raw); } catch { return false; } } }
  return lc.includes(k.toLowerCase());
});
function layers(seed, maxL = 8) {
  const act = new Set(); let pr = seed, pl = seed.toLowerCase(); const out = [];
  const push = arr => { for (const e of arr) { act.add(e.id); if (!e.prevent) { pr += '\n' + e.raw; pl += '\n' + e.lc; } } };
  const l0 = [];
  for (const e of E) if (e.constant) l0.push(e);
  for (const e of E) if (!act.has(e.id) && e.keys.length && !l0.includes(e) && hit(e, seed, seed.toLowerCase())) l0.push(e);
  push(l0); out.push(l0);
  let d = 0;
  while (d++ < maxL) {
    const nw = [];
    for (const e of E) { if (act.has(e.id) || !e.keys.length || e.exclude) continue; if (hit(e, pr, pl)) nw.push(e); }
    if (!nw.length) break; push(nw); out.push(nw);
  }
  return out;
}
// 换成你的"组合式场景"文段
const seeds = { '示例·多对象': '一段同时点名多个型号/研究/角色的实战文段……' };
for (const [n, s] of Object.entries(seeds)) {
  const L = layers(s); let acc = 0, cnt = 0; const row = [];
  for (const lay of L) { acc += lay.reduce((a, e) => a + e.tok, 0); cnt += lay.length; row.push(`${Math.round(acc)}t/${cnt}条`); }
  console.log(`【${n}】层累计(=steps1,2,3…): ${row.join('  ')}`);
}
```

> 说明：token 估算用"中日韩字≈1、其余≈0.3"，与真实分词器有 ±15% 偏差，够做预算判断；精确值以真机为准。

## 七、落地纪律（红线，务必遵守）

1. **先备份**：改动前把原文件复制为带时间戳的 `.bak`，并移出 `worldbooks/` 现行真源目录。无参数体检默认只扫描 `worldbooks/*_世界书.json`；备份仍建议命名为 `XXX_backup-日期.json.bak`（既不含“世界书”连缀又非 `.json` 结尾），避免显式递归扫描或其他工具误收。
2. **定点替换、不重排**：只改目标字段（如 `"excludeRecursion": false`→`true`），**逐字节保留原格式**（缩进/换行/BOM）。若"解析→重排→写回"的字节自检不通过，就**不要用重排**，改字符串定点替换。
3. **断言命中数**：替换前后统计目标出现次数，数目不符立即 ABORT（防误伤其他布尔字段）。
4. **每批体检**：跑 `校验世界书.mjs`（结构无阻断）+ `统计常驻.mjs`（常驻/总量在预期内）。
5. **静态测 ≠ 真机验收**：本文所有 token/激活数字都是**脚本静态模拟**。真实的激活/递归/budget 竞争行为**必须在真 SillyTavern 导入后验证**，且验收结论由人来定，自动化不得代判。
6. **保护清单**：与并行工程（如 MVU）共享目录时，明确哪些书**不可动**，全程绕开。

## 八、给未来扩展的一句话

**"红警指挥系统是常量，阵营/世界是变量。"**
把跨阵营/跨世界共享的"底座"（类别总则、机娘通则、基地布局、暴露分级）下沉为共享书，把阵营/世界专属的型号做成叶子化名词条目——扩展成本就从"乘法"变成"加法"，多阵营、多世界才跑得起来。这套优化不是一次性调参，而是**面向长期扩展的地基**。

> 📎 相关设计：**多阵营 token 模型**（仓库容量 ~300K；单轮开销按参战阵营数计费——单阵营 ~25K／双阵营交战 ~36K／三方混战 ~48K）与"共享底座下沉"的架构决策，见 **《T2扩展设计案.md》方向④·多世界适配**。本文讲"怎么做"（优化技巧），那边记"为什么这么定"（架构决策），两处配套阅读。
