## 〇、为什么必须立此规范（病灶复盘）

在以往的自动化管线中，世界书条目演变为高度模板化的“规格记录卡”：

```text
kind=personnel；tier=T1。组织化人员梯次，非廉价生命值/可牺牲属性（真源§2.1/§2.3）：短训防御……
分账：人口不等于合格兵；动员/补充有节奏……
前置：sov.research.t1.national_mobilization……
【key 说明】本叶 key 采用正则 /(?<!总)动员兵/……未过则转 E7 债。
```

这种文本在工程审计上能够 100% 通过（ID 闭环、字段合规），但**给 LLM 注入时会产生灾难性的负面效果**：

1. **风格污染（Few-shot Register Drift）**：LLM 会将这种“策划免责公文体”当成世界的真实语域，输出干瘪、生硬、毫无沉浸感的汇报式台词与旁白。
2. **管线内裤外穿（Pipeline Leaks）**：把“【key说明】”、“E7债”、“owner任务”、“未实现”等作者工作台的便签直接喂给模型，极易导致模型在生成剧情时把技术债词汇当成世界设定。
3. **上帝视角说教（Defensive Preachiness）**：满篇“不是廉价生命值”、“需要始终记住”、“不等于自动生效”，将系统规则写成了防 AI 钻空子的训诫标语。
4. **同人黑话出戏（Meta-Jargon）**：出现“现实锚点”、“生态位转译”、“架空工程实物化”等网文考据黑话，严重破坏第四面墙。

**规范一句话总纲**：
> **世界书的正文是写给模型读的“世界内严肃历史与技术档案”，不是策划防作弊的免责声明，更不是开发团队的内部工单。**

## 一、文风四大铁律（Style Invariants）

### 1. 世界内严肃语域（Diegetic Register）

- 正文必须统一采用**冷战军事实体档案体、总参谋部条令体或国家重工业技术备忘录体**。
- 叙述者是世界内部客观、严谨、冷峻的高级档案员或参谋机构，具备统一的世界内自洽性。
- 严禁出现第二人称说教（“你必须注意”、“需要始终记住”）。

### 2. 严禁管线元语言（Zero Meta-Language）

正文中**绝对禁止**包含以下任何内容：

- **开发便签**：禁止出现“E7债”、“待真机验证”、“owner任务”、“接收端未实现”、“未来规划”。此类信息只许保留在条目的 `comment` 字段或工程任务包内。
- **正则与 Key 解释**：禁止在正文解释 key 的正则设计理由（如“为防误触采用 lookbehind”）。
- **文档章节回引**：禁止在正文中保留“（真源§2.1）”、“详见建筑书 BLD-02”等对现实 Markdown 文件的引用。条目必须具备内容自包含性。
- **设计黑话**：禁止出现“现实锚点”、“生态位”、“架空实物化”、“T1电力语言”、“不叠加百分比增益”等游戏策划术语。

### 3. 因果化融入约束（Causal Constraints）

- 原条目中的“核心限制”、“分账铁律”、“前置门槛”，**必须 1:1 完整保留，但必须转化为世界内部的因果逻辑与现实代价**。
- **反例（策划免责）**：`分账：人口不等于合格兵；严禁随意当炮灰。`
- **正例（条令因果）**：`动员体制将动员兵作为定额后勤资产管理，伤亡须由动员中心依后备名册逐批回补；基层军官与技术兵种属于独立培养序列，无法通过扩大动员兵规模凭空折算。`

### 4. 机器契约底线收容（System Mapping Separation）

为了保证跨书 Stable ID、拓扑前置与未来 MVU 运行时的机器解析，**所有机器字段一律压缩至条目末尾的独立行**，与上方自然文学正文严格隔离：

```text
[特色科技·苏联 | 宽轨重载军运学]
……（这里是高质感的自然段落正文，详见样本）……

*系统映射：研究 | tier=T1 | 前置: sov.research.t1.national_mobilization ＋ ext.tech.common.logistics | 解锁: sov.module.logistics.strategic_rail_mobilization*
```

## 二、受控质感规则（Controlled Texture Rule）

为了让文本具有“人类自然语言的重量感与机械美感”，同时严守**0 臆造、0 数值漂移**的工程纪律，全体 Agent 必须严格遵守以下口径：

### 1. 允许引入的受控细节（Allowed）

允许补充**无机制含义的物理、工艺、材料、环境与操作常识**，包括：

- **工程与工艺细节**：如“1520毫米标准宽轨”、“厚装甲埋弧自动焊”、“百吨级行车吊车”、“高压外露母线排”、“重油与天然气物流管线”。
- **单兵与生活质感**：如“战壕积雪”、“标准化步兵轻武器”、“后备役兵籍核对”、“连排军官压阵”。
- **操作与故障表现**：如“柴油机排气轰鸣”、“高负荷瞬时过载跳闸”、“泥泞公路转运降级”。
- **来源要求**：所有补充细节必须符合真源设定的阵营基调，或严格基于现实工业/冷战军事公开常识。

### 2. 绝对禁止臆造的机制要素（Prohibited）

**绝对禁止**擅自增加任何具备游戏/数值平衡属性的要素：

- **禁止臆造数值**：造价、吨位、有效射程、航程、发电机功率、冷却时间、建造工期等（**只要真源没写精确数字，正文绝不得擅自发明数字**）。
- **禁止臆造型号专名**：不得自行发明未在真源中出现过的武器改型代号、厂所编号、历史人物真名。
- **禁止臆造编制规模**：不得擅自设定未定义编制（如将未注明的“编队”擅自写成“每师三团制”）。

### 3. 交付时的“质感增量对账清单”（Audit Disclosure）

后续任何 Agent 在交付改写或新写批次时，必须在回执中附带**《质感细节对账表》**，列出本批补充了哪些常识性细节，供驾驶员抽审与一票否决。

## 三、四步写作标准法（The 4-Step Protocol）

编写或翻修任一世界书条目时，必须严格执行以下四步：

```text
[第 1 步：提取事实清单]  从设计真源或原条目中提炼出：核心职能、限制代价、分账要点、前置/解锁 ID
           ↓
[第 2 步：档案体撰写]    以世界内冷峻军工档案语域撰写 2～3 段自然文字，将限制无缝织入因果叙述
           ↓
[第 3 步：收容系统映射]  在正文末尾附上规范的 `*系统映射：...*` 紧凑行
           ↓
[第 4 步：双重闭环对账]  核对事实 1:1 未丢失 ＋ 核对未引入非法数值 ＋ 朗读测试（读起来必须像人类写的档案）
```

## 五、验收与 Reviewer 审查核对表（Checklist）

任何涉及条目改写或新建的 PR/交付，Reviewer 与主 Agent 必须逐项核对：

- [ ] **1. 非 `content` 字段 0 变更**：`uid`、`key`、`order`、`depth`、`selective`、`preventRecursion` 等 32 项控制字段完全未变。
- [ ] **2. 机器 Stable ID 0 丢失**：所有原有的 `sov.*`、`ext.*`、`pool.*` 稳定 ID 完整存在于 `*系统映射：...*` 行中，跨书检索无悬空。
- [ ] **3. 管线黑话 0 残留**：全文不含 `【key 说明】`、`E7`、`owner`、`接收端`、`真源§`、`现实锚点`、`生态位` 等词汇。
- [ ] **4. 说教式否定句 0 残留**：不含“需要始终记住”、“不是廉价生命值”、“不等于”等策划防御式排比。
- [ ] **5. 非法数值 0 臆造**：无真源背书的造价、吨位、射程、产能数值为 0。
- [ ] **6. 驾驶员朗读通过**：文字读来具备工业冷峻质感与严密因果逻辑，无生硬断句，无机器拼凑感。
