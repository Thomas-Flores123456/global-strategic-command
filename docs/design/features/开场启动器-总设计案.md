# 开场启动器 · 总设计案

> 项目 ID: launcher · 版本 v1.0 · 2026-09-01 脑暴冻结
> 蓝图档位: single-blueprint · 宿主: SillyTavern 1.18.0 + 酒馆助手 (TavernHelper/JS-Slash-Runner)
> 关联项目: mvu指挥系统（同仓库）· MVU 协议（四批已验收）

---

## 1 · 目标

为"红警系统·测试"角色卡提供**独立的开局配置界面**：玩家选择难度、阵营、部署地点、人设等，确认后一键组装首条消息并触发 AI 回复，无缝进入指挥系统主循环。

## 2 · 非目标

- 不做多世界适配书内容（由另一 Agent 出改造方案，本项目只留 worldId 接口位）
- 不改 schema.ts / parsePipeline.ts / useParse.ts / systemCheck.ts 已验收代码
- 不做持久自定义提示词（作者注释/常驻条目）
- 不做苏军/第三阵营真实科技内容
- 不做地图美术/日历轮盘等重 UI
- 不做 fetch API 聊天列表导入

## 3 · 项目类型与承载面

```yaml
type: independent-launcher-frontend
hosting: same-repo-multi-entry（共享 schema 唯一真源）
fit: suitable
reason: 范围超出指挥系统内部模式；社区惯例成熟；共享 schema 防双源漂移
```

### 工程结构

```
mvu指挥系统/
  src/
    红警指挥系统/     ← 现有指挥系统（不动）
    开场启动器/       ← 新入口
      main.ts
      App.vue
      steps/          ← 步骤组件
      pipeline/       ← 组装线

  dist/

    开场启动器/       ← 新产物
```

vite.config.ts 加第二入口，build 输出两个独立 HTML。

## 4 · 双正则辖区

| 正则 | find | tag 判定 | 加载目标 |
|---|---|---|---|
| 启动器 | 匹配 `<launcher>` 开头 | `<launcher>` | `dist/开场启动器/index.html` |
| 状态栏-实时修改 | 匹配 `<StatusPlaceHolderImpl/>` | `<StatusPlaceHolderImpl/>` | `dist/红警指挥系统/index.html`（现有） |

- 楼 0（first_mes）写为 `<launcher>` 开头 → 渲染启动器
- AI 回楼/后续楼正文不含 `<launcher>` → 渲染指挥系统
- 两条正则 placement 均为 markdownOnly，互不侵入 prompt

## 5 · `$boot` 状态机

```
message_id === 0 && !$boot.confirmed  →  渲染启动器向导
$boot.confirmed === true              →  渲染指挥系统（或空壳，楼0无需再展示）
```

`$boot` 为 chat 域 `$` 前缀变量：
```ts
$boot = {
  confirmed: boolean,
  preset: string,          // 'easy' | 'normal' | 'hard' | 'custom'
  choices: { ... },        // 用户选择快照（资金/科技/地点/日期/阵营/叙事基调）
  personaId: string|null,  // 应用的 persona id
  importedFrom: string|null, // 导入源标识
  confirmedAt: string       // ISO 时间戳
}
```

## 6 · 向导步骤流

线性四步，不做花哨路由：

### Step 1 · 战略身份
- **阵营**：盟军（默认选中）· 苏军（灰显"即将开放"）· 第三阵营（灰显预留）
  - 选中阵营展示徽章 + 一段势力简介
- **部署地点**：北坡 / 云溪（文本卡片选择）
  - 每地点附风味描述（"三面环山，天然屏障" / "水网密布，隐蔽但补给困难"）
- **开局日期**：默认"秋·九月初一"，文本输入可改

### Step 2 · 战略资源
- **难度预设**：

  | 档位 | 资金 | 初始科技 | 暴露度 | 叙事指令种子 |
  |---|---|---|---|---|
  | 简单 | 3000 | 最初级电力 + 一项自选 T1 | 0 | "资源充裕，威胁保守" |
  | 正常 | 2000 | 最初级电力 | 0 | "标准态势" |
  | 困难 | 1200 | 无 | 0 | "资源紧张，敌情主动" |
  | 自定义 | 滑块 | 多选列表 | 滑块 0-10 | 自填文本 |

- 自定义展开时，科技多选列表从 catalog 权威名单取（共享 effectiveCatalogNames）

### Step 3 · 指挥官身份
- **人设来源**三路径：
  - 选现有 persona（`getPersonaNames()` 列表 + 点击预览 `getPersona(id).description`）
  - 创建新的（名字 + 描述文本域 → `createOrReplacePersona()`）
  - 跳过（酒馆默认 User）
- 切换/应用 persona 走 DOM 操作或 `triggerSlash('/persona 名字')`

### Step 4 · 导入与发射
- **导入存档**：粘贴框。粘入 JSON 后 Schema.parse 归一 → Step 1-2 自动回填（资金/地点/日期/科技/基地全部恢复）；解析失败红框提示
- **自定义提示词**：文本域（可空），随首条消息一次性发出
- **叙事基调**：下拉选择（军事简报风 / 日常温馨风 / 紧张潜入风 / 史诗序章风，默认军事简报）
- **发射按钮**：`[ 🚀 展开 MCV · 开始作战 ]`

## 7 · 组装线 (Launch Pipeline)

可插拔工序数组，每工序 `{ name, run(ctx), skip?(ctx) }`：

| # | 工序 | 职责 | skip 条件 |
|---|---|---|---|
| 1 | `writeStatData` | 归零态 + 用户选择合并 → `Schema.parse` → `updateVariablesWith` 写楼 0 stat_data | 永不 |
| 2 | `markBoot` | `$boot.confirmed = true` + 选择快照 + 时间戳 → `updateVariablesWith` 写 chat 域 | 永不 |
| 3 | `applyPersona` | `createOrReplacePersona()` + DOM/slash 切换 | 未选/未建人设 |
| 4 | `bindWorldBooks` | 按 worldId 绑/解绑世界书组 | **第一版始终 skip**（只有一套书组已绑好），接口留空位 |
| 5 | `composeAndSend` | 组装首条消息（设定摘要 + 叙事基调指令 + 自定义提示词）→ `createChatMessages([{role:'user', content}])` → `triggerSlash('/trigger')` | 永不 |

失败路径：
- 工序 3 失败 → toast 提示"人设应用失败，使用默认身份"，继续后续工序
- 工序 5 失败 → 停在错误态，按钮变"重试发射"，可重试（幂等：stat_data 已写不会重复写）

## 8 · 指挥系统侧配套

系统 tab (PanelSystem.vue) 新增按钮：**"导出存档到剪贴板"**
- `JSON.stringify({ stat_data, meta信息, 导出时间 })` → `navigator.clipboard.writeText`

## 9 · MCV、首台机娘与「零预设基地」铁律（Stage H / Stage I 升级冻结 · 2026-10-18）

- **三种开场切入模式（`OpeningEntryMode`）**：
  - `field_drop`（**战地直降·初抵待命**，默认）：指挥官与首发 MCV 刚刚抵达拟定部署区域隐蔽待命，MCV 尚未展开；
  - `pre_transmigration`（**原世界序章·穿越前夕**）：先从穿越前的原世界与系统初醒序幕切入，再过渡至异世界与 MCV 汇合；
  - `dormant_infiltration`（**异世潜行·待机觉醒**）：指挥官已在目标世界潜伏生活或立足，首轮激活红警系统并与隐蔽待命的 MCV 建立连接。
- **MCV 展开前零预设基地铁律（`bases: []`）**：
  - 无论选择何种开场切入模式，开局写入 `#0` 楼 `stat_data` 时一律设 `bases: []`（仅当导入存档继承已有基地时保留导入的 `bases`），拟定部署地点写入 `meta.location`；
  - 世界书《异能穿越模拟器v1.0》（`uid=28` `96·事件上报与态势规约`）、启动器 `buildStatData` / `composeLaunchMessage`、以及解析/部署引擎（`parsePipeline.ts` + `mcvDeploymentEngine.ts`）三端共同强制执行：仅在指挥官明确下令展开 MCV 且 `<事件>` 上报 `类型: MCV展开` 时，才消耗车队中的 MCV 并创建首座基地（含阵营建造厂与 +50 发电）。
- **中控台（`CONSOLE`）双层沉浸门控契约**：
  - **第一层（未开局锁死态 `isPreLaunchLocked === true`）**：当 `$boot.confirmed !== true` 且尚无已推进楼层时，顶栏显示 `CONSOLE · PRE-LAUNCH · 待开局`，禁用顶栏四按钮与快捷三按钮，雷达屏显示 `待开局部署 // 待命锁定`，建造网格展示 `data-test="prelaunch-locked-panel"` 且 6 大页签计数全部为 `0`；
  - **第二层（已开局零基地 MCV 待命态 `isZeroBaseStandby === true`）**：当开局向导已发射确认（`bases: []` 且车队存有待命 MCV）时，解锁顶栏与快捷栏；雷达屏显示 `无在役基地 // MCV待命`、`拟定坐标：...` 与 `待展开 MCV`；建造网格以 `runtimeBasesActive = hasRuntimeBases.value || isZeroBaseStandby.value` 拦截全部静态建筑卡片泄露（6 大页签计数全部为 `0`），居中展示 `data-test="mcv-standby-panel"` 与 `data-test="deploy-mcv-btn"`（点击后按 `resolvePlannedDeploySiteName(snapshot)` 向宿主 `#send_textarea` 填入就地展开 MCV 的标准战术指令）。
- **具象世界·赛博朋克2077（`cyber2077`）**：
  - 作为启动器默认首选推荐的具象世界（挂载 63 条全景世界书《具象世界·赛博朋克2077》，含 `UID 122–129` 全球十大战区选址指南），提供 11 个全球可选部署区 + `custom` 自定义坐标、4 档时代锚点（`2042 / 2045 / 2069 / 2077`）以及三段式沉浸开场电文组装（`【世界时空与态势锚点】` + `【开场切入与统帅部署】` + `【首轮叙事演进要求】`）。

## 10 · 四态决策账本（冻结）

### Confirmed
- 独立前端 · 同仓库多入口共享 schema
- 双正则 tag 辖区（`<launcher>` / `<StatusPlaceHolderImpl/>`）
- `$boot` chat 域状态机
- 组装线可插拔架构
- 难度四档（简单 3000 / 正常 2000 / 困难 1200 / 自定义）
- 阵营盟军 + 灰显苏军/第三阵营预留
- 部署地点文本卡片选择
- 开局日期可编辑
- persona 三路径（选现有/创建新的/跳过）
- 叙事基调四选项
- 剪贴板导入（启动器粘贴）+ 导出（指挥系统按钮）
- 自定义提示词一次性
- MCV 自带首台机娘（AI 叙述诞生）
- 导入后自动回填 Step 1-2
- 发送走 `createChatMessages` + `triggerSlash('/trigger')`
- 世界书绑定工序留空位（第一版 skip）

### Rejected（含理由，防复活）
- 同 dist 内部模式（范围撑不下）
- 零机娘开局（MCV 就是首台机娘）
- schema 加 player 键（无程序追踪需求，纯叙事层足够）

### Growth Tracks
| 方向 | 触发条件 |
|---|---|
| 世界观选择 + 书组合绑定 | 另一 Agent 改造方案落地 |
| 地图选点部署 | 有美术资源/地图数据 |
| 初始情报种子 `intel[]` | 各世界情报条目写好 |
| 初始任务 `quests[]` | 任务系统设计定稿 |
| MCV 机娘预告氛围文本 | 首台法则条目定稿 + UI 打磨 |
| 苏军/第三阵营真实内容 | 对应 catalog + 世界书就绪 |
| "再来一局"种子记忆 | 多次开局真实需求 |
| fetch API 聊天列表导入 | 剪贴板路径验证稳定后 |
| 持久自定义提示词 | 有人要求"每轮都带的指令" |
| 日历/时节轮盘 UI | UI 打磨期 |

### Parking Lot
- schema v2 player 键
- localhost:5500 分发依赖解法
- 两条遗留可选正则（显示折叠/裁旧楼）
- 多前端路由表（三前端并存时 tag 自动补全）
