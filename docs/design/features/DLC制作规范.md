# DLC 制作规范

版本 1.1 · 对应前端核心 `CORE_VERSION 1.0`（批4 交付物；1.1 同步：原生 book 格式/数据卡/万能导入口/双步舞/schema kind 枚举）
上游设计：`DLC设计.md`（已批准）· 单一权威：`mvu指挥系统/src/红警指挥系统/dlcInstaller.ts` 与 `systemCheck.ts` 的实现——本文与代码冲突时以代码为准并修订本文。

样板：`../../../samples/dlc/DLC样板_欧盟.json`（v2.0.0 完整 faction 包+takeover，**样板即模板**，已过真机安装/takeover/卸载回滚全链路验证）· `../../../samples/dlc/DLC测试包_欧盟mini.json`（v0.3.0 最小冒烟载荷，仅验管道）。两包书名相同，**互斥安装**。

导入入口：状态栏系统页**万能导入口**（选文件/拖拽可多选，DLC 包与 ST 原生世界书 .json 混选自动嗅探分流：有 `dlc` 块→预检确认门；裸 `entries`→直接导书队列附 lint、可选绑卡、同名整本覆盖=重拖即更新）。裸世界书也可走酒馆原生导入按钮。

## 1. 包类型

| kind | 用途 | 典型内容 |
|---|---|---|
| `faction` | 新阵营 | faction 声明 + 特色科技 + 双书 + codex 阵营注册（必有 `data.faction`，特色科技书必含 MCV 铁律，缺一预检红） |
| `addon` | 支线内容 | 新建筑/单位/机娘模板等，不注册新阵营 |
| `patch` | 修改原生 | 世界书条目物理替换（自动备份、卸载回滚）；faction 包也可携带 patch 块（如 takeover） |

## 2. manifest 结构（双层）

**data 结构化层**给前端 overlay 与校验器；**worldbooks 文本层**给 AI 讲故事。两层必须一致（R8 查漂移）。

```jsonc
{
  "dlc": {
    "id": "eu-expedition",        // 必填，全局唯一，kebab-case
    "name": "欧盟远征体系",        // 必填，展示名
    "kind": "faction",            // 必填：faction | addon | patch
    "version": "1.0.0",           // 必填
    "requires": { "core": ">=1.0" } // 可选，仅支持 ">=X.Y"
  },
  "data": {
    "faction": {                  // faction 包必填
      "name": "欧盟",
      "mcv": "欧盟建造厂核心",     // 命名约定：{阵营}建造厂核心
      "lab": "欧盟战斗实验室",     // 命名约定：{阵营}战斗实验室
      "labResearch": null          // 建 lab 的前置理论名；无则 null（UI 显示"需{lab}（详见世界书）"）
    },
    "researches": [ /* ResearchDef，见 §3 */ ],
    "buildings":  [ /* BuildingDef */ ],
    "productions":[ /* ProductionDef */ ],
    "codex": [                    // 安装时写入 message 变量的种子（AI 可见）
                                  // kind 必须在枚举内：科技|建筑|载具|人员|装备|阵营|其他
                                  // （schema 对非法 kind 降级为'其他'——阵营注册写错 kind 即静默失效）
      { "name": "欧盟", "kind": "阵营", "desc": "…",
        "params": { "MCV": "欧盟建造厂核心", "实验室": "欧盟战斗实验室" } }
    ]
  },
  "patch": {
    "takeover": [                 // 主权移交（见 §6）
      { "from": "武备·盟军", "entries": ["78·欧盟陆地载具"], "to": "武备·欧盟" }
    ]
  },
  "worldbooks": [                 // ST 原生世界书导出体原样内嵌（§4）
    { "name": "特色科技·欧盟", "book": { "entries": { /* uid→条目，§4 格式 */ } } }
  ]
}
```

> `relations`（同盟关系结构化声明）为设计预留字段：**当前核心不解析**，阵营间关系暂以世界书文本表述（如武备书总则的 allied 声明）。

## 3. data 字段规范（校验器执行）

**ResearchDef**（科技）：

| 字段 | 必填 | 规则 |
|---|---|---|
| `name` | ✅ | 全局唯一（对 base 93 条+全部已装包查重，R4 红）；建议带阵营风味前缀 |
| `cost` | ✅ | 数值（R3 红） |
| `line` | ✅ | 命名约定 `{阵营}特色`——前端按 `endsWith('特色')` 判定阵营归属显示"需MCV在场" |
| `tier` | ✅ | 显式 1\|2\|3（R1 红）；有 T2 科技则 faction.lab 必须声明（R2 红）；T3 开放条件未定义，出现即红 |
| `eta` `desc` | 建议 | 缺失黄（R3 警） |
| `prereqs` | 建议 | 数组，引用**真实存在**的通用理论名（跨树组合前置）；`prereq` 为人读描述串 |
| `need_buildings` | 建议 | MCV 铁律的机器形态：特色科技必含 `{阵营}建造厂核心`；T2 另含 `{阵营}战斗实验室` |
| `unlocks` | 建议 | 人读解锁描述 |

**BuildingDef**：`name`/`cost` 必填；`power`（正=供电，负=耗电）、`research`、`prereqs`、`need_buildings`、`desc`。
**ProductionDef**：`name`/`cost` 必填；`need_building`（单数主描述）、`need_buildings`（数组）、`desc`。

## 4. worldbooks 层规范

**格式 = SillyTavern 原生世界书导出体**，整本原样内嵌（`book.entries` 为 uid→条目对象表，32 字段全集）——酒馆“导出世界书”得到什么就嵌什么，安装器 `importRawWorldbook` 零转换消费：

```jsonc
{ "name": "特色科技·欧盟",
  "book": { "entries": {
    "0": { "uid": 0, "comment": "01·总则",        // comment=条目名（takeover 按此匹配）
           "key": [], "constant": true,            // constant=蓝灯常驻；false+key=绿灯关键词
           "content": "[书名 | 分类]\n…", "disable": false /* 其余字段照 ST 导出原样 */ }
  } } }
```

制作方式：直接在酒馆里建书写内容 → 导出 .json → 把导出体整个填进 `book`。
**优雅降级**：`book` 本身就是标准导出体，可拆出存成独立 .json 交给玩家走酒馆原生导入按钮（或本前端万能导入口）手动装——DLC 管道不可用时内容不失效。

硬规则：
- **标头体例**：content 首行必须 `[书名 | 分类]`（R5 警）。
- **token 红线**：蓝灯常驻仅总则一条/书；其余全部绿灯。全包常驻 >10 条或 >8000 字触发 R9 警。
- **随机性红线**：禁止预告式剧透（"预告："/"未解锁不展开"等模式，R7 红）。只写已存在、已公布的内容；未解锁的东西一个字不提。
- **MCV 铁律**：faction 包的《特色科技·X》必须含 MCV/建造厂核心铁律表述（R6 红）。参考句式：
  > 铁律：特色科技的研究必须有{阵营}MCV（{阵营}建造厂核心）在场——特色理论依赖本阵营核心数据库的加密层，异阵营核心与纯通用设施无法替代。
- **双层一致**：data 里每个科技名应出现在包内某世界书文本中（R8 提示——数据卡会自动把 data 精确数值喂给 AI，文本层未提及不再致命，但叙事深度仍建议补齐）。

书名约定：`特色科技·{阵营}` / `武备·{阵营}`（体检的 R10 对账正则按此识别 DLC 书）。

## 5. 命名约定（前端动态发现依赖）

| 对象 | 约定 | 消费方 |
|---|---|---|
| MCV | `{阵营}建造厂核心` | useCatalog 建筑命名兜底：该名建筑出现即注册阵营 |
| 实验室 | `{阵营}战斗实验室` | 兜底注册时的 lab 推定名 |
| 科技线 | `{阵营}特色` | PanelTech 分线 + useDetail 归属行 |
| codex 阵营注册 | `kind:'阵营'` + params `MCV`/`实验室`（+可选 `实验室研究`） | factionDefs 三源合并第 3 源 |
| 科技名 | 全局唯一，建议阵营风味（如焚风"湍流××学"） | R4 查重 |

阵营注册优先级：内置三阵营（不可覆盖）→ `$dlc.faction` → codex `kind:'阵营'` → 建筑命名兜底。

## 6. takeover（主权移交）

用途：把寄档在他书的"影子分区"条目（如《武备·盟军》同盟国·欧盟三条）移交给本包的书。

- `entries` 按**条目名**（酒馆 comment，如 `"78·欧盟陆地载具"`）精确匹配。
- 安装时：原文自动备份进 `$dlc.{id}.backups` → 原条目改写为一行接管指引（含"原引进渠道保留"）→ 卸载时照备份精确还原。
- 原条目 **keys 不动**：聊到型号时命中"原书一行指引 + 新书完整档案"双条，语义正确（他阵营视角看到指引，本阵营视角看到主场档案）。
- 新书条目必须**继承被接管型号**（数值事实原样，叙述可转主场视角），否则接管语义不成立。
- 预检 R11 查 from 书存在性（酒馆内）；多包争抢同条目按安装序后者胜，体检报冲突。

## 7. 校验规则对照

| 规则 | 层 | 级别 | 内容 |
|---|---|---|---|
| REQ | 包 | 红/黄 | requires.core 版本；格式非 `>=X.Y` 降黄跳过 |
| R1 | data | 红 | tier 必须显式 1\|2\|3 |
| R2 | data | 红 | 层级门槛一致性：有 T2 无 lab 声明；出现 T3（条件未定义）；faction 包缺 data.faction |
| R3 | data | 红/黄 | 硬键值：name/cost/line 缺=红；desc/eta 缺=黄 |
| R4 | data | 红 | 科技名与 base/已装包重名 |
| R5 | 文本 | 黄 | 标头 `[书名 \| 分类]` 体例 |
| R6 | 文本 | 红 | faction 包特色科技书缺 MCV 铁律 |
| R7 | 文本 | 红 | 预告式剧透（随机性红线） |
| R8 | 跨层 | 提示 | data 科技名未出现在包内书文本（数据卡兜底后降为提示） |
| R9 | 文本 | 黄 | 常驻预算：蓝灯 >10 条或 >8000 字 |
| R10 | 运行 | 红/黄 | 同名书已存在非重装（装）；世界书↔$dlc 对账（体检） |
| R11 | 运行 | 红 | takeover 目标书/条目不存在 |
| R12 | data | 提示/红 | 覆盖 base 同名=提示（patch 行为）；多包同名=红 |
| R13 | 变量 | 黄/提示 | codex 结构缺参、tech.done 孤儿名 |

## 8. 存储与卸载（安装器行为，作者须知）

- 世界书本体 → 双步舞 `importRawBookRegistered`：先 `createOrReplaceWorldbook` 建空册登记书名，再 `importRawWorldbook` 灌原生内容；然后绑卡 additional（去重追加）。
  > 为什么两步：真机实测酒馆助手 `importRawWorldbook` 内部列表刷新不 await 且缓存永不自刷——直接导入后 `getWorldbookNames`/绑卡校验读到旧缓存，报“未找到世界书”。自建工具的作者同样绕不开这个坑。
- 数据卡（默认开）→ 机器渲染 data 层精确数值为一条绿灯条目“99·数据卡（EVA自动生成）”，追加到特色科技书（无则第一本书）末尾；触发词=全部研究/建筑/生产名，power 渲染为“发电N/耗电N”。`"dlc": { "dataCard": false }` 可关。
- codex 种子 → message 变量 MVU 树（AI 可见；kind 必须合枚举，见 §2）。
- 注册表 → chat 变量 `$dlc.{id}`（`$` 前缀对 AI 不可见）：version/books/codexSeeds/backups/data 副本/installedAt——**卸载的全部依据**。
- 卸载顺序：takeover 还原 → 解绑 → 删书（仅注册表内的书，原生书免疫）→ codex 清理 → 删注册表。
- 前端 overlay 唯一来源是 `$dlc.data`，**永不解析世界书文本**；安装后 `catalog.init()` 热重载即生效，无需重新打包前端。

## 9. 制作流程

1. 复制样板 `../../../samples/dlc/DLC样板_欧盟.json` 改造（或按 §10 模板先在酒馆建书写内容→导出→内嵌）。
2. 自查：R7 预告词全文搜索；科技名对 93 条 base+已装包查重；tier/cost/line 补齐。
3. 状态栏 → 系统 tab → 万能导入口**选文件/拖拽**（可多选混选自动分流；粘贴为备）→ 自动预检：错误 0 才出现确认门。
4. 酒馆内确认执行 → 研究树出现新特色线、层级卡出现新阵营行、图鉴出现词条。
5. 体检复扫（世界书/变量/对账三维）→ 试卸载 → 复查回滚干净。

## 10. 双书模板（骨架）

> 下为内容规划视图；落地时按 §4 原生条目格式填写（`[constant]`→`"constant": true`，`[selective keys: …]`→`"constant": false, "key": […]`）。最省事的路径：照骨架在酒馆里建书写内容 → 导出 → 内嵌进包。

**《特色科技·X》**：
```text
01·X特色科技总则           [constant]
  [特色科技·X | 总则]
  收录范围一句 + MCV 铁律句式（§4）+ T2 门槛 + 特色线索引（每线一行"·线名——一句定位（详见本书0N）"）
0N·某某线                  [selective keys: 理论名, 解锁物名]
  [特色科技·X | 某某线]
  · 理论名（cost·eta·T{n}·前置…[通用]+X MCV在场）：一到两句理论定位。
  研究成功→解锁……（型号档案指向《武备·X》）。
```

**《武备·X》**：
```text
00·总则                    [constant]
  [武备·X | 总则]
  归属三档声明（自研/引进/特色）+ 同盟关系表述 +（如有 takeover）主权说明
0N·分类档                  [selective keys: 各型号中英名]
  [武备·X | 自研·分类]
  （生产资格由××学整线解锁；均产首台机娘。）
  · 型号（产地·造价·T{n}）：两三句——核心参数+定位+代价。
```

写作口吻对齐现有武备书：数值进括号体例、每型号"强在哪+代价是什么"、不写空洞形容词。
