### 1.2 域盘点：什么是"指挥部的"，什么是"窗外世界的"

设计愿景一句话：**红警指挥系统是常量，世界是变量**——MCV 降落到哪个位面，状态栏就展开成哪个位面的形状。

| 归属 | 域 | 说明 |
|---|---|---|
| 世界无关（不动） | credits/credits_daily、bases、buildings、queues、tech、girls、troops、ammo、vehicles、command_cap、quests、options、codex | 指挥部本体经济与军事，跨世界同构 |
| 世界相关（要抽象） | **wallet**（货币体系） | 本轮 D2 |
| 世界相关（要抽象） | meta.date（历法：秋·九月十八 vs 2026-09-01） | 格式随世界 |
| 结构通用·内容世界化 | exposure（数值轴 0–10 通用；**观察者**世界化：修士灵觉/都市卫星媒体/末世掠夺者） | 与方向①暴露分级交叉 |
| 结构通用·内容世界化 | factions、intel | 结构不动，实体随世界 |
| **缺失** | world_id | 本轮 D3 |

### 1.3 第1轮决策（状态：**confirmed** 2026-09-01）

**D1 · 世界清单与首版分母**
架构按 N 世界设计，首版实装 2 个：修真正史（现有青岚山北坡）+ 1 个验证世界。验证世界**已拍板：赛博朋克世界·2042**。

**D2 · 钱袋内胆方案（三选）**
- A（推荐）：`wallet: record<货币名, number>` 通用记录；合法货币名单由世界适配数据提供、进 L2 权威名单校验；灵石三品扁平为"下品灵石/中品灵石/上品灵石"三个键。理由：troops/ammo 已是 record 惯例；权威名单/别名表基建现成；末世"以物易物"（子弹/罐头）也装得下。
- B：rejected（削足适履）。
- C：rejected（第一版过重）。**拍板：方案 A。**

**D3 · world_id 落点与切书机制**
schema v2 新增 `meta.world_id`；开局 UI（D1 归零态预留的接口位）选世界→写入 #0 楼。世界书加载三案：
- a：全部适配书常挂+条件激活——脏，token 浪费；
- b：一世界一卡，分发时组不同书——干净但维护 N 份；
- c（拍板主攻）：运行时动态启停世界书（酒馆助手 API）——**待真机验证**，b 为兜底。**拍板：按此执行。**

### 1.4 第2轮 · 赛博朋克2042验证世界的架构冲击（状态：**confirmed** 2026-09-01"基本认可"）
赛博2042 对架构的三记重拳（修真单世界时代从未被迫想清的问题）：

1. **科技代差反转**：修真世界指挥部全面领先、只怕被感知；赛博世界本地科技（网络战/义体/AI）部分领先指挥部——适配书必须声明"本地科技水位 vs 指挥部科技树"的相对关系。
2. **位面限定科技暴露**：灵气屏蔽/灵气共振弹/灵沁油精炼是修真位面特产依赖科技，赛博世界无灵气无灵沁油——科技树里藏着一批世界限定项，需机制化处理。
3. **新暴露面：网络空间**：修士灵觉→企业天网/卫星/netrunner 入侵——暴露度数值轴通用，观察者与被入侵面世界化。

第2轮决策（已确认）：

**D4 · 适配书骨架（情报档案体）**：每世界一本，标准六章：①世界总览与历法 ②本地科技水位与效力矩阵 ③暴露观察者与分级表现层 ④货币与经济接口（含合法货币名单） ⑤势力格局 ⑥交战条令。写法统一"指挥部已侦知"口吻，未侦知处显式留白。

**D5 · 效力声明 + 位面限定 + 本地引进轨三件套**：通用书只写本征能力（雷达截面/红外/声学特征），对抗关系归适配书效力矩阵；位面特产科技（灵气系/灵沁油系）数据层标 worldAffinity；每世界开"本地科技引进轨"（复用武备#0 同盟国引进轨机制：赛博=义体改造/网络战套件/本地无人机）。

**D6 · 赛博2042基调**：自创城市+类型公版元素（megacorp/义体/netrunner），还是现成 IP（夜之城/荒坂）？另注：强尼·银手在本工作区是审查人格彩蛋，世界内再出现有串戏风险。

### 1.5 第3轮 · 通用书去世界化手术切法（状态：**confirmed** 2026-09-01）

第2轮拍板落定：D4 六章适配书骨架 ✅；D5 三件套（本征能力归通用书/效力矩阵归适配书/worldAffinity 标记/本地引进轨） ✅；D6 赛博2042=自创城市+类型公版元素（megacorp/义体/netrunner），不用现成 IP ✅。

手术对象：军事/科技 207 条中 124 条含修真耦合词（多为尾部"伪装方向/修真侧注/对修士"行）。

第3轮决策（已确认）：

**D7 · 剥离目的地：混合制**
- 通例进适配书②章效力矩阵，集中写一次（如"隐身涂层对修士灵觉无特效"是全隐身系通例）；
- 特例开型号镜像短条目（key=型号名，如幻影坦克"神识扫描下仍是金属树"）——提型号名时通用条目+适配侧注成对进场，内容局部性好；
- 全镜像（124+条）rejected：条目爆炸；全矩阵 rejected：特例失去激活局部性。

**D8 · 伪装段切法：本征评级留通用书，伪装辞典归适配书**
通用书武备条目保留一句世界无关的"可伪装性评级"（体积/可拆分度/特征强度——本征属性）；"伪装为锅炉/粮囤/水车轴"等具体方案迁入修真适配书伪装辞典；赛博2042 辞典另写（集装箱/物流仓/数据中心/涂装成企业物流）。与 D5"本征能力归通用书"同构。

**D9 · 豁免清单 + 验收断言 + 迁移顺序**
- 豁免①：worldAffinity 科技的型号名/研究名不改（灵气共振弹、灵沁油完全精炼工学、灵气屏蔽工学——名字本身即位面限定项，改名破坏权威名单）；
- 豁免②："藏字诀"判定为指挥部自有教义（世界无关方法论），保留于通用书；
- 验收：去世界化 CI 断言——耦合词表（修士/灵气/宗门/灵觉/神识/天劫/御剑/金丹…，豁免项除外）扫描通用书=0 残留；激活模拟断言型号名→通用+适配条目成对进场；
- 顺序：先建修真适配书（内容从 124 条剥出落地）→ 校验 → 再清通用书源行；中间态允许短暂双写，不允许内容悬空。

### 1.7 多阵营 token 模型（E7e 型号叶子化实测外推·2026-09-02）
方向④的"共享底座 vs 世界/阵营专属"分层，在 token 预算上已由 E7e（武备 129 型号 + 机娘 8 个体叶子化）验证为可行且必要：

- **仓库总容量（静态）**：5 阵营（盟/苏/尤/中/欧）外推 ≈ 300K，但这是加载概念，非每轮开销。
- **单轮开销（动态）按"参战阵营数"计费，而非"库存阵营数"**：
  - 单阵营战役 ≈ 25K（其他阵营存在**完全不影响**单轮 token——叶子化让未点名阵营的型号全程沉默）
  - 双阵营交战 ≈ 36K（共享底座 ~13K 不翻倍，只加交战方型号包各 ~11–12K）
  - 三方混战 ≈ 48K
- **叶子化把扩展成本从"乘法"降成"加法"**：无叶子化时 5 阵营型号互相递归会朝 300K 全库狂奔，多阵营根本跑不起来。

**对方向④架构决策的加固**：
1. 印证"共享底座下沉"的必要性——把类别总则/机娘通则/基地布局/暴露分级做成跨阵营（也跨世界）共享书，避免每阵营/每世界重写 ~13K 底座。
2. 印证"型号=叶子化名词条目"应作为跨阵营/跨世界的统一编写律。
3. 落地建议：多阵营/多世界采用**按需挂载**（选谁的战役就挂己方+可能敌方），配 budget 硬顶 ~40K，靠 order 分带在多方混战时保当前主力。

> 📎 具体优化手法（叶子化/order 分带/budget/诊断脚本）见 **《（必看）编写世界书时的优化技巧》**。本节记"为什么这么定"（架构），那边记"怎么做"（技巧），双向配套。
