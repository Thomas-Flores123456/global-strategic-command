## 0. 目标 · 红线 · 验收（A0 三门冻结）

### 0.1 目标
给生产（及建造/改装）注入与研究侧同构的产线裁决器：`laneKeyFor`（事务→产线键）＋`parallelLimitFor`（产线并行上限），替换引擎默认 `base|type` 单线行为，落地「主建筑/防御辅助/人员/载具等多产线并行槽位」的设计意图。

### 0.2 红线（继承，不得推翻）
1. **产线同源原则**：日程文本/面板的产线分组必须消费引擎 `laneKeyFor` 真实输出，禁止文本侧另立分类（§3.6 已冻结，scheduleText 骨架已预留）；
2. **账本写权铁律**：产线裁决只读 stat_data，队列数组写权唯一在引擎结算链；LLM 只能通过 `<队列>` 文本下单/调度令表达意图；
3. **不重复造 owner**：产线注册表引用现有建筑/生产条目 uid，不在世界书重复新建 owner（ECON-01 §4.3 落地边界）；
4. **存档兼容**：旧档读入零迁移脚本——缺产线字段一律惰性落默认行为，行为等价于 v1 单线；
5. **最小可维护（A0）**：与研究槽模块同构复用判定范式，不引入新抽象层。

### 0.3 验收（骨架阶段）
Q1–Q5 全部驾驶员核准 → 本文档转 `confirmed` → 方可登记实施子任务（schema 字段＋裁决器＋引擎升格门接入＋测试＋真机门）。实施验收标准届时在实施卡细化（基线参照 RSLOT-IMPL-01 六关真机门规格）。

## 2. 轴二 · 裁决器（laneKeyFor / parallelLimitFor）

### Q2 · laneKeyFor 判定优先级（✅ 已确认 2026-09-30）
1. **显式指定**：QueueItem/事务文本显式产线字段（schema 新增，见 Q4）；
2. **产物映射**：catalog ProductionDef/BuildingDef 新增 `lane` 字段（注册表引用，不重复造 owner）；
3. **类型推导**：按产物 type/建筑分类规则推导（注册表内置映射表）；
4. **兜底**：`lane.default`（行为等价 v1 单线）。

### Q3 · 并行上限与升格门（✅ 重裁确认 2026-09-30 二轮「基本许可」：canon 原生容量模型）
- **槽容量＝canon 原生**：每基地每产线容量＝**该基地该品类处于「生产模式」的建筑数**（canon《多建筑并联加速》：「生产模式建筑数量无上限——每座独立执行各自的生产队列」；n 座生产建筑＝n 条并行产线，如两座兵营全生产＝两条人员线并行）；全部加速＝容量 0（队列滞留，待任一切回生产）。初轮「恒 1＋MCV 全加速例外」条款**作废**（被双模机制一般化吸收）；
- **加速系数**：见 §4.2（实际生产时间＝基础÷系数，硬上限 2.50，与分装减免乘法叠加）；
- **全局 tier 门**：**不设**——并行度由「建筑数×双模」自然调节，叠加全局门将使「为什么排不上」不可解释（A2 落后清单 P1 教训）；引擎裁决器保留接口位；
- **升格门接入点**：§3.4 升格带宽门统一裁决处（settleFloor 升格段），容量判定读 mode 真源（§4.1）；
- **调度令兼容**：置顶/置底/暂缓/恢复四动词作用于同 laneKey 分组（现状为同 base|type，平移语义不变）。

## 4. 双模机制与加速系数（canon《多建筑并联加速（双模机制）》整合，2026-09-30 驾驶员基本许可＋补充裁定）

> canon 原文由驾驶员提供（手机端酒馆条目，工作区库尚未同步——见 §6 同步前置）。核心：同类型生产建筑拥有**生产/加速**两种运行模式，指挥官可逐座切换。

### 4.1 模式真源
- Building schema 增设可选 `mode:'生产'|'加速'`（**缺省＝生产**，旧档行为等价；属已授权「允许动 schema」范围）——状态与效率解耦（双模真源之问由 canon 落地正式回答：走 C 案，mode 为状态真源，引擎消费）；
- **适用品类（canon 冻结）**：建造厂核心/MCV（全局建筑建造）、兵营（步兵）、战车工厂（陆地载具）、空军指挥部（空中载具）、造船厂（舰艇）——与 Q1 九线 anchor 一一对齐；非适用品类建筑无 mode 语义（恒视为生产）。

### 4.2 加速系数（canon 公式冻结）
- **递减加成**：第 1 座加速 +0.50（系数 1.50）｜第 2 座 +0.30（累计 1.80）｜第 3 座 +0.20（累计 2.00）｜第 4 座起 +0.05/座；**硬上限 2.50**（生产时间不低于基础值四成）；
- **均摊不稀释**：系数对适用范围内每座生产建筑全额生效，不因生产建筑数量摊薄；
- **公式**：实际生产时间＝基础时间 ÷ 加速系数；与 T2 分装减免**乘法叠加**：最终＝基础 ÷ 系数 ×(1−分装累计减免)（canon 示例：灰熊七日 ×1.50 ×0.55 ≈ 两日半；twoStageAssemblyEngine 已在库，叠加点＝settleFloor 积分链）；
- 加速模式建筑：**不生产、不研究、仅贡献加速**；**仍耗完整电力与日常维护**（「空转供能」非免费——工况引擎电力按在场计费则天然兼容，实施核实）；
- 引擎形态：纯函数 `accelCoefficientFor(生效加速建筑数)→系数`（对照 researchSlots 版型，表驱动可测）。

### 4.3 加速对象（✅ 驾驶员裁定先行落地）
- 加速建筑增设可选 `accel_scope:'global'|'base'`：**global**＝加速同品类**全部基地**的生产建筑（canon 原生默认）；**base**＝仅加速**所属基地**同品类生产建筑；
- 每座生产建筑的生效加速数＝global 同品类加速建筑数＋本基地 base 同品类加速建筑数，按 §4.2 递减表得系数；
- 缺省＝global（canon 原生）；基地间差异考量（仓库/资源/暴露度）属调配模式辖区（§4.5 备案），v1 仅提供手工 scope 开关。

### 4.4 模式切换（canon 数值，建模为引擎事务）
- 切换校准**约半日（720 分钟）**：生产→加速需清空当前队列或暂存半成品；加速→生产需重新校准产线节拍——**建模为引擎事务**（走结算链，非瞬时改字段）；
- 战时紧急切换可压缩至数时辰，首批产出良品率下降一至两成（v1 可先只记事件流水不扣良品，数值惩罚待实施卡细化）；
- **写权入口（账本铁律）**：切换指令由 LLM `<队列>` 文本动词或前端调度令表达、引擎裁决落账——实施卡细化。

### 4.5 备案靠后（驾驶员点子在案，不进 v1）
- **调配模式**：用户开启后智能划分生产队列与加速对象（需接入基地差异信号：仓库余量/资源供给/暴露度等）——复杂系统，**后续单独立项**；
- **MCV 副核心细则**（canon：副核心无意识、造价 1200、仅建 T1/T2 须主核心授权、通讯中断维持不可新建等）——v1 仅承载「副核心作为普通建筑条目＋mode 语义」，细则备案。

- 不做产能输入表/节奏模型的数值化（工况引擎 eff 已覆盖降速语义，产能数值化属 ECON-05 估值字段辖区，不越界）；
