## 1. 设计背景与现存四大断口诊断

通过对 `worldbooks/`、`docs/Architecture/` 与 `mvu指挥系统/src/` 的全链路静态核查，当前机娘系统存在 4 处阻碍深度叙事与角色塑造的结构性断口：

1. **世界书硬锁「每型号永远只有 1 台」**：
   - `worldbooks/异能穿越模拟器v1.0_世界书.json` 的 `uid: 2`（`07L·首台机娘法则与涌现总纲`）、`uid: 25`（`05·首台机娘法则`）、`uid: 31`（`97·机娘档案输出规约`）及 `worldbooks/通用·人员_世界书.json` 的 `uid: 2`（`03·首台机娘生产规则与编制约束`）均写死“每型号只有第 1 台是机娘，第 2 台及后续永远为普通单位，严禁重复输出 `<机娘档案>`”。
   - 实际上，`girlFiler.ts` 在聊天绑定世界书中按 `档案·{name}·{model}` 与 `剧情·{name}·人格与现状` **以 `name` 为主键分立存储**，代码层早已具备容纳同型号多名独立机娘的能力。
2. **初诞时机与赐名仪式错位（反高潮）**：
   - 旧规要求机娘在产线下线瞬间由 LLM 一次性包办「姓名 + 化名 + 社会外壳 + 全套档案」。
   - 这既剥夺了指挥官亲口为初生机娘赋予**专属代号（Callsign，对机娘而言比世俗真名更具灵魂锚定意义）**的互动仪式，又强行要求刚在基地车内诞生的机娘凭空捏造一套尚未用上的“社会外壳”。
3. **`<机娘>` 与 `<机娘档案>` 双标签字段断口**：
   - **通道一（`<机娘档案>`）**：`uid: 31` 要求 LLM 输出 `名称 / 原型 / 阵营 / 外貌 / 性格 / 能力 / 背景`，但 `parsePipeline.ts` 的 `upsertDossier`（L1416-1498）未将 `原型`、`外貌`、`背景`、`阵营` 纳入别名表，导致这些字段被 `quarantineLeftovers` 当作未知键隔离；同时缺少 `编号(serial)`、`代号(callsign)`、`序列(seq)`、`躯体特征(body)`。
   - **通道二（`<战况>` `部队.机娘` 及独立 `<机娘>` 标签）**：`schema.ts` 的 `Girl` 仅放行 `name / duty / hp / base` 4 个字段，且不支持顶层 `<机娘>...</机娘>` 标签；机娘初诞时的身子体态、性格心智、好感度/服从度与特征标签无法随战报同步到 `ModalMechaGirl.vue`。
4. **聊天楼层缺少 `<机娘>` 与 `<机娘档案>` 的 Iframe 视觉卡片**：
   - `tavernRegexPipeline.ts` 与 `floorCardHydrator.ts` 已为 `<阵营解锁>` 和 `<航天合同>` 提供了成熟的「局部展示正则壳 + 长驻脚本 `MutationObserver` 同源 Iframe 水合」机制，但 `<机娘>` 与 `<机娘档案>` 尚未接入。

## 3. 三步生命周期与标签协议规范

### 3.1 Step 1：初诞登场（仅输出 `<机娘>`，聚焦身子与初生性格，待指挥官赐名）

当首台原型机娘下线，或第 2 台及后续同型号单位触发「母网谐振异构 / 战地老兵觉醒」涌现为次生二号机时，先在正文中重点描写其纳米核心凝结、身子体态特征与睁眼面对指挥官的初生神态，并在文末输出 `<机娘>` 标签（**此时暂不输出 `<机娘档案>`，也不强填社会外壳**）：

```xml
<机娘>
名称: 待授名
编号: 犀牛-02
型号: 犀牛主战坦克
序列: 次生二号机
阵营: 苏联
状态: 完好
驻地: 北坡主基地
职务: 重装突击待命（待指挥官赐予代号）
躯体特征: 158cm娇小紧致型纳米躯体，银白短发带赤红挑染，锁骨与脊椎浮现暗红散热微流道，体温偏高，呼吸间伴随轻微涡轮低鸣

服从: 85
特征标签: [次生异构, 极限过载, 待授名]
</机娘>
```

## 4. 数据模型与原地认亲合流契约

### 4.1 `schema.ts` 扩展（100% 向后兼容旧档）

1. **`Girl`（`forces.girls` 元素）**：
   - 保留既有必填/默认字段：`name`、`duty`、`hp`、`base`；
   - 新增可选带默认值字段：
     - `serial: z.string().default('')`（出厂工程编号，如 `犀牛-02`）
     - `callsign: z.string().default('')`（指挥官亲赐代号）
     - `model: z.string().default('')`（原型/型号）
     - `seq: z.string().default('')`（序列：`首台原型` / `次生二号机`）
     - `faction: z.string().default('')`（所属阵营）
     - `body: z.string().default('')`（躯体特征/身子）
     - `personality: z.string().default('')`（性格心智）
     - `appearance: z.string().default('')`（外貌衣装）
     - `shell: z.string().default('')`（社会外壳，允许为空）
     - `alias: z.string().default('')`（对外化名，允许为空）
     - `status: z.string().default('')`（当前心境/剧情状态描述）
     - `affection: z.number().min(0).max(100).default(50)`（好感度）
     - `obedience: z.number().min(0).max(100).default(50)`（服从度）
     - `traits: z.array(z.string()).default([])`（特征标签）
2. **`GirlDossier`（`pending_lore` 机娘档案元素）**：
   - 在既有 14 项字段基础上新增：
     - `serial: z.string().default('')`（出厂编号）
     - `callsign: z.string().default('')`（专属代号）
     - `rename_from: z.string().default('')`（赐名前旧称/待授名标识）
     - `seq: z.string().default('')`（`首台原型` / `次生二号机`）
     - `faction: z.string().default('')`（阵营）
     - `body: z.string().default('')`（躯体特征/身子）

### 4.2 `parsePipeline.ts` 双通道解析与原地认亲算法

1. **顶层 `<机娘>` 标签接入**：
   - `VOCAB` 新增 `'机娘'`；`TAG_SYNONYMS` 新增 `mecha_girl: '机娘'`, `mechagirl: '机娘'`, `maiden: '机娘'`, `机娘状态: '机娘'`。
   - 当 `block.tag === '机娘'` 时，调用统一的 `upsertGirls(data.forces.girls, parsed, ctx, '机娘')`。
2. **`upsertGirls` 认亲定位优先级（防幽灵记录）**：
   - 若输入项仅提供 `编号(serial)` 或 `代号(callsign)` 而未写 `名称(name)`（或 `名称` 写为 `待授名`），自动用 `callsign || (serial ? `待授名·${serial}` : '待授名')` 补齐定位名。
   - 在 `forces.girls` 中查找既有条目时，按以下四级优先级匹配：
     1. `rename_from`（`原名 / 旧名 / 赐名前`）命中既有 `girl.name` 或 `girl.serial`；
     2. 非空 `serial`（`编号 / 出厂编号`）命中既有 `girl.serial` 或 `girl.name`（如 `待授名·犀牛-02` 或 `犀牛-02`）；
     3. 非空 `callsign`（`代号`）命中既有 `girl.callsign` 或 `girl.name`；
     4. `canon(name)` 命中既有 `girl.name`，或当输入有明确 `model` 且库中存在唯一一条同名/待授名同型号记录时命中。
   - 命中后，若新输入的 `name`（或 `callsign`）为正式名字且旧记录为 `待授名*` 或工程编号，**原地将 `existing.name` 覆写为新名字**，并合并全部新增字段（含 `好感变化` / `服从变化` 增量计算）。
3. **`<机娘档案>` 别名断口修复与 `forces.girls` 自动同步**：
   - `upsertDossier` 补齐全部别名映射：
     - `model`: `['型号', '机体型号', '原型', '本体型号', 'model', 'prototype']`
     - `serial`: `['编号', '出厂编号', '工程编号', '机体编号', 'serial', 'unit_no']`
     - `callsign`: `['代号', '战术代号', '呼号', '赐名', 'callsign', 'code_name']`
     - `rename_from`: `['原名', '旧名', '赐名前', '前称', 'rename_from', 'old_name']`
     - `seq`: `['序列', '代次', '批次', '机体序列', 'seq', 'unit_seq', 'generation']`
     - `faction`: `['阵营', '所属阵营', '派系', 'faction']`
     - `body`: `['躯体特征', '躯体', '身子', '体态', '体态特征', '生理特征', '纳米躯体', 'body', 'physique']`
     - `appearance`: `['外观', '外貌', '衣装', '形象', '外貌特征', 'appearance']`
     - `status`: `['当前状态', '现状', '背景', '来历', '履历', 'status', 'background']`
   - 当 `<机娘档案>` 入库 `pending_lore` 时，**同步调用 `syncDossierToForcesGirls`**，将档案中的 `name / callsign / serial / rename_from / model / seq / faction / body / personality / appearance / shell / alias / status` 同步更新至 `data.forces.girls`，确保指挥官赐名仅输出 `<机娘档案>` 时，部队编制表内的待授名条目也能立即转正！

### 4.3 `girlFiler.ts` 聊天书原地更名与 `<数据>` 块升级
