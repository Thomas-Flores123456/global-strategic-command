## 〇、一句话合同与设计哲学

**以“一主指挥官（Persona 唯一绑定）＋ 多副官（阵营主责席 / 参谋增益席）”重构战区最高统帅部：开场启动器支持 1~3 个阵营并线开局（多 MCV 机娘齐发，背负资金摊薄、暴露度翻倍与磨合期代价），局内通过 `<阵营解锁>` 标签与 `<事件> 副官指派` 实现无上限的新阵营两步解锁；每次阵营解锁自动触发“阵营四书启用（含 Swipe 回退对齐）＋ 唯一 MCV 机娘入列 ＋ 科技面板分支开放 ＋ 协议面板空院所亮起（具体协议全隐藏至满足前置才逐条浮现）”四联联动；同时将 `tavernRegexPipeline.ts` 升格为通用声明式正则注册表（先读后写、单次原子批处理），以“极简正则壳 ＋ 长驻中控脚本托管渲染”在不新开任何前端项目的前提下统一承载 `<阵营解锁>` 动态配色卷宗卡与 `<航天合同>` 等多 Iframe 终端。**

## 一、第一章 · 立项动机与现状诊断

### 1.1 现状与四大痛点

1. **世界书资产丰沛但开局与指挥席位被单线锁死**：
   - 现行仓库已具备完整的盟军四书（武备、特色建筑、特色科技、工程）、苏联四书（116 条武备、39 条建筑、124 条科技及工程）以及 13 卷通用重工与机娘世界书。
   - 然而 `mvu指挥系统/src/开场启动器/presets.ts` 与 `pipeline.ts` 仍停留在单一 `factionId: string`、单一指挥官、固定发放 `['MCV（盟军）']` 的单线结构，玩家无法在开局或局内体验跨阵营合成参谋部的战略博弈。
2. **多阵营高爽感与前期硬核生存压力缺乏因果平衡器**：
   - 若多阵营开局仅简单叠加科技树而不设物理与后勤代价，将破坏本工程体系“重工业产能定额、后勤资产刚性分账、高压电网动态平衡”的硬核根基。
   - 必须通过“资金不倍增（多前哨摊薄）、暴露度翻倍、异构电网与后勤磨合期代价（随 $\Delta t$ 消退）”构建高爽感与高决策压力的正向张力。
3. **局内阵营解锁缺乏仪式感与统一状态机**：
   - 玩家在战役中收编异阵营残部或启封移动基地车时，亟需一套既能展现高仪式感视觉演出（`<阵营解锁>` 专属动态配色卷宗卡），又能自动拉通“唯一 MCV 机娘入列、阵营世界书自动挂载、科技树解锁、协议院所开放”的确定性机制。
4. **多楼层内嵌 Iframe 面临重复建项与正则重载陷阱**：
   - 继《航天工业与天基工程系统总设计案》提出 `<航天合同>` 楼层 Iframe 后，本次又新增 `<阵营解锁>` 楼层 Iframe。若每个标签单独建立前端工程或将庞大打包产物塞入酒馆正则 `replace_string`，不仅维护割裂，更会因频繁调用 `updateTavernRegexesWith` 触发 `tavern_events.CHAT_CHANGED` 导致整页反复重载。

## 三、第三章 · 数据模型与预设池契约（Schema & Presets）

### 3.1 `schema.ts` 联席参谋部域（`stat_data.command`）

严格遵循旧档零破坏铁律：所有新增字段均配置 `.default()` 或 `.prefault({})`，既有存档过 `Schema.safeParse` 100% 零报错自动回填。

```typescript
/** 副官席位实体（阵营主责席 / 参谋增益席） */
export const AdjutantRole = z.enum(['faction', 'staff']);
export const AdjutantIdentity = z.enum(['human', 'mcv_girl', 'commander']);
export const AdjutantStatus = z.enum(['active', 'degraded', 'suspended']);

export const Adjutant = z.object({
  id: z.string(),                                           // 唯一标识，如 adj_soviet_katyusha
  name: z.string(),                                         // 姓名（若 identity==='mcv_girl'，与 forces.girls[].name 同名对齐）
  title: z.string().default(''),                            // 军衔/头衔，如“苏维埃远征重工总督造”
  role: AdjutantRole.default('faction'),                    // faction=阵营主责副官 | staff=参谋Buff副官
  identity: AdjutantIdentity.default('human'),              // human=人类军官 | mcv_girl=阵营MCV机娘兼任 | commander=主指挥官直辖
  faction: z.string().default(''),                          // 绑定阵营ID（'allied' | 'soviet' | 'rising_sun' 等；staff 可空）
  buff_preset: z.string().default(''),                      // 专长 Buff 预设 ID（对齐 ADJUTANT_BUFF_PRESETS 白名单）
  upkeep_daily: z.number().min(0).default(0),               // 人类副官每日参谋行政维持费（MCV机娘与主官兼任恒为 0）
  status: AdjutantStatus.default('active'),                 // 当前生效态（前端/引擎结合机娘 HP 与基地展开态动态求值）
  note: z.string().default(''),                             // 任命背景或参谋性格简注
});
export type Adjutant = z.output<typeof Adjutant>;

/** 阵营并网磨合期代价实例（DEC-07 磨合期自动消退制） */
export const PenaltyEffectKind = z.enum([
  'power_loss',      // 电网有效出力折减（比例，如 0.12 表示发电有效率 -12%）
  'daily_upkeep',    // 磨合期每日刚性维护支出（资金/日，如 150）
  'exposure_floor',  // 磨合期暴露度底线抬升与自然衰减放缓
  'prod_slowdown',   // 特定阵营或跨系产线工期效率折减（比例，如 0.12）
]);

export const FactionBreakInPenalty = z.object({
  id: z.string(),                                           // 预设代价 ID（对齐 FACTION_PENALTY_PRESETS 白名单）
  faction: z.string(),                                      // 触发该代价的阵营 ID
  name: z.string(),                                         // 代价显示名，如“苏式高压并网冲击”
  effect_kind: PenaltyEffectKind,                           // 物理效应分类
  magnitude: z.number().min(0).default(0),                  // 效应数值（由预设表硬编码决定，严禁 LLM 自由篡改）
  total_minutes: z.number().min(0).default(21600),          // 初始磨合总时长（默认 15 日 = 21600 分钟）
  remaining_minutes: z.number().min(0).default(21600),      // 剩余磨合时长（随 settleFloor Δt 递减，归零自动移除）
  reason: z.string().default(''),                           // 剧情归因说明
});
export type FactionBreakInPenalty = z.output<typeof FactionBreakInPenalty>;

/** 顶层 stat_data.command 联席参谋部快照 */
export const CommandHQ = z.object({
  commander_name: z.string().default(''),                   // 主指挥官名称（唯一 Persona 绑定对象）
  commander_title: z.string().default('战区最高统帅'),      // 主指挥官头衔
  unlocked_factions: z.array(z.string()).default(['allied']), // 当前已解锁阵营 ID 列表（开局 1~3，局内无上限）
  mcv_granted_factions: z.array(z.string()).default([]),    // 已触发过唯一 MCV 机娘赠送的阵营锁列表

export type CommandHQ = z.output<typeof CommandHQ>;
```

### 3.2 参谋编制容量派生纯函数（`deriveStaffSlotCap`）

依据 `DEC-03`，参谋增益副官（`role === 'staff'`）的编制槽位上限不存冗余脏数字，直接由当前在场运转建筑纯函数推导：
- **基础编制**：开局默认提供 **`1` 个** 参谋 Buff 副官槽位；
- **进阶扩编**：
  - 任意基地存在运转中的通信/雷达中枢（如 `雷达站`、`空军指挥部`、`模块化网电作战枢纽`）→ 参谋槽上限 **`+1`**（达 2 槽）；
  - 任意基地存在运转中的高阶指挥/科研圣地（如 `战斗实验室`、`盟军战斗实验室`、`红星实验设计局综合体`、`国家战略工程综合体`、`盟军联合科研与国家工程组织节点`）→ 参谋槽上限再 **`+1 ~ +2`**（最高封顶 **4 槽**，严控 Token 与心智负担）。

## 五、第五章 · 通用酒馆正则注册中心与单工程多 Iframe 托管架构（`DEC-10 / 11 / 12`）

### 5.1 为什么采用“极简正则壳 ＋ 长驻中控脚本托管渲染”？

1. **彻底规避 `CHAT_CHANGED` 连环重载陷阱**：
   - 酒馆助手 `updateTavernRegexesWith` / `replaceTavernRegexes` 一旦写入，会强制重载整个聊天记录并触发 `tavern_events.CHAT_CHANGED`。
   - 将正则 `replace_string` 设计为**固定不变的极简接收壳**后，卡片的 UI 样式、Vue 组件逻辑、配色算法全部保存在 `mvu指挥系统` 的长驻脚本中——后续无论怎么迭代卡片界面，正则本身一个字符都不用改，永远不会在游戏过程中无故触发整页重载！
2. **零新增前端项目、零重复初始化开销**：
   - `<阵营解锁>`、`<航天合同>` 及未来所有楼层内嵌卡片，全部作为轻量组件存放在 `mvu指挥系统/src/中控悬浮窗/cards/` 目录下；
   - 楼层小 Iframe 无需重复加载几百 KB 的 Vue/Pinia/Catalog，直接由父级长驻脚本同源水合（Hydrate）挂载，毫秒级瞬开。

**批量自愈函数 `ensureSystemRegexRegistry(deps?)` 执行铁律**：
1. 调用 `getTavernRegexes({ type: 'character' })` 读取现有角色卡局部正则列表；
2. 逐一核对 `SYSTEM_TAVERN_REGEX_REGISTRY` 中的每一项是否均已存在且通过 `isSystemRegexSpecConfigured(existing, spec)` 严格校验；
3. **若全部通过**：立即返回 `{ ready: true, installedCount: 0, updatedCount: 0, characterRegexEnabled }`，**绝对不调用 `updateTavernRegexesWith`**；
4. **若存在缺失或配置漂移**：在**单次** `updateTavernRegexesWith(regexes => ..., { type: 'character' })` 调用中一次性补齐/修复所有受管规则，同时 100% 原样保留用户或其他模块创建的非受管正则！

## 六、第六章 · 边界红线与验收门禁

1. **Swipe 物理隔离红线**：`stat_data.command`（含已解锁阵营、唯一 MCV 赠送锁、在编副官、磨合期代价）100% 存储在每楼 Message 变量槽，严禁使用 Chat 级全局单例存储副官或解锁状态。
2. **唯一 MCV 机娘防刷红线**：同一阵营在整场战役（含开局发放与局内 `<阵营解锁>`）中至多发放 1 次初始 MCV 机娘；`mcv_granted_factions` 一旦记录该阵营，后续任何同阵营解锁标签均不得再次向 `forces.vehicles` 塞入 MCV。
3. **零信任数值红线**：LLM 在 `<事件> 副官指派` 中只能填写 `专长预设` 与 `代价预设` 的名称/ID，严禁在事件中直接指定任意百分比或直接篡改 `credits`；所有 Buff 幅度、人类副官日薪（80/日）与磨合期扣费/折减均由前端纯函数查预设表计算。
4. **正则零冗余刷新红线**：`ensureSystemRegexRegistry` 在规则已对齐时必须保持 0 次 `updateTavernRegexesWith` 调用；需新增或修复多条规则时必须在 1 次 `updateTavernRegexesWith` 回调内原子完成。
5. **五重独立门禁**：单元测试（Vitest）→ 生产打包验证（Webpack）→ 真实 SillyTavern 宿主验证（正则自动注册、楼层卡片水合、Swipe 切页世界书回退）→ 驾驶员最终验收（`driver-accepted` 仅限驾驶员本人授予）。
