## 〇、一句话合同与设计哲学

**凡是战区推进中由叙事引发或物理衍生的变故，统一定义为标准事件（Event）；事件仅作为纯函数状态机的输入声明，严禁 LLM 越权直写账本；资金增长剥离裸数字注入，全面改由资金链条（IncomeChain）按游戏内时钟（$\Delta t$）因果派生；全系统账本严格依附于单楼层消息变量槽（Message Variables），从物理底层天然免疫酒馆切页（Swipe）与多时间线分支漂移。**

```
                     ┌─────────────────────────────────────────────────────────┐
                     │          LLM 剧情叙事正文 (<正文> / 自然语言)             │
                     └────────────────────────────┬────────────────────────────┘
                                                  │ 伴随声明
                                                  ▼
                     ┌─────────────────────────────────────────────────────────┐
                     │         标准事件声明报文 (<事件> / 中文 YAML 块)         │
                     └────────────────────────────┬────────────────────────────┘
                                                  │
                                                  ▼
                     ┌─────────────────────────────────────────────────────────┐
                     │     三色对账与因果裁决门 (parsePipeline 扩展通道)       │
                     │  · 🟢 确定性事件：直接入账 (势力变动/常规收支/情报归档) │
                     │  · 🟡 疑义事件：宽容留痕 (轻度差额/未注册小实体/弱相关) │
                     │  · 🔴 隔离事件：越权阻断 (裸改资金总额/凭空制造超模资产)│
                     └────────────────────────────┬────────────────────────────┘
                                                  │

                     │     时间推进与周期结算引擎 (settleFloor 纯函数接缝)     │
```

## 一、第一章 · 立项动机与现状诊断

### 1.1 现状与三重病根

1. **资金流转缺乏物理因果，退化为“数字叙述”**：
   - 现行 `schema.ts` 中的 `economy` 仅有 `credits`（总余额）与 `credits_daily`（日均净入）两个裸数字。
   - 剧情中 LLM 提到“商队遇袭断流”或“开辟黑市渠道”时，目前只能靠 LLM 在 `<战况>` 块粗暴增减数字，完全没有实体化的“商路”、“矿线”、“采购合同”等链条实体。没有链条，就无法因前置设施受损而真实减产，更无法因战区推进而自然枯竭。
2. **战区认知资产（势力/情报/任务）游离孤立**：
   - 势力认知（`factions`）、情报流水（`intel`）、作战任务（`quests`）早已在 `schema.ts` 中完成类型建模，且在旧版红警控制台具备对应面板（`PanelFactions.vue`、`PanelIntel.vue`、`PanelQuests.vue`）。
   - 然而在当前中控悬浮窗（Floating Console）的现代化改造中，这三项重要认知资产尚未完成面板迁移与事件总线统合，处于“数据在底层跑、玩家在高级中控看不到、更新缺乏标准事件规约”的半脱节状态。
3. **酒馆宿主环境特有的多时间线（Swipe）致命冲突**：
   - 酒馆支持消息左右滑动切换候选页（Swipe）、重新生成（Regenerate）以及编辑历史楼层（Edit）。
   - 若事件系统盲目引入“全局单例事件总账”或“事件触发即刻写入世界书”，用户切页时旧时间线的事件将永久残留，引发致命的**时空串线与幽灵资产污染（Ghost State Bleed）**。

### 1.2 现有资产盘点与可复用底座

| 现有组件 | 所在位置 | 架构成熟度 | 对事件系统的价值 |
| :--- | :--- | :--- | :--- |
| **三色解析管道** | `parsePipeline.ts` | 极高（已过多轮实测） | 提供 L0 标签提取、L1 YAML 三级容错、L2 中文映射与 L3 隔离区机制，直接复用为事件解析器 |
| **楼层扫描与快照** | `floorScanner.ts` / `useParse.ts` | 极高 | 具备基线逆序扫描、Swipe 读写双因子复核、fail-closed 熔断防护 |
| **事务与时间推进** | `transactionEngine.ts` / `settleFloor.ts` | 高 | 确立“$\Delta t$ 是唯一燃料”的铁律，为资金链周期结算提供现成齿轮组 |
| **认知展示面板** | `panels/Panel*.vue` | 完备（旧端运行中） | 势力态势卡片、情报置顶/流水/冷存、任务跟踪卡片逻辑完整，可零成本整体迁徙 |

## 二、第二章 · 统一事件分类学与协议契约

### 2.1 事件双轴模型：瞬时事件 vs 持续实体事件

为了防止事件系统退化为无序日志流，将战区事件严密划分为两套轴线：

```text
               ┌─────────────────────────────┐
               │         战区标准事件        │
               └──────────────┬──────────────┘
                              │
         ┌────────────────────┴────────────────────┐
         ▼                                         ▼
┌─────────────────────────────┐           ┌─────────────────────────────┐
│  一、瞬时事件 (Ephemeral)   │           │ 二、持续实体事件 (Entity)   │
├─────────────────────────────┤           ├─────────────────────────────┤
│ · 单次资金收支 (赏金/罚没)   │           │ · 资金链条 (建立/断裂/枯竭) │
│ · 战术情报捕获 (截获密电)   │           │ · 势力态势 (结盟/宣战/警觉) │
│ · 战役阶段通告 (通报/警报)   │           │ · 战备任务 (接取/推进/结项) │
│ 落地：纯流水记录，配容量裁汰│           │ 落地：全生命周期状态机管理  │
└─────────────────────────────┘           └─────────────────────────────┘
```

### 2.2 `<事件>` 报文协议规范

LLM 在战况末端以独立的 `<事件>` 标签输出 YAML 格式的结构化声明。允许在同一报文中声明多项事件，但受每楼上限约束（默认单楼最多 5 项，防事件洪水）。

```yaml
<事件>
- 类型: 资金链建立
  对象: 灵石走私走廊
  流向: 收入
  额度: 600
  周期: 日
  依赖:
    - 基地: 1号前哨站
    - 设施: 隐蔽仓库
  理由: 与当地修真家族达成私下供货协议

- 类型: 资金链断裂
  对象: 旧城废料回收线
  原因: 治安巡逻队全面封锁废料处理中心，运输通道切断

- 类型: 势力发现
  名称: 极光生物科技
  态度: 警觉
  风险: 中
  情报: 驻扎于第三工业区的外资安保集团，装备轻型外骨骼

- 类型: 情报获取
  来源: 无线电监听
  可信度: 高
  内容: 巡逻队将在明日零点轮换防务，东侧排污口将出现15分钟监控盲区

- 类型: 任务接取
  名称: 猎取高纯微晶样本
  详情: 在不惊动治安官的前提下潜入旧实验区，回收3管完好的试剂
  进度: 0/3
</事件>
```

### 2.3 三色裁决门（Triage Gate）规则

与 `parsePipeline.ts` 的三色哲学严格对齐：

1. **🟢 确定性事件（Green Light）**：
   - 语法规范、动词收口、实体参数完备。
   - 自动映射进状态快照，生成绿色事件留痕。
2. **🟡 疑义事件（Yellow Light）**：
   - 存在轻微瑕疵但可自愈（如资金链额度写为 `+600点` 带有文字后缀、来源未注名但内容明确）。
   - 纯函数归一化处理后入账，并在审计流水中记录 Warn 留痕，提供一键撤销（Undo）基线。
3. **🔴 越权与畸形隔离（Red Light）**：
   - 严禁行为：LLM 试图直接声明 `全局资金重置: 999999`、声明超出当前世界观物理逻辑的凭空产物、或字段缺失导致无法解析。
   - 整项事件直接打入本楼隔离区（`quarantine`），绝不动用任何核心账本，并在中控台展示隔离提示。

## 三、第三章 · 资金链条实体模型与生命周期状态机

### 3.1 资金链实体模型（IncomeChain）

在 `schema.ts` 中为 `economy` 域增设可选字段 `chains`（旧档零破坏）：

```typescript
import { z } from 'zod';

/** 资金链流向 */
export const ChainFlow = z.enum(['收入', '支出']);

/** 资金链五态状态机 */
export const ChainStatus = z.enum([
  'establishing', // 铺设中（在途构建，消耗工时/资金）
  'active',       // 正常履约（产生全额日息）
  'distressed',   // 受挫告警（前置受损/外部干扰，效率降级）
  'broken',       // 链条断裂（彻底停摆，保留骨架可修复）
  'exhausted',    // 永久枯竭（资源采空/合约终止，只读终态）
]);

/** 资金链条实体 */
export const IncomeChain = z.object({
  id: z.string(),                                         // 唯一标识 (如 "chain_crystal_smuggle_01")
  name: z.string(),                                       // 链条专名 (如 "青岚山原矿直销通道")
  flow: ChainFlow.default('收入'),                         // 资金流向
  rate_daily: z.number().min(0),                          // 标称日额度 (credits/日)
  status: ChainStatus.default('active'),                  // 运行状态
  eff: z.number().min(0).max(1).default(1),               // 实际履约效率 (0.0 ~ 1.0)
  
  /** 物理依赖清单 (软绑定，用于工况连锁判定) */
  deps: z.object({
    base_id: z.string().default(''),                      // 依托基地
    buildings: z.array(z.string()).default([]),           // 依托建筑 (如 ["矿石精炼厂", "货运站"])
    world_resource: z.string().default(''),               // 依托世界书矿脉/资源条目 ID
  }).prefault({}),

  /** 枯竭与时序指标 */
  capacity: z.object({
    total_yield: z.number().nullable().default(null),     // 理论总蕴藏额度 (null 为无限/长期稳定)
    extracted: z.number().default(0),                     // 累计已提取额度
  }).prefault({}),

  reason: z.string().default(''),                         // 当前状态说明 (如 "因暴风雪封路，货运暂缓")
  updated_at_day: z.number().default(0),                  // 最后一次状态跃迁的游戏内天数
});

export type IncomeChain = z.output<typeof IncomeChain>;
```

### 3.3 结算齿轮：基于 $\Delta t$ 的纯函数派生

资金链条的运行严格挂接在 `settleFloor.ts` 的时钟结算逻辑中：

1. **有效日息折算**：
   $$\text{DailyNet} = \sum_{\text{inflow}} (\text{rate\_daily} \times \text{eff}) - \sum_{\text{outflow}} (\text{rate\_daily} \times \text{eff})$$
2. **楼层结算步进**：
   当本楼推进 $\Delta t$（分钟）时：
   $$\Delta \text{credits} = \text{DailyNet} \times \frac{\Delta t}{1440}$$
3. **枯竭判定（Exhaustion Guard）**：
   若链条设有 `capacity.total_yield`，当累积提取 `extracted` 达到上限时，引擎自动将状态置为 `exhausted`，并生成对应战报事件，无需 LLM 人工提醒。

## 四、第四章 · 抗 Swipe 分支漂移与时空隔离详设

这是整个事件系统在 SillyTavern 环境下得以稳定运行的核心护栏。

### 4.1 变量作用域隔离铁律

酒馆助手（TavernHelper）与 SillyTavern 变量分为两级：

- **Chat 级变量（`type: 'chat'`）**：跨所有楼层、跨所有 Swipe 共享全局单例。
- **Message 级变量（`type: 'message', message_id`）**：**严格与具体楼层以及该楼层当前的 `swipe_id` 绑定。**

```
[全局聊天信道 Chat Variables] ── 严禁存放任何可变业务账本与事件流水！
  ├── 仅允许：$parse 运行时元数据 (解析成功指纹 {hash, swipe_id}、最近审计日志)
  └── 仅允许：$boot 开局不可逆锁定配置

[单楼层 Message Variables: stat_data] ── 业务数据与事件系统的唯一物理真源！
  ├── Floor #5 (Swipe 0) ── 持有该分支独立的: 资金、资金链条、势力认知、进行中任务
  ├── Floor #5 (Swipe 1) ── 持有该分支正交的: 资金、资金链条、势力认知、进行中任务
  └── Floor #5 (Swipe 2) ── 持有该分支正交的: 资金、资金链条、势力认知、进行中任务
```

### 4.2 外部世界书落地的“延迟确认门”（Attended Commit Gate）

新势力、新科技、新任务如果随事件直接写入世界书，切页后将变成无法自动撤销的“幽灵条目”。为此确立双重防线：

1. **暂存隔离原则（Stage First）**：
   - 楼层解析时，新发现的势力与档案只能写入本楼 `stat_data.pending_events` 或 `pending_lore`；
   - 只要还在当前楼层滑动 Swipe，变动均仅限于 Message 变量内部，**绝不调用世界书写入 API**。
2. **入档触发门控（Filing Triggers）**：
   - **途径 A（显式确认）**：指挥官在中控悬浮窗的“战备态势审核台”中，人工点击【确认入册】；
   - **途径 B（时空锚定确认）**：当玩家在当前 Swipe 下**发送了新的用户指令**、触发生成下一楼层时，系统判定该 Swipe 已经成为驾驶员认可的既成历史事实，自动触发本楼暂存项的原子入档。

### 4.3 历史楼层修改与“下游级联重演”（Cascade Replay）协议

当玩家在非末尾楼层（如第 5 楼，当前总共 20 楼）切换 Swipe 或编辑正文时：

```
[用户在第 5 楼切换 Swipe]
       │
       ▼
1. 现有保护生效：第 5 楼本楼根据第 4 楼快照重新计算并落盘新 stat_data。
       │
       ▼
2. 触发 Downstream Mismatch 告警：
   中控悬浮窗顶栏亮起警告横幅：【⚠ 检测到历史时序分支改写：第 6~20 楼状态已与本楼脱节】
       │
       ▼
3. 悬浮窗提供【从本楼级联对账 (Replay Downstream)】安全动作：
   ┌────────────────────────────────────────────────────────────────────────┐
   │ 纯函数循环：从第 6 楼推进至当前最新楼                                  │
   │ · 以第 i-1 楼的最新 stat_data 为输入 baseline                          │
   │ · 提取第 i 楼当前激活 Swipe 的正文与 <事件> 报文                       │
   │ · 依次执行 settleFloor 与事件更新，重写各楼 message 槽 stat_data       │
   └────────────────────────────────────────────────────────────────────────┘
```

## 五、第五章 · 势力、情报、任务系统统合方案

### 5.1 战区认知三子系统模型收归

将旧版 `红警指挥系统` 中的独立面板数据完全对齐到统一事件总线：

```typescript
// 1. 势力更新事件
interface FactionEvent {
  kind: 'faction';
  name: string;                                           // 势力名 (对齐 catalog.factionDefs 权威名单)
  attitude?: '敌意' | '警觉' | '中立' | '友善' | '未接触';
  risk?: '高' | '中' | '低' | '未知';
  intel?: string;                                         // 认知概要增量
}

// 2. 情报获取事件
interface IntelEvent {
  kind: 'intel';
  src: string;                                            // 监听/侦察/线报…
  content: string;                                        // 情报正文 (按 canon(content) 自动去重)
  date?: string;                                          // 战区公历
  cred?: '高' | '中' | '低';                              // 可信度
  pinned?: boolean;                                       // 是否高优置顶
}

// 3. 任务变更事件
interface QuestEvent {
  kind: 'quest';
  name: string;                                           // 任务名
  action: 'accept' | 'update' | 'complete' | 'fail';     // 状态动作
  progress?: string;                                      // 进度简述 (如 "2/3")
  detail?: string;                                        // 任务目标与背景
  note?: string;                                          // 参谋便签
}
```

### 5.2 前端中控悬浮窗迁移动线

## 六、第六章 · 与既有管线的接缝

### 6.1 与 `parsePipeline.ts` 的接缝

在 `parsePipeline.ts` 的主执行流中：
1. **L0 词表扩充**：在 `scanMarkers` 与 `extractBlocks` 中注册 `<事件>` 标签为合法一级标签；
2. **新提取器 `extractEvents`**：解析 YAML 数组，提取资金链、势力、情报、任务四类声明条目；
3. **权威名单模糊匹配（`applyAlign`）**：势力名称、设施名称自动过 `canon()` 和编辑距离对齐，防止因繁简或错别字分裂出多个同名势力。

### 6.2 与 `settleFloor.ts` 的接缝

在 `settleFloor.ts` 中加入第四结算接缝（与产线结算、工程结算平级）：
1. 输入：`baseline.stat_data.economy.chains` ＋ 本楼 `parseResult.chains`；
2. 状态机运算：执行链条的建立、断裂、受挫状态合并；
3. 时钟积分：按本楼 $\Delta t$ 计算实际资金净收益，更新 `economy.credits`；
4. 枯竭更新：累加 `capacity.extracted`，超限自动结项。

### 6.3 与 `operationEngine.ts`（工况引擎）的接缝

资金链条的效率 `eff` 不仅由剧情事件决定，也受战区客观物理环境钳制：
- **电网赤字**：若链条依赖的基地处于电力断供状态，依赖设施停机，链条 `eff` 强制跌落至 0（自动转入 `distressed` 态）；
- **恶劣天候**：极端辐射风暴或暴风雪天气，物流类资金链效率乘以工况衰减系数。
