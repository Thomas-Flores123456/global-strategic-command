## 1. 决策点总览（9 项，逐条拍板或整体"按推荐来"）

| # | 决策点 | 推荐 | 一句话理由 |
|---|---|---|---|
| D1 | 初始化方案 | **（拍板修订）schema 默认值 = 归零态**：键全、值零/空；开局正式值由未来开场专用 UI 确认后写入 #0 楼；`<初始状态>` tag 保留但降优先级 | 富演示数据未经驾驶员检查不当开局正史；归零让“未继承基线”一眼可见，比富数据伪装正常更诚实 |
| D2 | 指令模型 | **声明式 YAML 深合并 + 按域固定合并语义 + 最小指令集**（`操作: 完成/取消`） | 一致性约束内置到解析器（如"完成研究"自动联动 queues+tech.done），LLM 少写就少错 |
| D3 | delta 语义 | **「变化」键名后缀**（`资金变化: +120`），不用值前缀 | YAML 会把 `+120` parse 成 `120` 吞掉加号——值前缀是坑，键名后缀天然免疫 |
| D4 | tag 词表 | 三个中文 tag：**`<战况>` `<图鉴>` `<初始状态>`** | 两 tag 分职责（状态更新 vs 实体注册）隔离失败面；中文与键名/主题一致 |
| D5 | 楼层传承语义 | **每个 AI 楼解析后必落快照**（无 tag 也落基线）；用户楼/隐藏楼跳过；swipe 每页独立重算；编辑旧楼只重算自身+下游失真提示（级联重放按钮后置） | 必落快照堵住"渲染开局态"事故；其余与简报一致 |
| D6 | 变量可见性 | 批 D 新增**变量注入条目**（`{{format_message_variable::stat_data}}` 惯例），第一版全量注入 | AI 看不到当前值就写不对增量——这是协议闭环的缺失件 |
| D7 | 正则周边件 | 两条 scoped 正则（显示隐藏 tag 块 + promptOnly 裁旧楼 tag 块）**打包进批 D，可选**；批 A-C 裸跑 | 不影响功能正确性，只影响观感与 token；成熟卡范式现成可抄 |
| D8 | schema v1.1 | 仅新增可选 `schema_version` 字段（`.default(1)`），其余不动 | 未来迁移要锚点；兼容性扩展，老存档无感 |
| D9 | 协议键名 | **中文协议键** → L2 映射表转英文 schema 字段（附件 §4） | 中文正文语境下 LLM 写中文键漂移率低；协议层与 schema 解耦 |

以下为各项详析。

## 2. D1 · 初始化方案（拍板修订版：归零态）

驾驶员裁定：默认开局态尽可能**归零**——只确认有哪些键、有"零值"；未来将在首楼做开场专用前端 UI 自定义开局，用户确认后才向变量填入确定值。现存富演示数据（两基地/7机娘/示例任务等）未经驾驶员检查，不得充当开局正史，当断则断。

落地语义：

- **归零层（schema 默认值，批 A 改造）**：字符串→`''`、数字→`0`、数组→`[]`、record→`{}`；元素级枚举默认值保留（元素由 UI/LLM 创建时缺字段的合理兜底）。`Schema.parse({})` = 归零态 = 键结构契约。
- **预览 mock 层（与开局态分离）**：原富演示数据搬进预览场景模块（store.ts 预览侧）作 mock 基底，`pnpm dev:vite` 仍可看到有数据的 UI；真机空楼则是干净归零态。
- **开场 UI（未来规划，不在本次四批内）**：用户确认开局 → 写入 #0 楼 message 变量 → 解析器楼层传承自然继承。归零态就是为它留的接口位。
- **`<初始状态>` tag**：保留在词表（管道免费能力，后备通道），批 D 落地优先级降低，不再是开局主路径。
- **不选 b 的原因（不变）**：本项目无 MVU 本体，读禁用世界书条目要专门开管道，且我们的 tag 协议不是 MVU 方言，装了本体也解析不了。

## 3. D2-D4 · tag 协议详设

### 3.1 tag 词表（L0 收词范围）

| tag | 职责 | 出现位置 | 多块语义 |
|---|---|---|---|
| `<战况>` | 声明式状态更新 + 少量操作指令 | 每个 AI 楼 0~n 个 | 按出现顺序依次深合并（后者胜），🟢 |
| `<图鉴>` | codex 实体注册/修改（名称定位 upsert） | 出现新实体时 | 多块 append 合并，🟢 |
| `<初始状态>` | 首楼初值覆盖（整棵中文键状态树） | 仅 #0 楼 | 非首楼出现 → 忽略并记🟡 |

- 内容一律 **YAML**（已共识底线）；L0 按简报既定方案容忍 `<tag|>`、`＜战况＞`、大小写、属性垃圾、代码围栏、闭合错拼编辑距离≤1、未闭合截断。
- 拆两个业务 tag 而非一个大 tag：**局部失败局部隔离**（图鉴块 YAML 崩了不拖累战况入库）；也不拆成五六个（LLM 漏写率随 tag 数上升）。
- `<图鉴>` 独立的另一个理由：它是实体注册入口，直接对接实体对齐（批 C）与归档管道（`${kind}·${name}` 命名，`ArchiveCandidate` 形状），教学 few-shot 单独成节更清晰。

### 3.2 声明式合并语义（按域固定，LLM 无需理解）

| 结构 | 语义 | 适用域 |
|---|---|---|
| 标量/嵌套对象 | 深合并覆盖 | meta/economy/exposure 等所有标量 |
| 数字 + `变化` 键后缀 | delta（当前值±N，clamp 到 schema 边界） | 资金/铜银/灵石/兵力/天数/暴露度/完成任务数 |
| record | 按键合并（值可 delta） | 兵力 troops / 弹药 ammo / 钱袋 wallet |
| 数组·**按名 upsert** | 有则深合并该元素，无则 append；元素内数组递归同语义 | 基地(名称)/建筑(名称)/队列(项目)/机娘(名称)/势力(名称)/任务(名称)/图鉴(名称) |
| 数组·**append 去重** | 只增不减（减法走指令） | 已研科技 tech.done、情报 intel（canon(内容) 判重） |
| 数组·**整体替换** | 每次全量给出 | 选项 options、载具 vehicles、基地警报 alerts |
| 同键绝对值与 `变化` 同现 | 绝对值优先，delta 忽略，记🟡 | — |

### 3.3 最小指令集（`<战况>` 内 `操作:` 列表）

第一版只有两个动词，其余场景全部砍掉（intel 归档走 UI、girls 阵亡是 `状态: 离线` 不是删除）：

```yaml
操作:
  - 完成: 相位折射涂层    # 按名查 queues：type=研究 → 移除队列 + append tech.done
                          # type=建造 → 移除队列 + 对应建筑 state='运转'
                          # type=生产 → 移除队列（产物由 LLM 在 部队/载具 里声明）
  - 取消: 谍报无人机试制   # 按名移除队列，无联动
```

联动逻辑（一个"完成"保证多处一致）内置在解析器——这是防错设计的核心收益：LLM 一句话，机器保证 queues/tech/buildings 三处一致。

### 3.4 delta 的 YAML 陷阱（D3 的技术依据）

`YAML.parse('资金: +120')` → `{资金: 120}`，**加号静默丢失**；若要求写字符串 `"+120"`，LLM 漏引号后 `资金: 120` 会被当成绝对值覆盖（1514→120 灾难）。故 delta 一律用键名后缀：`资金变化: +120` / `资金变化: -30`——负号 YAML 天然保留，正号丢了也无碍（`变化` 键已声明是增量）。

### 3.5 analysis 注释行（借鉴 MVU 生态，零成本防错）

MVU 正路的 `<analysis>` 前置段被生产卡证明能降错。我们的零成本等价物：**规约鼓励（不强制）在块首写 YAML 注释行**：

```yaml
<战况>
# 本轮：完成相位涂层研究；资金+120（药材订单）；暴露度+0.15（夜间试飞被目击）
资金变化: +120
...
</战况>
```

注释被 YAML 天然忽略，零数据污染、零解析成本；隔离区 UI 展示原文时它还是现成的人读摘要。

## 5. D5 · 楼层传承与事件语义（解析器的"MVU 本体补位"）

```
GENERATION_ENDED（批 B 真机确认与 MESSAGE_RECEIVED 的取舍）
  → 守卫: getCurrentMessageId() === getLastMessageId()（仅最新楼 iframe 执行）
  → 幂等: $parse.done[message_id] === hash(原文) 则跳过
  → 基线: 从 message_id-1 向下找第一个含 stat_data 的楼（getChatMessages 判 role/is_hidden，跳过用户楼/隐藏楼/无变量楼）；
          找不到 → Schema.parse({})（开局态）
  → 解析: L0-L3 处理本楼 tag → 增量应用到基线副本
  → 归一: Schema.safeParse；越界 clamp；params 值 String() 强转
  → 落盘: updateVariablesWith 写本楼 message.stat_data（await）+ $parse 留痕（await）
```

关键语义（较简报的两处强化）：

1. **每个 AI 楼必落快照**：没有 tag、tag 全进隔离区、解析中途失败——**都至少把基线原样落盘本楼**，否则该楼丢失全部继承进度。D1 归零修订后此条更干净：无基线可继承时落归零态，全零界面一眼可识别"未继承"，不会像富数据那样伪装成正常状态。红线"红区不入库"指的是坏增量不入库，基线快照照落。
2. **写入物 = Schema.parse 归一产物**：顶层严格 object + 轮询归一化回写（§0-7）决定了写"生数据"会被 2s 内改写；直接写归一产物一步到位，也消灭解析器与轮询的双写者分歧。
3. swipe：MESSAGE_SWIPED 重解析，每页从同一基线独立重算，hash 幂等天然区分——同简报。
4. 删楼：变量随楼删，天然回退；`$parse.done`/隔离区中指向已删楼的残留由 **R20 对账**清理（仿 R16"登记 vs 实况"模式）。
5. 编辑旧楼：MESSAGE_EDITED 重解析该楼自身（基于其上楼基线）；**不级联重算下游**，UI 提示"下游 N 楼可能失真"。级联重放按钮列为后续增强不进第一版（边界多：中间隔离未决楼、用户楼），删下游楼重新生成是现成的完全重算路径。
6. 消"默认值闪现"：init 顺序调整为解析先于 mount（解析完成写入 → `waitUntil(_.has stat_data)` 即刻满足 → mount 读到正确值），批 B 实施细节。

### 6.1 变量注入条目（D6，批 D 必做）
