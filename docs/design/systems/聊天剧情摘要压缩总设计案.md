## 2. 第二章 · 摘要条目合同（Q6=A · 冻结）

- **落点＝当前聊天档案书**（不另立独立摘要书）：守 CHATBOOK-01「每聊天一本用户好管理」裁决；摘要天然随聊天走、随孤儿治理走；
- **前缀**＝`摘要·{区间}`（如 `摘要·001-020`，姊妹案 §2.4 注册表已预留）；`extra` 记 `{from, to, generatedAt, model}` 机读区间元数据——**条目 extra 为区间唯一真源**，不自建独立账本；
- **激活策略默认＝`constant` 蓝灯常驻＋`at_depth`（role=system，depth 提案值 4，真机门实测校准）**——摘要是「已发生正史」，默认无条件在场；
- **次要选项（驾驶员 2026-09-23 补充裁决：社区同类方案有先例，升格为正式设置项非 Parking）**：`分层激活`模式——近期区间 constant 常驻＋久远区间 selective 绿灯（key=区间内主要实体名，摘要生成时一并产出），压更低常驻 token、代价是久远段命中不确定；管理页设置项二选一，**默认 constant 全常驻**；实现为逐条目 strategy 字段切换，两模式共用同一区间账本零迁移；纯 selective 全绿灯仍否决（漏命中＝剧情断片，无常驻兜底不可接受）；
- **常驻预算（提案值，真机门 token 实测后校准）**：单条摘要目标 ≤500 token；聊天书内摘要段总预算 ≤3000 token，超限时管理页提示合并重摘——**v1 只提示不强制**（接 rolecard-performance 预算体系的护栏语义）；分层压缩（摘要的摘要）v1 不做，进 §6 Parking。

## 3. 第三章 · 区间划分与触发（Q7=A · 冻结）

- **区间连续性铁律**：区间左闭右闭、首尾相接、零重叠零漏段——`下一区间 from ＝ 上一区间 to + 1`；唯一真源＝聊天书内既有 `摘要·` 条目的 extra.to 最大值，新区间自此起算（零新状态，防重叠/漏段由构造保证）；
- **触发时机默认＝玩家手动为主**（管理页「摘要到当前楼」按钮）＋每 N 楼**提醒**不自动执行（N=20 提案值，可调）——摘要质量需人把关（§4 质量门）；
- **次要选项（驾驶员 2026-09-23 补充裁决，正式设置项）**：`自动预生成`模式——每 N 楼自动后台 generateRaw 生成摘要**进暂存**（pending_summaries），管理页角标提醒待审，玩家仍须过 §4 质量门采纳才入书＋隐藏；对齐社区自动总结类方案的体验，同时守住「坏摘要绝不静默入书」底线不放松——**自动的只是生成，采纳永远是人**；设置项二选一，默认手动；
- **尾部保留带**：最近 M 楼永不入摘要区间（M=10 提案值，可调，保持近场原文精度），单次摘要范围＝`[已有摘要末楼+1, 当前楼-M]`。

## 4. 第四章 · 摘要生成与质量门（Q8=A · 冻结）

- **生成方＝`generateRaw` 后台独立请求**（`should_silence:true`＋`ordered_prompts` 自定义摘要提示词＋`max_chat_history` 圈定区间楼层，generate.d.ts:199/:160/:164-165）——不污染主对话回复；额外 token 成本在手动触发（Q7=A）下频次可控，属可接受代价；
- 否决记录：主对话模型顺带输出 `<剧情摘要>` 标签——摘要指令常驻每楼提示词、输出混入正文，与省 token 立项动机自相矛盾；
- **质量门**：摘要生成后先进暂存（`pending_summaries`，照 pending_lore 形制），管理页预览→玩家「采纳/重摘/弃置」→采纳才经守卫入书；坏摘要可回滚：删该区间条目→区间指针自动回退（§3 构造保证）→重摘；
- 入书经 CHATBOOK-01 三重守卫，fail-closed 不清暂存（机制原样复用）。

## 5. 第五章 · 原始楼层处理（Q9 · 驾驶员裁决冻结：采纳即隐藏＝默认行为）

驾驶员裁决（2026-09-23）：「一般来说原始楼层直接隐藏了，不然摘要用来干嘛？」——不隐藏则 token 零节省、摘要沦为冗余，立项动机被架空。据此冻结：

- **默认行为＝采纳摘要即 `setChatMessages` 隐藏对应区间楼层**（`[{message_id, is_hidden:true}]`，chat_message.d.ts:143-148）；管理页提供逐区间「取消隐藏」逆操作；
- **次要选项（驾驶员 2026-09-23 补充裁决，正式设置项）**：`仅注入不隐藏`模式——采纳只入书不隐藏楼层（摘要与原文并存，多吃 token 零风险）；适用场景：放行门探针未过期间的过渡态（此时该模式即强制态）、玩家宁多花 token 也要全文可回看、以及社区「世界书记忆＋原文保留」类方案的使用习惯；设置项二选一，**默认采纳即隐藏**；两模式切换不破坏成对铁律——切到不隐藏模式不自动取消既有隐藏，已隐藏区间仍由逐区间开关管理；
- **放行前置（🔴 实现顺序约束，非功能删减）**：§1.2 必测 1（`is_hidden` 对 MVU 变量链——变量继承/`<timePast>` 链/消息楼层变量）与必测 2（隐藏楼是否仍被世界书 `scan_depth` 扫描）是**隐藏功能的真机放行门**——实现任务先交探针、驾驶员真机跑通后隐藏才可用；探针未过期间隐藏入口以「待真机验证」置灰，摘要入书功能不受阻（先摘后隐、分步放行）。若必测 1 证实隐藏破坏变量链，回本案重裁（备选＝隐藏时豁免带变量关键楼），不得静默带病默认化；
- **可逆性铁律**：弃置/删除某区间摘要条目 → **必须自动取消隐藏**对应区间楼层（摘要与隐藏状态严格成对，不留「无摘要的黑洞段」）；区间指针回退（§3 构造保证）与取消隐藏同一事务完成；
- **豁免带**：尾部保留带 M 楼（§3）与 #0 楼（MVU 初始变量锚）永不隐藏。
