## 1. 核心设计哲学：为什么航天不能当普通载具或建筑？

在红警战略指挥系统中，常规地面/水面/航空单位与建筑遵循传统 RTS 与“机娘/舰娘”心智模型，而**航天工业与天基活动具有根本性的品类特殊性**：

1. **心智模型的本质分野（机娘舰娘 vs 工业载具与发射工程）**：
   - 造一辆主战坦克或一艘巡洋舰，在玩家与 LLM 的叙事心智中等同于“整备或唤醒一位完整的机娘/舰娘作战单位”，出厂即具备独立作战与机动能力；
   - **运载火箭与卫星载荷则完全不同**——正如 V3 火箭发射车或无畏级导弹舰必须先有弹体装填才有发射可能，绝大多数人不会把一根消耗性运载火箭视为拟人机娘，而是将其视为**“将精密载荷顶出地球重力井的多级工业运载系统”**。
2. **航天活动是“工序型战役工程”，而非“兵营下饺子”**：
   - 一次完整的航天任务天然包含：**芯一级/二级/助推器制造 → 有效载荷（卫星/飞船/空间站舱段）预制 → 垂直总装与低温加注 → 发射窗口点火升空 → 级间分离与入轨测控 → 太空交会对接/月面软着陆**。
   - 因此，航天发射活动必须**彻底与工程系统（Project V1 阶段链 / V2 仓段模块拓扑）深度绑定**，让火箭成为连接地面重工业与外层空间巨构的“运力载体与工程行动”。
3. **前端可视化管理与 LLM 叙事自主性的双轮驱动**：
   - **前端侧**：提供专属的【天基测控与发射大厅】（Mission Control），直观展示地面发射工位、火箭多级总装进度、近地轨道星座/空间站合拢状态、地月转移航线与月面基地；
   - **LLM 叙事侧**：前端锁定硬核工业账本与轨道状态，为 LLM 提供丰富的叙事锚点（如倒计时点火、科罗廖夫十字分离、黑障区通讯中断、太空舱外抢修、反卫星暗战），赋予 LLM 极高的戏剧张力与叙事自主权。

## 4. 运载火箭的多级总装工程阶段（Staging & Launch Pipeline）

为了彻底体现“火箭不是机娘，而是多级工业总装产物”的核心体验，运载火箭的制造与发射不走普通兵营的单条读条，而是深度融入工程系统的 **5 阶段总装与发射流水线（5-Stage Launch Pipeline）**。

### 4.1 运载火箭五阶段标准架构

无论发射卫星、飞船还是空间站舱段，一次标准重型航天发射工程由以下 5 个子阶段/模块构成：

```
┌─────────────────────────────────────────────────────────────────────────────────────┐
│                        【运载火箭垂直总装与发射工程流水线】                          │
├──────────┬──────────────────────────┬──────────────────────┬────────────────────────┤
│ 阶段序号 │ 阶段/模块名称            │ 工程物理内涵         │ 机制特性与科技联动     │
```

### 7.2 标签一：`<航天合同>` 与楼层内 Iframe 拟定终端（正则 Display 挂载 × 零信任校验）

当玩家在对话中流露出筹备航天发射或天基工程的意图时，LLM 可在回复正文末尾（或参谋汇报段落后）输出 `<航天合同>` 标签，作为**非权威的初始意向建议（Untrusted Proposal Hint）**。

> **🚨 核心工程铁律（零信任 LLM 输入 & 单一解锁真源）**：
> LLM 输出的 `<航天合同>` **极易出现错别字、简称、跨时代越级推荐甚至捏造幻觉型号**，因此：
> 1. **禁止 LLM 在标签内算账**：`<航天合同>` 仅允许传输轻量级文本意向（工程名、基地、轨道、载荷名、火箭构型建议），**严禁由 LLM 输出运力、造价、工期等数值**——所有物理运力、资金造价、回收抵扣与工期 **100% 由前端 Iframe 根据世界书 `<数据>` 块真源实时计算**！
> 2. **下拉框选项严格锁定“当前已解锁池”**：Iframe 内所有下拉框（牵头基地、有效载荷、运载火箭型号、芯一级、助推器、芯二级、远征上面级）的选项列表，**绝不从 LLM 文本生成**，而是直接调用 `catalogEffective.ts`（`EffectiveCatalog`）与 `prerequisites.ts`（`evaluatePrerequisites(item.requirements, PrerequisiteContext)`），结合宿主 `stat_data`（`tech.done` 已完成科技、`bases` 已建航天发射场基地、`projects` 在建天基工程的未完工舱段、库存已回收芯级数）**动态过滤出的当前已解锁合法子集**！未解锁项一律不予选入（或在下拉框底部置灰带锁 `🔒 [未解锁：需研发「无毒推进剂工学」]` 且禁止选中）。

### 7.5 与《通用任务编排器总设计案（UTO · CTRL-UTO-CORE-01）》的原生会师契约

鉴于 [`通用任务编排器总设计案.md`](./通用任务编排器总设计案.md)（UTO）即将进入实施阶段，航天系统**严禁另建私有计时器、私有排队数组或独立状态机**，而是 100% 作为 UTO 六大轴的原生业务消费者接入：

#### 1. 轴一对齐：`UnifiedTask` 统一建模（消灭“火箭发射”与“空间站舱段”的双账本分裂）
- **天基 V2 巨构总成与舱段（`domain: 'megastructure'`）**：
  - 空间站/月面基地总成为父级 `UnifiedTask`（`id: "task:proj_orbital_station@base1"`），其下属舱段（`core / solar / dock / lab / hab`）为子级 `UnifiedTask`，通过 `topology: { parentId, dependsOn, subTaskIds }` 表达舱段合拢的 DAG 依赖拓扑；
- **运载火箭发射与太空行动任务**：
  - 每次签署 `<航天合同>` 发起的发射任务，直接建模为挂载在 `laneKey: "${baseId}:eng.orbital"` 上的 `UnifiedTask`，并在弱类型扩展槽 `metadata` 中挂载航天载荷与运载构型：
  ```typescript
  metadata: {
    aerospaceKind: 'launch' | 'eva_repair' | 'orbital_maneuver',
    targetOrbit: 'LEO' | 'SSO' | 'GEO' | 'TLI',
    payload: { name: '轨道空间站·实验舱', targetModuleTaskId: 'task:mod_lab@base1', massT: 20.5 },
    vehicle: { model: '重型低温无毒运载火箭', reuseStage1: true, boosters: 4, upperStage: false },
    hazardReason?: string, // 当处于 held（险情待抢修/气象推迟）时的世界内理由
  }
  ```
- **五阶段过程量的零存储纯函数派生**：
  - 火箭总装发射的 Stage 1~4 无需污染持久化 Schema，直接由 `spentMinutes / totalMinutes` 进度比无状态派生：`[0~25%) = Stage 1 芯级总装`、`[25%~50%) = Stage 2 助推与二级对接`、`[50%~80%) = Stage 3 有效载荷整流罩封装`、`[80%~100%) = Stage 4 发射塔架竖立与低温加注`；当积分满额（`100%`）进入 `settling` 态时，自动对应 `Stage 5 窗口就绪，待点火与入轨判定确认`！

#### 2. 轴一状态机对齐：UTO 七态（`TaskStatus`）与航天生命周期 1:1 映射
| UTO `TaskStatus` | 航天系统业务语义映射 |
| :--- | :--- |
| **`draft`** | 天基 V2 巨构中**已立项但尚未签署发射合同**的待投送舱段模块。 |
| **`queued`** | 已签署 `<航天合同>`，正在等待基地 `eng.orbital`（天基工位）空缺的候列发射任务。 |
| **`active`** | 正在占用发射工位推进 Stage 1~4 的在编火箭工程（消耗 $\Delta t \times \text{accel} \times \text{power} \times \text{compute}$）。 |
| **`held`** | **气象推迟 / 奉令暂缓**，或 `<航天>` 判定触发 **`⚠️ 险情待抢修`**（让出工位、冻结进度，等待太空 EVA 抢修任务完成后 `Resume`）。 |
| **`settling`** | **Stage 5 发射窗口就绪（T-0）**：火箭已在塔架完成低温加注，等待 LLM 在本轮输出 `<航天>` 判定回执过三色对账门。 |
| **`completed`** | `<航天>` 判定 `圆满成功`，火箭任务结项，同时通过 `topology` 触发关联的在轨舱段 `UnifiedTask` 同步转为 `completed`（合拢点亮）！ |
| **`cancelled`** | 发射任务或工程奉令撤销，按条令退回未消耗资源（若曾预扣库存回收芯一级且尚未点火，原样退回库存）。 |

#### 3. 轴二 & 轴三对齐：`EngineeringLaneProvider`（`eng.orbital`）与回收一级工时折算
- **天基工位派生（`ILaneProvider`）**：
  - 在 `EngineeringLaneProvider` 中输出 `laneKey: "${baseId}:eng.orbital"`（显示名：`天基与轨道工程序列`）：基地建成《航天发射中心》时 `capacity = 1`；建成《国家重型航天发射中心》或《山体发射场》时容量与 `accelMultiplier` 累加；基地无发射场时 `capacity = 0, locked = true, lockedReason = "航天发射中心未建成，序列未开通"`；
- **电网与超算算力原生联动（`TickEngine`）**：
  - 直接复用 UTO 积分方程 $\Delta \text{spent} = \Delta t \times \text{accelMultiplier} \times \text{powerEfficiency} \times \text{computeRatio}$——发射场断电或战区超算算力赤字时，火箭总装与轨道解算自动降速或停摆，零私有分支代码；
- **♻️ 回收芯一级复用的纯数据化实现**：
  - 玩家勾选 `[♻️ 调用库存已回收芯一级]` 立项时，生成的 `UnifiedTask` 直接在创建期将 `workload.totalMinutes` 乘以 `0.5`（免除 Stage 1/2 制造工时）或预充 `spentMinutes = totalMinutes * 0.5`（直接从 Stage 3 载荷封装起步！），令 `TickEngine` 内核保持 100% 领域中立！

#### 4. 轴四对齐：复用 `UnifiedDispatchBus` 六动词总线
- `<航天>` 标签与【🚀 天基航天】面板中的调度操作，底层全部收敛为 UTO 标准总线调用：
  - 优先抢发某颗紧急侦察星 → `Promote(taskId)`（调升首序，自动将原在编火箭安全挤退回 `queued` 且保留已装进度）；
  - 气象窗口关闭 / 险情待抢修 → `Hold(taskId)`；
  - 抢修完毕 / 窗口重开 → `Resume(taskId)`；
  - 取消发射任务 → `Cancel(taskId)`；
  - 跨基地调配发射场承建 → `Allocate(taskId, baseId)`。
