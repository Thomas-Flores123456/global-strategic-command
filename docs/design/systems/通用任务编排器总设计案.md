> 状态：`draft-v1.0`（2026-10-18：主参谋部与驾驶员总揽草案，待驾驶员裁决立项）  
> 归属：`CTRL-UTO-CORE-01`（系统编排与底层调度统一演进工程）  
> 前置依据：《系统事务与时间推进总设计案》、《产线与产能调度总设计案》、《科技研究槽总设计案》、《仓段化 V2 设计案》

## 0. 目标 · 红线 · 验收（A0 三门冻结）

### 0.1 目标
打造一个**领域中立（Domain-Agnostic）、纯函数驱动、拓扑感知、高扩展**的战区通用任务编排内核（Universal Task Orchestrator, 简称 **UTO**），供战术科研、基地建造、装备生产、现代化改装、重工巨构等多业务系统统一接入使用：
1. **统一数据契约**：消除 `stat_data.queues[]` 与 `stat_data.projects[]` 双账本分立与虚拟项反向投影的架构分裂；
2. **统一调度逻辑**：将九大制造产线、十一科研序列、仓段化改装工位的“容量判定、工位抢占、工时积分、暂缓跳过”抽象为统一的工位管线模型；
3. **统一指令总线**：构建领域中立的调度指令总线（Promote / Demote / Hold / Resume / Cancel / Allocate），前端各模态仅作为领域专用视图投影。

### 0.2 核心红线（严禁违背）
1. **账本写权铁律**：编排器内核恒为**纯函数**计算（输入 `state + catalog + deltaMinutes`，输出 `nextState + events`），零 Pinia、零 Vue、零宿主 API、零未受控全局变量写入；
2. **存档兼容与零破坏迁移**：严格保持现行酒馆 MVU 变量树兼容；通过双向投影适配器（Two-way Projection Adapter）实现旧档无缝水合，禁止强行要求用户重开档；
3. **领域表现解耦**：编排内核不感知 UI 样式与 DOM，仅输出结构化状态投影；科研中心、工程改装中心、日程面板、雷达预警各自负责其世界内 UI 质感呈现；
4. **零臆造数值与因果闭环**：工期推进、工位容量、算力门槛必须严格来源于静态目录或世界书实体，严禁在调度中凭空产生未声明资源。

### 0.3 验收标准
- 核心编排函数 100% 具备单元测试覆盖，包含并发工位竞争、拓扑树激活、算力赤字降级、四动词调度；
- 既有 `ModalSchedule.test.ts`、`scheduleRunner.test.ts`、`projectEngine.test.ts` 零破坏回退。

### 0.4 机制继承与升维溯源对照（三位一体演进拓扑）

UTO 并非推翻既有调度体系的新生事物，而是将《系统事务与时间推进总设计案》（时间发条基石）、《产线与产能调度总设计案》（制造空间与双模基石）、《科技研究槽总设计案》（科研分槽基石）以及《仓段化 V2 设计案》（模块拓扑基石）四者**向上抽象解耦、统领会师的中央调度总线**：

## 1. 轴一 · 统一任务实体模型（UnifiedTask）

将现行散落在 `QueueItem`（基础建造/生产/改装/研究）与 `ProjectItem`（长期工程/仓段化巨构）中的任务实体统一归一化为 `UnifiedTask`：

```typescript
/** 任务所属业务领域 */
export type TaskDomain =
  | 'construction'   // 基地基础设施/防御建筑建造
  | 'production'     // 人员训练、载具制造、军备下线
  | 'research'       // 基础与前沿理论攻坚
  | 'retrofit'       // 现役装备现代化总成改装
  | 'megastructure'; // 战略级跨基地仓段化巨构

/** 统一七态状态机 */
export type TaskStatus =
  | 'draft'          // 规划立项中（未进入正式候列，如待注资模块）
  | 'queued'         // 已立项候列（等待流水线工位空缺）
  | 'active'         // 在编推演/制造中（占用工位带宽，消耗时间/算力推进）
  | 'held'           // 奉令工务暂缓（工位让出，工时进度冻结保留）
  | 'settling'       // 实体装配就绪，待战区呈报收讫确认（指令性交付终态）
  | 'completed'      // 已验收交付/已定型并网（结项归档）
  | 'cancelled';     // 奉令撤销/作废

/** 统一任务实体契约 */
export interface UnifiedTask {
  /** 全局唯一实例标识（如 "task:prod_rhino_01", "task:proj_grizzly_v2"） */
  id: string;
  /** 任务所属领域 */
  domain: TaskDomain;
  /** 实体条令名称（如 "灰熊坦克现代化改装工程", "先进防空导弹系统"） */
  name: string;
  /** 属地范围：base=属地单基地 | theater=战区跨基地协同 */
  scope: 'base' | 'theater';
  /** 承建属地（单基地承建时必须；跨基地时为牵头基地） */
  leadBaseId?: string;
  /** 参与基地清册（跨基地巨构或协同排产用） */
  participatingBases?: string[];
  /** 目标流水线 Key（如 "基地A:lane.vehicle_land" 或 "theater:slot.main"） */
  laneKey: string;

  /** 工期负荷与工业指标 */
  workload: {
    totalMinutes: number;         // 额定总工时（分钟；0 为即时/未核定工额）
    spentMinutes: number;         // 已消耗有效工时（积分量）
    minDaysLock?: number;         // 物理硬下限（天；0 为不锁，供 2STAGE 引擎钳制最低工期）
    tflopsRequired?: number;      // 算力推演 TFLOPS 门槛
    topsRequired?: number;        // 边缘战术 TOPS 门槛
    naniteCost?: number;          // 纳米装配资源定额
  };

  /** 状态机状态 */
  status: TaskStatus;
  /** 资金账务记账（true=立项时已扣除 | false=LLM 叙事立项欠条，待对账补扣） */
  costPaid?: boolean;
  /** 批量生产批次参数（用于批量流水作业） */
  batch?: {
    totalQty: number;             // 目标总批量
    completedQty: number;         // 已下线入役批量
  };

  /** 依赖拓扑图谱（DAG 拓扑节点，支持 V1 阶段阶梯与 V2 仓段化模块拓扑） */
  topology?: {
    parentId?: string;            // 所属总成/父任务 ID
    dependsOn?: string[];         // 强依赖的前置子任务 ID 清单（全部 completed 方可激活本任务）
    subTaskIds?: string[];        // 包含的子任务 ID 清单
  };

  /** 业务领域私有元数据扩展（弱类型自由挂载） */
  metadata?: Record<string, unknown>;
}
```

## 2. 轴二 · 流水线与工位提供者接口（ILaneProvider）

将九大制造产线（`productionLanes.ts`）、十一科研序列（`researchSlots.ts`）与工程改装工位（`engineeringSlots.ts`）解耦为独立的“工位环境提供者”。编排器不硬编码产线逻辑，只消费提供者输出的工位容量与工况系数：

```typescript
/** 运行时流水线工位状态快照 */
export interface LaneStationView {
  /** 流水线全局唯一索引 Key */
  laneKey: string;
  /** 业务领域名 */
  domain: TaskDomain;
  /** 规范显示名称（如 "陆地载具生产线", "主建筑研究序列"） */
  displayName: string;
  /** 属地基地 ID（全域序列为空） */
  baseId?: string;
  /** 额定并发工位容量（0 = 产能锚定建筑不在场，序列滞留） */
  capacity: number;
  /** 工时推进加速倍率（如双模机制并联加速，基准 1.0） */
  accelMultiplier: number;
  /** 是否处于锁定态（前置建筑未建成/未并网） */
  locked: boolean;
  /** 锁定原因说明 */
  lockedReason?: string;
}

/** 领域工位提供者接口 */
export interface ILaneProvider {
  domain: TaskDomain;
  /** 根据战区基地、建筑与目录快照，推导并输出该领域的所有可用流水线 */
  resolveLanes(env: {
    bases: Array<{ id: string; name: string; buildings: Array<{ name: string; mode?: string }> }>;
    catalog: unknown;
  }): LaneStationView[];
}
```

## 3. 轴三 · 统一时间推进与结算步进机（TickEngine）

每当游戏时钟推进 $\Delta t$ 分钟时，编排器通过纯函数执行**标准三阶段结算**：

$$\Delta \text{spent} = \Delta t \times \text{accelMultiplier} \times \text{powerEfficiency} \times \text{computeRatio}$$

```typescript
export interface TickContext {
  deltaMinutes: number;          // 时钟推进时间步长（分钟）
  powerEfficiency: number;       // 战区电网供电率（0.0 ~ 1.0）
  computeRatio: number;          // 算力供需比（无算力缺口恒为 1.0，赤字时折算降速）
}

export interface TickResult {
  nextTasks: UnifiedTask[];
  completedTaskIds: string[];
  settlingTaskIds: string[];
  promotedTaskIds: string[];
  preemptedTaskIds: string[];    // 因工位容量缩减而挤退退回 queued 的任务 ID 清单
}

/**
 * 通用任务编排步进核心函数（纯函数，零副作用）
 */
export function tickTaskOrchestration(
  currentTasks: readonly UnifiedTask[],
  lanes: readonly LaneStationView[],
  ctx: TickContext
): TickResult {
  // 1. 建立流水线容量映射表
  const laneMap = new Map<string, LaneStationView>(lanes.map(l => [l.laneKey, l]));

  // 2. 第一阶段：工位带宽抢占与超额挤退裁决（Bandwidth Allocation & Eviction）
  // 遍历每条流水线：
  // a) 容量缩水挤退（Capacity Shrinkage）：若在编（active）任务数 > 容量，按末序在编优先挤退，
  //    将其安全退回 queued 态（spentMinutes 进度完整留存），记入 preemptedTaskIds；
  // b) 空额带宽升格：若在编数 < 容量，且存在候列（queued）且未暂缓（!held）任务，按序升格为 active，
  //    记入 promotedTaskIds；
  const resolvedTasks: UnifiedTask[] = currentTasks.map(t => ({ ...t }));

  // 3. 第二阶段：有效工时积分推进（Workload Integration）
  // 对所有处于 active 态的任务，结合电网与加速比积分进度
  // spentMinutes += deltaMinutes * accelMultiplier * powerEfficiency * computeRatio
  // 当 spentMinutes >= totalMinutes 时，状态转入 settling

  // 4. 第三阶段：拓扑依赖触发与离散步长边界（Topology Trigger & Discrete Step Boundary）
  // 当子任务 settling/completed 时，检查依赖它的后置任务中的 dependsOn 是否全部就绪：
  // - 就绪后，将后置拓扑节点由 draft 激活为 queued（或在容量有余且免排队时准入）；
  // - 铁律规约（零跨任务穿透）：离散单次结算步长内，新解锁的任务不继承消耗本轮结余的剩余时间，
  //   严格遵循“本轮解锁就绪、次轮竞争带宽与推进工时”的因果时序，防范单 Tick 递归穿透复杂度。

  return {
    nextTasks: resolvedTasks,
    completedTaskIds: [],
    settlingTaskIds: [],
    promotedTaskIds: [],
    preemptedTaskIds: [],
  };
}
```

## 4. 轴四 · 统一调度指令总线（UnifiedDispatchBus）

提供一组全系统通用的标准化指令动词，消除各面板各自为政的指令格式：

| 调度指令 | 语法与语义 | 前置约束与副作用 |
| :--- | :--- | :--- |
| **`Promote(taskId)`** | **调升首序**：将任务提至所在流水线候列第 1 位；若工位满员，则置换末序在编任务（工时进度完整留存） | 目标必须处于 `queued` 态；免疫终态不可调 |
| **`Demote(taskId)`** | **移送末序**：将任务移至所在流水线最后一位；若原为在编则退回挂起，由首序候列项递补 | 目标处于 `active` 或 `queued` 态 |
| **`Hold(taskId)`** | **工务暂缓**：标记暂缓令，任务立即退出在编工位回退挂起（工时留存），工位由后续项递补 | 目标不得处于终态或已暂缓态 |
| **`Resume(taskId)`** | **解除暂缓**：清除暂缓标记，任务重新参与工位带宽竞争 | 目标必须处于 `held` 态 |
| **`Cancel(taskId)`** | **工程撤销**：终止任务，释放工位与预扣资源，状态转为 `cancelled` | 非终态任务可撤销；按条令退回已扣减物资 |
| **`Allocate(taskId, baseId)`** | **承建指派**：为多基地巨构或跨区工程指派具体的属地承建车间 | 仅限 `scope='theater'` 且处于 `draft` 阶段的任务 |

## 5. 轴五 · 领域适配器与多业务系统接入

各前端业务系统不再直接维护各自底层的排队与计时逻辑，而是通过适配器模式作为 UTO 的**观察者（Observer）与指令发起者（Command Issuer）**：

1. **战时战术科研中心（PanelTech / ModalTechTree）**：
   - 接入方式：实现 `ResearchLaneProvider`，注册 11 大科研序列工位与全域算力约束；
   - 表现层：渲染高密度双栏拓扑工作台，直接监听编排器下发的多课题推演进度；
2. **重工总成改装中心（ModalEngineering）**：
   - 接入方式：实现 `EngineeringLaneProvider`，将 V1 阶段与 V2 仓段化模块注册为带拓扑树的 `UnifiedTask`；
   - 表现层：渲染车间 3D/SVG 视窗、模块网格与分体注资界面；
3. **战时基地工务日程面板（ModalSchedule）**：
   - 接入方式：作为**全景看板投影者**，直接以只读矩阵消费编排器输出的各基地流水线工位状态与工单；
   - 交互：直接绑定四动词指令组下达调度令。

## 6. 轴六 · 向下兼容与演进路线（Migration & Phasing）

为保证生产环境与现有测试的 100% 稳定性，UTO 采取**三阶段渐进式落地**：

### 阶段一：全景只读视图投影适配器（Read-Only View Adapter，首期落地）
- **持久化层零破坏**：继续保持 `stat_data.queues` 与 `stat_data.projects` 现有持久化 Schema 绝对不动；
- **单向只读纯函数投影**：
  - 实现纯函数 `toUnifiedTasks(queues, projects, lanes): UnifiedTask[]`，将双账本统一装载并归一化为标准任务列表；
  - **规避指针失配暗礁**：阶段一严格限定为**只读投影（Read-Only Projection）**，不执行反向写回（`fromUnifiedTasks`），彻底规避 `projects[].modules[].queue_index` 指针漂移与双向数据阻抗失配风险；写权与调度令维持既有链路；
- **成效**：前端模态（如 ModalSchedule、PanelTech、ModalEngineering）可以立即采用统一工位模型进行只读渲染，彻底消除表现层的多账本拼装冗余。

### 阶段二：结算内核与调度指令接管（Core Settle & Command Migration）
- **三位一体既有资产接合**：
  - 将既有 `productionLanes.ts`（九大产线分类、双模建筑容量与递减加速比）平滑封装为 `ProductionLaneProvider`；
  - 将既有 `researchSlots.ts`（十一科研序列分槽、锚定建筑开通门）平滑封装为 `ResearchLaneProvider`；
  - 将既有 `engineeringSlots.ts` 与 `projectEngine.ts`（工位注册与模块拓扑）封装为 `EngineeringLaneProvider`；
