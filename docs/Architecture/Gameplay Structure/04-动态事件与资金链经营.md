# 04 · 动态事件与资金链经营

> 静态核查：2026-10-28（基于 2026-10-14 初版与 2026-10-23 补记演进更新）。`<事件>` 14 标准动词 + 5 独立一级标签、资金链 `FD-51` 三轨结算（`credits / wallet_daily / resources_daily` 含欠料停机与商路防串轨守卫）、`establishing` 原位激活与 `exhausted` 终态防覆盖、`credits_daily` 与 `channel_daily` 双端同步、多基地时区与局部天候引擎（`timezoneWeatherEngine.ts`）、时序错位纠偏横幅（`ChronoMismatchBanner.vue`）、战术 PDA 四大页签（含 `PdaTabQuests.vue` 15 类悬赏交割与 17 个任务原型）及 `<世界演变>` 三档反剧透楼层卡均已接通；本次未运行真机。

## 1. 玩家目标与领域边界

玩家在剧情中建立贸易、矿业、物流或持续支出关系，处理战地情报、世界暗流与作战任务，让战区决策产生可追踪的三轨现金/物资流，并理解断电、欠料、局部恶略天气、受挫和枯竭的经营后果。

```text
剧情行动 → AI <事件>(14动词) 或 <资金链>/<任务>/<情报>/<世界演变>/<扩展档案> 顶层块
   ├─ 认知与任务：bookEventEntities / applyQuestBlock / appendIntel（L1/L2三级容量守卫 + 15类任务悬赏交割）
   └─ 资金链与经营：
        → 资金链五动词 / <资金链> 先入池（含本土商路防串轨软修正 D-CHAIN-NET-02）
        → 电网与建筑运转钳制（applyGridConstraints）
        → 多基地局部天候视图（timezoneWeatherEngine + withWeatherView，月球/轨道真空豁免）
        → 参谋部正向链加成（evaluateCommandHQModifiers）
        → 三轨 Δt 积分与欠料停机守卫（settleChainsDeltaT：deltaCredits / deltaWallet / deltaResources）
        → 同步写回 credits / wallet / resources / chains / credits_daily / channel_daily
        → PDA 四大页签（Events / Chains / Intel / Quests）+ 楼层战术卡片呈现
```

## 2. 事件门 14 标准动词与 5 独立一级协议标签

### 2.1 `<事件>` 14 个标准动词（`eventDoor.ts` + `parseEventsAndPatches.ts`）

1. **资金链五动词**（原仅开放 3 动词，现已全量开放）：
   - `资金链建立`（兼容 `资金链新立 / 开通 / 投产 / 激活` 等 12 个同义词）、`资金链断裂`、`资金链受挫`、`资金链恢复`、`资金链枯竭`；
   - `资金链受挫` 与 `资金链恢复` 支持解析可选 `效率 / eff` 参数（`0~2` 或 `0%~200%`），经 `registerParsedChainEventEff` 透传至 `settleFloor`。
2. **认知实体三动词**：`势力发现`、`情报获取`、`任务接取`（委托 `applyQuestBlock(..., { fromEvent: true })`）。
3. **战略协议三动词**：`协议发现`、`协议实验`、`协议排程`（支持 `加入候列 / 移出候列 / 置顶 / 上移 / 下移 / 暂缓 / 恢复` 7 动作，详见[第 02 篇](02-科技研究与战略协议.md)）。
4. **指挥与部署三动词**：`副官指派`（`CMD-PARSE-01`）、`MCV展开`、`MCV收起`（`MCV-ENGINE-01`）。

解析门按跨块累计前 5 条声明单遍保序裁决（`G04-01`），颜色仅作审计元数据。

### 2.2 独立一级协议标签（`parsePipeline.ts`）

除 `<事件>` 外，解析管线直接支持顶层平级标签：`<资金链>`（`applyChainsBlock`）、`<任务>`（`applyQuestBlock`）、`<情报>`（`appendIntel`，`defaultScope: 'tactical'`）、`<世界演变>`（`appendIntel`，`defaultScope: 'world'`）、`<扩展档案>`（`upsertExpansion`）。

## 3. 资金链 `FD-51` 三轨模型与五态生命周期

### 3.1 `IncomeChain` 扩展字段（`core/schema.ts` + `chainEngine.ts`）

- **基础与六大物理分类**：`id、name、flow、rate_daily、status、eff（0.0~2.0）、reason、updated_at_day`，以及 `chain_kind?: '采矿精炼' | '废料回收' | '油气化工' | '本土商路' | '工业转化' | '后勤维护'`（`inferChainKind` 支持按名称/建筑/载具自动推断）。
- **三轨日收支**：除 `rate_daily`（系统 `credits`）外，新增 `wallet_daily?: Record<string, number>`（本地外币正负日收支）与 `resources_daily?: Record<string, Record<string, number>>`（六柱战略资源正负日收支）。
- **物理三要素依赖与储量**：`deps: { base_id, base?, buildings: string[], vehicles?: string[], faction?: string, world_resource }`；`capacity: { total_yield: number | null, total?: number | null, extracted: number }`。
- **本土商路防串轨软修正守卫（`D-CHAIN-NET-02`）**：未绑定造币建筑（精炼厂/回收厂/暗网中继站/钻井油田）的 `本土商路` 若声明 `rate_daily > 0` 且无 `wallet_daily / resources_daily`，自动软修正为 `wallet_daily: { 本地通用货币: rate_daily }`、`rate_daily = 0` 并记 R18 黄灯。

### 3.2 五态转移与终态防覆盖闭环（`applyChainEvent`）

| 状态 | 语义 | 是否计息 | 转移与防覆盖规则 |
|---|---|---|---|
| `establishing` | 铺设中 | 否 | 收到同名/同 ID `资金链建立`（或开通/投产）时**原位转正为 `active`、`eff = 1`**，保留既有 `extracted` |
| `active` | 正常履约 | 是 | 可因事件或电网/欠料转入 `distressed`，因断裂转入 `broken`，因采尽转入 `exhausted` |
| `distressed` | 受挫降额 | 是 | `eff` 取传入值（缺省 `0.5`）；电网或欠料暂停时 `eff = 0` 并编码挂起快照 |
| `broken` | 断裂停摆 | 否 | 可经 `资金链恢复` 回到 `active`（缺省 `eff = 1.0`） |
| `exhausted` | 储量枯竭 | 否 | **终态不可逆**：`applyChainEvent` 拒绝同名 `建立` 覆盖重置；`<资金链>` 块（`BUG-R2-09`）仅在显式扩容（`nextRemainingCap > 0`）时允许恢复 |

## 4. 三轨 Δt 积分、欠料停机与 `credits_daily` 自动同步

1. **参谋部正向链加成**：`settleFloor.ts`（L1026–1040）先调用 `evaluateCommandHQModifiers` 计算 `positiveChainBonus`，临时乘算至正向计息链的 `eff`（上限 `2.0`）。
2. **欠料/欠费自动停机守卫（`FD-51`）**：`settleChainsDeltaT`（`chainEngine.ts` L360–411）根据 `stockView` 核验含负向 `wallet_daily` 或负向 `resources_daily` 的链条；若当前外币或六柱原料不足支付本轮消耗，立即降格为 `status: 'distressed'`、`eff: 0`（`[上游原料/外币不足暂停]`）并持久化，绝不透支为负数。
3. **三轨同步积分与写回**：按 `days = deltaMinutes / 1440` 同步积分输出 `deltaCredits`、`deltaWallet`（写回 `economy.wallet`）、`deltaResources`（写回 `economy.resources`，原 `null` 小类自动解锁）。
4. **`credits_daily` 与 `channel_daily` 双端同步**：`settleFloor.ts`（L1119 `calcDailyNet(persistedChains)` + `S2h_DARKNET_ECON`）与 `parseDomainAppliers.ts`（`syncEconomyChainDailySummary`）均自动重算并写回 `economy.credits_daily` 与 `economy.channel_daily`（闭合了旧版“`credits_daily` 不随链池更新”的缺口）。

## 5. 环境工况：电网钳制、多基地时区与局部天候引擎

### 5.1 电网与依赖建筑联动（`operationEngine.ts`）

`settleFloor` 将基地建筑数组（含空数组 `buildings: []`，`G04-02`）完整透传给 `applyGridConstraints`：断电或依赖建筑缺失/非运转时转为 `distressed`、`eff=0` 并编码 `[原状态:active|distressed,eff:...]` 挂起后缀；供电与建筑恢复时精确还原（`G04-03`）。

> **当前透传边界**：`operationEngine.ts` 的 `applyGridConstraints` 已实现 `deps.vehicles`（采矿车/载具核验）与 `deps.faction`（贸易势力断交核验），但 `settleFloor.ts` L1002 主调用当前仅传入 `chains / bases / nowDay`，尚未把 `forces.vehicles` 与 `factions` 传入 `applyGridConstraints`。

### 5.2 多基地时区与局部天候引擎（`timezoneWeatherEngine.ts`，FD-26）

- **标准 12 气象与选址推断**：`normalizeCanonicalWeather` 归一 12 类标准气象；`inferBaseSiteType` 推断 6 类基地选址；`resolveBaseLocalClock` 推导首基地锚定标准时区、昼夜四相位与夜间暴露乘数（`0.85`）。
- **按基地独立气象折减与真空豁免（`resolveEffectiveBaseWeather` + `withWeatherView`）**：
  - 月球（`lunar_surface`）与轨道（`orbital_dock`）基地恒为 `'真空无气象'` 且 `economyMultiplier = 1.0`；
  - 地面基地优先取 `base.weather`、缺省回退 `meta.weather`（`大雾` `0.85`，`暴雨 / 雷暴 / 暴风雪 / 强台风 / 沙尘暴 / 强磁暴` `0.50`），积分后还原持久 `eff` 防跨楼复合衰减。

### 5.3 时序错位纠偏横幅（`ChronoMismatchBanner.vue`，CTRL-UI-CHRONO-01）

当 `<生产>` 声明完工但事务剩余工时未满（三色对账门 `OVERRUN`）时，弹出琥珀色横幅，提供四按钮闭环：`[忽略]`（`dismissChrono`）、`[撤回重生成]`（`regenerateChronoFloor`）、`[自动顺延时间 +Δt]`（`autoAdvanceChrono`，差值 `<= 1440` 分钟即 1 日带宽内高亮推荐，注入 `extraDeltaMinutes` 重跑结算）、`[强制特批入役]`（`forceCommissionChrono`，写 R23 审计留痕）。

## 6. 战术 PDA 四大业务页签与楼层卡片体系

### 6.1 战术 PDA 宿主与四大页签（`pda/`）

- **收纳与展开双态**：收纳态由 `PdaBeaconButton.vue`（44×44px 纽扣）+ `PdaNotificationPill.vue`（单条轮播胶囊）+ `PdaFanoutStack.vue`（2~5 条风琴层叠通知栈）组成；展开窗 `PdaWindowFrame.vue` 支持三档尺寸切换与 Mini HUD 速览条。
- **四大业务页签**：
  1. **`PdaTabEvents.vue`（战况动态）**：消费 `derivePdaEventsFromSnapshot`，按聊天作用域隔离已读（`G04-04~06`），空态展示战地值班简报；
  2. **`PdaTabChains.vue`（资金链网）**：展示五态、六大分类徽章、三轨收支胶囊与三要素依赖；
  3. **`PdaTabIntel.vue`（五合一战区情报工作台）**：集成 `STAGING` 待收录世界书门（联动 `PdaWindowFrame.onAdoptLore` 真实写书核销 `G08-01`）、`TACTICAL INTEL` 明牌情报与 `FD-50` 情报链/暗流加密角标、`CODEX` 在册人员与 `FD-32` 信任度条、`FACTIONS` 势力简表、`MEMO` 持久化备忘录；同时在解析层执行 L1 常规情报（`<=12`）、L1 世界演变（`<=6`，5 轮自然衰减）、L2 冷存池（`<=30`）三级容量守卫（`FD-33/FD-35`）；
  4. **`PdaTabQuests.vue`（作战任务面板，FD-29/FD-30/FD-48）**：展示四态任务流转、**15 类悬赏交割胶囊**（`settleQuestRewards`，含硬封顶与 `reward_claimed` 幂等防重）与一键推进指令，联动 `planning/questArchetypes.ts`（6 大系列 17 个预设任务原型、任务链与 `FD-50` 情报链三阶推导）。

### 6.2 楼层内嵌战术卡片与三档反剧透模式（`cards/`）

`floorCardMounts.ts` 与 `floorCardExtraMounts.ts` 渲染 `<事件>` 脉冲卡、`<timePast>` 琥珀胶片条、`<资金链>` 卡、`<任务>` 卡、`<情报>` 卡，以及 **`<世界演变>` 三档反剧透隐身卡**（`mountWorldEvolutionStealthHost`：默认 `stealth` 仅显示加密暗流信号条 / `peek` 悬停毛玻璃窥视 / `full` 完全展开），同楼多卡时由 `attachCompactRackHeader` 默认折叠为单行战术导轨。
