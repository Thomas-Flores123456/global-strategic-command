# 01 · 基地建设、列装生产与产线调度

> 静态架构核查：2026-10-28（基于 2026-10-14 初版演进更新）。建造网格、空间化详情立项、三视图建筑沙盘与 Dagre 蓝图、六动词双通道日程调度、二阶段分段积分、满工时自动交割及资产入库均已接通；本次未运行真实宿主端到端验证。

## 1. 玩家目标与玩法循环

玩家根据基地设施、先决条件、电网、资金、纳米库存和算力安排建设与列装，在各基地产线中协调候列任务、切换生产/加速模式、规划三环防区布局并核对实际交付。

```text
查建设 / 生产目录（五大顶层类 + 标签/阵营/四态快筛）
    → 详情抽屉选择策略（新建/升阶/挂载）、基地、数量、层位与三环方位
    → 填框发送指令（或批准参谋部排产方案 <排产计划> 入队）
    → 解析入列与工期回填 → 新建零进度项空闲预升格（BUG-LIVE-10）
    → 按产线容量升格 → 二阶段配料/装配分段推进（含同车道溢出顺延 BUG-R2-14）
    → 满工时系统主权自动交割（BUG-R2-20）+ 三色对账门（CTRL-RECONCILE-01）
    → 建筑转正/升阶替换/挂载补建 & 部队自动入账 forces / base.forces
                          ↑
      ModalSchedule 六动词双通道调度 / ModalBuildings 产线与供电直写调度
```

这不是按现实时间跑的后台计时器。推进主要由消息中解析的游戏时间 `Δt` 驱动；同时支持在 `ModalSchedule`（默认 `instantMode = true`）与 `ModalBuildings`（开启 `editMode`）中通过 `updateFloorVars` **前端即时直写当前楼层 `stat_data`**，无需等待下一楼 AI 回复即可调整队列排程与建筑工况。

## 3. 账本与产线容量

### 3.1 队列、建筑与空间状态字段

`QueueItem.status` 是权威队列状态：

```text
queued → active → settling → done
   ↖ 暂缓 / 降序 / 超编回检
queued 或 active → cancelled（即时撤销可按未完成比例退费并联动取消工程阶段）
```

- **队列核心字段**：`type、item、base、progress、started_at、total_minutes、spent_minutes、qty、qty_done、cost_paid、min_days_lock、hold、lane`，以及新增的：
  - `building_delivered_qty?: number`：建造队列已转正的同名建筑座数（落盘默认 `0`，用于 `qty > 1` 多座同名建筑分批或完工转正防重）；
  - `auto_settled?: boolean`：`BUG-R2-20` 本楼是否已由系统满工时主权自动交割为 `done`（供同楼或后续 `<生产>` 声明幂等防重确认）。
- **建筑实例与基地空间字段**：`bases[].buildings[]` 含 `name、state、mode、accel_scope、coord（三环相对坐标）、layer（部署层位）、addons（已挂载附属模块列表）、progress、eta`；`bases[]` 另含 `sectors`（FD-38 空间防区）、`timezone_offset` 与 `weather`（FD-27）。

### 3.2 九类制造产线与统一工位中心

| 制造类别 | 容量含义 |
|---|---|
| 主建筑、防辅、其他建筑 | 对应设施（建造厂/MCV 等）提供本基地建造工位 |
| 人员、陆车、空车、舰艇、装备 | 对应在场母体设施与 `production` 模式提供工位 |
| 综合兜底 | 兜底单线容量 |

分类是九类，但单基地某类的并行容量由匹配锚定建筑的数量和 `mode === 'production'` 决定；全部转 `accel` 时容量可能为 0。`LaneRegistryHub`（`laneProviders.ts`）同时统一注册制造 9 槽（`base\0prod.<laneId>`）、工程双槽（`base\0eng.main` / `theater:eng.orbital`）、科研 11 槽（`theater:lane.research.<category>`）与统帅部条令槽（`theater:lane.protocol`）。

## 4. 四动词与六动词的确定性语义

| 动词 | 通道支持 | 主要效果 | 边界说明 |
|---|---|---|---|
| 置顶 | 即时直写 + `<队列>` 引擎 | 同工位优先，可抢占末序 `active` | 容量为 0 或 `hold` 未解除时不跳过门禁 |
| 置底 | 即时直写 + `<队列>` 引擎 | `active` 退 `queued`，排序靠后 | 不清除已做工时 |
| 暂缓 | 即时直写 + `<队列>` 引擎 | 回 `queued` 并置 `hold: true` | 不是取消，不销毁任务 |
| 恢复 | 即时直写 + `<队列>` 引擎 | 清 `hold`，重新参加升格 | 不跳过容量 / 全局上限 / 纳米门 |
| 撤销 | 前端即时直写（或托盘发文本） | 置 `cancelled`，联动取消 `projects`，按未完成比例退还 `credits` | 底层 `<队列>` 解析器 `DISPATCH_VERBS` 仅消费前四动词；托盘模式下依赖下一楼 AI 响应 |
| 指派 | 前端即时直写（或托盘发文本） | 跨基地改派承建 `base` | 同上，直写模式立即落盘 `stat_data` |

## 5. 时间、二阶段分段积分与双模

### 5.1 本楼预升格、时间积分与同车道溢出顺延

- **本楼新建零进度项预升格（`BUG-LIVE-10`）**：当 `deltaMinutes > 0` 时，`settleFloor`（L470–524）对本楼新增零进度 `queued` 项在空闲产线上先执行一次 `0` 分钟 `settleWithTwoStage` 预升格，使其在本楼立即转 `active` 并吃满本楼 `Δt`。
- **同车道溢出顺延（`BUG-R2-14`）**：`transactionEngine.ts`（L391–530）在同车道 `active` 项本楼跑满转 `settling` 且有剩余墙钟时间 `remWall > 0` 时，自动顺延给紧随其后的同车道 `queued` 项。

### 5.2 二阶段跨边界加权分段折算与纳米门禁

- **跨阶段边界精确拆段**：`twoStageAssemblyEngine.ts` 的 `makeTwoStageEffFor`（L280–286）已实现单步 `Δt` 跨越阶段一边界 `phase1End` 时的加权分段折算公式 `(phase1Remain + (deltaMinutes * base - phase1Remain) * p2) / deltaMinutes`。
- **纳米升格硬门禁与批次修正**：`advanceTwoStageProduction` 内置 `strictNanitePromotionGate`（`SIM-NANITE-01`），当可用纳米不足 `req_nanites` 时阻断升格；带纳米配料批次（`qty > 1` 且 `req_nanites > 0`）在阶段一备料期保持 `qty_done = 0`，进入阶段二后按组装进度折算下线台数，并由 `deductNanitesStock` 真实扣减 `economy.resources.nanites`。

### 5.3 建筑双模与 MCV 部署

- **双模双轨**：在 `ModalBuildings`（`editMode`）或 `ModalSchedule`（`instantMode`）中切换建筑 `production ⇄ accel` 或 `same_type ⇄ global`，通过 `updateFloorVars` **当楼即时修改并重算 `base.power`**；而经 AI 叙事 `<命令>` 块走 `settleModeSwitches`（`productionLanes.ts`）时，仍遵循「本轮登记 `mode_switching`（720 分钟校准）、到期翻转」的合同。
- **MCV 部署**：`deploymentEngine.ts` 处理展开/收起在途事务与模式切换冲突护栏；基地收起且建筑清空后标记“废弃”保留历史实体。

## 6. 满工时主权自动交割、三色对账与资产自动入账

`settleFloor.ts` 与 `useParse.ts` 现已实行**「满工时系统主权自动交割（`BUG-R2-20`）+ 三色对账门（`CTRL-RECONCILE-01`）双保险」**：

1. **满工时自动交割（`autoSettleCompletedQueues`）**：只要队列推进至 `status === 'settling'`（`spent_minutes >= total_minutes`），即使当楼 LLM 未输出 `<生产>` 标签，`settleFloor`（L622–720）与 `useParse`（L454–475）也会当楼自动将其交割为 `done`（打标 `auto_settled: true`）并执行 `applyAssetClaim` 资产入账。
2. **三色对账门（`reconcileProduction`）**：
   - **MATCH**：正常收讫结项；若该项已 `auto_settled: true`，幂等确认不重复入账。
   - **UNDERRUN**：数量少报时，已认领部分拆成 `done`，余量续跑。
   - **OVERRUN / REJECTED**：未满工时抢跑或超产声明保留原账本并告警拦截。
3. **资产自动入账闭环（`applyAssetClaim`）**：
   - **列装与改装自动入库 `forces`（`ARM-02`）**：通过 `buildItemCategoriesFromCatalog(catalog)` 注入单位分类表，在本楼未显式覆盖部队（`!forcesExplicitlyUpdated`）时，自动按 `troops / vehicles / equipment` 写入全局 `state.forces` 与属地 `targetBase.forces`（航天装备同步写 `state.space.equipment_stock`）。
   - **建造完工自动转正、升阶替换/挂载与缺失自动补建（FD-22 / FD-38）**：优先将同名 `state === '建造中'` 实例按 `building_delivered_qty` 逐座转正为 `'运转'`；支持 `BUILTIN_BUILDING_UPGRADE_SPECS` 的 `replace`（原位替换母体并更名）与 `addon`（写入母体 `addons` 并推入运转实例）；当目标基地无同名预插建筑且非纯外挂升级包时，**自动向目标基地 `buildings` 推入新运转建筑**，并在结算后调用 `recomputeBasePowerFromCatalog` 动态重算基地电网。
