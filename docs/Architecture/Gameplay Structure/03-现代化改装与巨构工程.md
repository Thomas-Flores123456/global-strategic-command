# 03 · 现代化改装与巨构工程

> 静态核查：2026-10-28（基于 2026-10-14 初版演进更新）。三页签工程工作台、V1 五令与 V2 四令（含跨基地模块指派 `Allocate`）、V1 完工存量单位/建筑原位升格（47 项规格）、V2 纳米真实扣库、暂停释放准入槽与恢复复验、同楼对账后补跑 `syncProjects` 及跨书 SVG 场景路由均已接通；本次未运行真机。

## 1. 玩家目标、入口与循环

玩家为现代化改装或战略巨构分期投入资金与纳米工料，协调基地工位、前置科技/协议、阶段/模块依赖与物理工期，最终取得单位/设施型号原位升格或巨构完成标记。

### 1.1 实际入口与三页签工作台（`ModalEngineering.vue` + `modalEngineeringHelpers.ts`）

中控快捷“工程”打开 `ModalEngineering`：
- **左栏三页签**：已从原“短期 / 长期”双标签扩展为 **`短期改装 (short)` / `长期巨构 (long)` / `🚀 天基航天 (space)`**（天基航天四子视图与蓝图画布详见[第 06 篇](06-航天工业与天基工程.md)）；`短期改装` 页签除等级筛选（全部/大改/中改/小改）外，新增 **兵种与对象分类筛选**（`SHORT_CATEGORY_FILTERS`：全部 / 陆战 / 空军 / 海军 / 设施）。
- **改装蜕变横幅与立项三门清单**：通过 `resolveRetrofitTargetPreview`（FD-22）展示改装对象、升级后高级型号 `upgraded_name` 及当前存档在役数量 `inServiceCount`；右侧通过 `buildEngineeringGateChecklist` 结构化核验前置理论、工程工位、资金与纳米预算。
- **V1 五令与 V2 模块四令**：
  - V1 提供 **立项、注资、暂停、恢复、取消**；
  - V2 提供工程级 **立项、暂停、恢复、取消**，以及模块级 **模块注资、模块暂停、模块恢复、模块指派基地（`buildAllocateModuleOrder`，当 `scope === 'theater' && bases.length >= 2 && mod.status === '未启动'` 时展示「指派基地」按钮）**。
  - 按钮经 `alignEngineeringActionWithDispatchBus` 对齐 `UnifiedDispatchBus` 动词（`Hold / Resume / Cancel / Allocate`）后调用 `fillHostSendInput` 填入聊天框。
- **Mock 退场门控修复（`FIX-P1-03`）**：`resolveUsingMock` 结合 `checkHasLiveRuntimeState`，**只要快照含实时战局状态（`meta.world_id`、非空 `queues`、`tech.done`、`credits > 0` 或非空 `protocols`），即使 `projects[]` 为空也绝不回退 `MOCK_PROJECTS`**，仅在无实时战局的纯空预览态或 `demoMode === true` 时展示演示实例。
- **跨书 SVG 场景路由（`engScene.ts` + `engSceneAsset.ts`）**：`scene.station.*` 路由至 `['工程·通用', '工程·盟军']`，其余路由至 `['工程·盟军', '工程·苏联']`（支持裸名与 `_世界书` 后缀双名探测及 `WeakMap` 缓存）；内置 `scene.workshop.generic`（通用改装车间）与 `scene.aerospace.mcc`（天基测控三视角 `pad / leo / tli` × 五热点）。

```text
选择目录定义 → 填框工程指令 → 玩家发送 → AI <工程>
 → engAndDeployOrders 收集与载荷归一 → engOrderBridge 可信度对齐与分流
 → projectEngine / projectEngineV2Core 裁决（扣款 + V2实扣纳米 + 写实例与queue投影）
 → Δt推进 → 满工时自动交割(autoSettleCompletedQueues) / 三色对账done
 → syncProjects（settleFloor内 + reconcileProduction后双次同步）
 → 全部完工 → outcome标记 + V1自动执行 applyRetrofitCompletionUpgrade 原位升格存量单位/建筑
```

## 2. 双版本账本、期次 ID 与 V1 型号实质兑现

运行账本为 `projects[] + queues[]`。每个项目元素用 `schema_version` 区分 V1 / V2（旧元素无版本补 V1），共同字段包括 `id、ref、scope、bases、lead_base、grade、status、outcome`。

| 结构 | 内容 | 启动与定位规则 |
|---|---|---|
| V1 `phases[]` | `idx / name / status / queue_index` | 串行，后段要求全部前序完工 |
| V2 `modules[]` | `id / name / status / base / assigned_base / queue_index` | 模块 DAG，所有依赖完工后可启动；立项仅自动注资定义顺序的**第一个根模块** |

- **重立项期次后缀 ID（`UX-SCHED-01`）**：同基地同名工程在旧实例终态（完工/取消）后重立项时，由 `allocateProjectInstanceId` 自动分配 `proj:<defName>@<leadBase>#2`、`#3` 期次后缀。
- **队列下标漂移自动重定位（`FIX-P1-03`）**：`resolveEngineeringQueueIndex` 校验 `(type==='工程', base, canon(item))`，当 `queues[]` 前置剔除导致下标漂移时自动重定位并修正 `queue_index`。
- **V1 完工存量单位/建筑原位升格（FD-22 / FD-37）**：
  - 账本字段仍写 `outcome: { type: 'mark' }`，但 **`syncProjects` 在 V1 工程全部阶段完工时会自动调用 `applyRetrofitCompletionUpgrade`**；
  - 依据 `BUILTIN_RETROFIT_UPGRADE_SPECS`（内置盟军 23 项 + 苏联 24 项共 **47 项改装规格**，含 45 项单位改装与 2 项建筑改装），自动将 `state.forces`（`vehicles / aircraft / troops / infantry / equipment / girls[].model`）、`state.bases[].forces` 及牵头基地 `buildings` 中的旧型号原位更名为 `upgraded_name`（含小鹰级/尼米兹级航母分流更名与同型号数量合并）；
  - `projectEngineHelpers.ts` 另提供 `evaluateRedStarHammerPayload`（`SOV-CODE-CAP-01`），支撑苏联「赤星天锤3→6枚扩仓改装模块」载荷上限计算。

## 3. 工程令解析、桥接与裁决三模块

- **`parse/engAndDeployOrders.ts`**：`<工程>` 收集逻辑已独立成模块，支持 `normalizeEngBlockPayload`（`BUG-LIVE-07` 兼容 YAML 数组与同级简写键值），支持 **立项、注资、暂停、恢复、取消、驳回、指派** 7 类动词及 `ENG_VERB_ALIASES` 别名；注资令省略 `phase / module` 时放行至桥接层自动推导（`BUG-LIVE-20a`）。
- **`engines/engOrderBridge.ts` + `engOrderHelpers.ts`**：接入 `evaluateEntityCredibility`（阈值 `0.78`）执行工程名/实例名高可信度容错对齐；支持 `指派 / 分配 / allocate` 调用 `assignModuleBase`；注资缺省时自动推导首个/唯一就绪阶段或模块；通过 `projectEngineeringObserverView` 提供 UTO 同源只读观察层投影。
- **`projectEngine.ts` + `projectEngineHelpers.ts` + `projectEngineV2Core.ts`**：前置科技门通过 `buildCompletedTechAndProtocolSet` 联合校验 `tech.done ∪ activeProtocols`（`FIX-P1-02`）。

## 4. 资金、纳米（V1门槛 vs V2实扣）与工位占槽规则

### 4.1 分期资金与取消不退

立项成功扣首期款，后续注资只接受未启动阶段/模块；取消时已注资资金不退、未完成折算进度作废。

### 4.2 纳米库存：V1 门槛不扣 vs V2 真实扣库（`SIM-NANITE-01`）

- **V1 改装工程（`startProject` / `startPhase`）**：保持 D8b「纳米开工门只校验门槛、不扣库存」。
- **V2 仓段化工程（`startProjectV2` / `investModule`）**：在 `checkModuleGates` 校验可用纳米达标后，**调用 `deductEconomyNanites` 从 `economy.resources.nanites` 按 7 档小类优先级（`通用 → 标准 → 军工 → 特种 → 高精构造型 → 高能 → 机娘修复凝胶`）真实扣减纳米库存**；取消时已消耗纳米不予退还，也不再重复扣减。

### 4.3 基地工位与暂停释放准入槽（`FIX-P1-03`）

- **锚定词表**：
  - `eng.main`（通用工程槽）：`['建造厂', 'MCV', '维修所', '军工车间', '造船厂', '科学城']`；
  - `eng.orbital`（轨道组装泊位）：`['航天发射中心', '海上发射平台', '大型航天发射综合体', '山体发射场', '巨型航天发射港']`（兼容 `'天基轨道船坞'`）；
  - `isEngBuildingActive` 排除 `['建造中', '停机', '受损', '离线', '被毁', '战损']`。
- **暂停释放准入槽与恢复复验**：`engagedSlotCount` 现包含 `if (q.hold) return false`——**暂停态（`hold=true`）模块不再占用 `eng.orbital` 准入槽**，允许让位给同基地其他模块；相应地，**`resumeModule` 与 `resumeProjectV2` 在清除 `hold` 恢复前强制复验属地空余槽位容量**，满槽时拒收恢复令（`no_slot`）。

## 5. UTO 演进与同楼对账次序风险闭合

- **权重纠偏与过时注释清理**：`weightsForType('工程') → WEIGHT_TENSOR`（**TFLOPS 0.3 / TOPS 0.7**），缺 `t_mat/t_asm` 时阶段时间占比默认 50/50；原 `projectEngine` 头部过时的“0.5/0.5”注释已在三模块拆分重构中彻底删除。
- **同楼对账与后续注资次序风险已闭合（`BUG-R2-20` + `FIX-P1-03`）**：
  1. `settleFloor.ts`（L622–698）在满工时进入 `settling` 时先执行 `autoSettleCompletedQueues` 自动转 `done`，再于 L906 执行 `syncProjects`；
  2. `useParse.ts`（L454–496）在 `reconcileProduction` 对账后、调用 `applyEngOrders`（L528）前**显式补跑第二次 `syncProjects`**，使同楼后续 `<工程>` 注资令能立即感知当楼刚刚竣工的阶段/模块。
