# 07 · 多阵营联席、阵营解锁与机娘协同

> 静态核查：2026-10-28（基于 2026-10-14 初版与 2026-10-23 补记更新）。开局 1～3 阵营预算/暴露度/磨合惩罚折算、局内双通道阵营启封、暴露度与民心双驱引擎（`exposureMoraleEngine.ts`）、三类楼层卡片双轨水合（`FactionUnlockCard / MaidenDossierCard / MaidenStatusCard`）、四维军备与机娘全角色正史动态回读（`ModalMechaGirl.vue`）、`《机娘·能力档案》` 全战区常备化及聊天绑定档案书单书双段自动入档（`CTRL-CHATBOOK-01`）均已落地；全角色专属技能细粒度战斗公式化仍属远期演进。本次未运行真机。

## 1. 玩法目标与双轨架构闭环

玩家组织跨阵营战区参谋部，以多科技体系和机娘专长换取预算、暴露和磨合压力：

- **开局轨（启动器）**：选择 1～3 阵营、开场切入模式（`field_drop / pre_transmigration / dormant_infiltration`）、系统通联时机与机娘孵化三模式（`iconic_plus_blindbox` 经典 MCV + 战地盲盒赐名方案 B / `full_blindbox` / `preset_roster`），配置主官 Persona、阵营主责副官与人类随行名册（`humanRoster`）。
- **局内轨（双通道启封 + 副官调度）**：经 `<阵营解锁>`/`<阵营启封>` 标签或战略任务 `Tier S: unlock_factions` 奖励确权新阵营、授予唯一首发 MCV 与机娘、注入 15 日异构磨合惩罚、同步切换阵营四书，并通过 `<事件>` 副官指派或中控操作调整席位。

## 2. 启动器多阵营折算与局内双通道启封

### 2.1 开局 1～3 阵营确定性折算公式（`presets.ts` + `pipeline.ts`）

`computeMultiFactionLaunchImpact`（`presets.ts` L1032–1083）与 `buildOpeningSeedStatData`（`pipeline.ts` L176–260）已冻结多阵营首发代价：

| 开局阵营数 | 初始资金倍率 | 初始暴露度增量（及 `0~10` 标度折算） | 异构磨合惩罚（`command.penalties`） |
|---|---|---|
| **单阵营开局** | `×1.00` | `+0`（`0.0`） | `0` 项 |
| **双阵营并网** | `×0.85` | `+15`（经 `schema.ts` `z.preprocess` 折算为 `1.5`） | 第 2 阵营注入 1 项 15 日（`21600` 分钟）磨合惩罚 |
| **三阵营全开** | `×0.75` | `+30`（折算为 `3.0`） | 第 2、第 3 阵营各注入 1 项 15 日磨合惩罚 |

此外，`syncAdjutantsFromHumanRoster` 支持人类随行人员分流：`assignment === 'companion'` 时随行不占副官槽、0 日薪；指派为 `staff` 或 `faction:xxx` 时生成 `source: 'human'`、`daily_upkeep: 80` 的在役副官。

### 2.2 局内双通道阵营启封与四联联动

1. **双入口汇流**：独立 `<阵营解锁>`/`<阵营启封>` 标签（`factionUnlockParser.ts`）与 `<任务>`/`<事件>` 任务完成奖励 `unlock_factions`（`parseDomainAppliers.ts` L5157–5196）统一调用 `settleFloorPhases.ts` 的 `applyFactionUnlockSettlement`：
   - 写入 `command.unlocked_factions` 与 `command.mcv_granted_factions` 唯一赠送锁（`G07-01`）；
   - 注入 15 日（`21600` 分钟）磨合惩罚至 `command.penalties`；
   - 授予首发 MCV 载具至 `forces.vehicles` 并注册对应 MCV 机娘至 `forces.girls` 与 `girls` 档案表；
   - 若该阵营主责副官槽为空，自动将该 MCV 机娘指派入 `command.adjutants`（`role: 'faction'`）。
2. **四书同步与 Swipe 回退（`G07-05`）**：`worldbookManifest.ts` 的 `planFactionWorldbookSync` 与 `floorObservers.ts` 的 `syncMultiFactionWorldbooksOnFloorEvent` 按 `unlocked_factions` 与 `worldId` 自动启用/卸载阵营四书（武备、特色建筑、特色科技、工程），保留非受管自定义世界书并在 Swipe 回退时对齐分支事实。
3. **科技与协议门控（`CMD-UI-01`）**：`ModalTechTree.vue`、`PanelProtocol.vue` 与 `ConsoleBuildGrid.vue` 均按 `command.unlocked_factions` 控制阵营胶囊与科研院所显现。

## 3. 暴露度与民心（士气）双驱结算引擎（`exposureMoraleEngine.ts`，FD-36）

存储于 `stat_data.exposure`（`value / level / floor / trend / updated_at_day`）与 `stat_data.morale`（`stage / engaged / economy_mult / exposure_drift / summary`），并在中控顶栏 `ConsoleTopNav.vue` 与 `<态势>` 楼层卡中实时呈现：

- **暴露度五档（`0.0~10.0`）**：`EL-0 日常隐蔽`（`0~2.0`）、`EL-1 民间流言`（`2.0~4.5`）、`EL-2 官方介入`（`4.5~7.0`）、`EL-3 战略围剿`（`7.0~9.0`）、`EL-4 位面出圈`（`9.0~10.0`，一旦触发 `>=9.0` 则 `floor` 不可逆锁死为 `9.0`）。
- **同基地跨阵营混建暴露摩擦**：`computeExposureFloor` 对同一基地内激活的跨阵营建筑种类数自动抬升暴露底线（**2 阵营混建 `+0.4`，3 阵营混建 `+0.9`**），叠加超武/巨炮（`+0.6`）、伪装建筑（`-0.35`，最多 2 座）与基地选址修正。
- **民心双轨状态机**：本土势力全处于 `'未接触'` 且 `exposure.value < 4.5` 时为第 0 态 `'无人在意'`（资金倍率 `1.0`，暴露漂移 `0`）；接触任一势力或暴露度 `>=4.5` 后激活五阶民心（`人心惶惶 ×0.75/+0.10`、`疑虑观望 ×0.9/+0.04`、`秩序井然 ×1.0/0`、`欣欣向荣 ×1.1/-0.06`、`万众归心 ×1.2/-0.12`）。

## 4. 副官席位、机娘双轨模型与四步自动桥接

### 4.1 副官任免与结算精度

- `<事件>` 副官声明（`applyAdjutantEventDeclaration`）强制校验目标阵营已解锁、机娘在编且非重损/离线；人类副官解任转 `status: 'standby'` 待命保留，机娘副官解任移出槽位。
- `settleCommandHQSlice` 对人类副官日薪采用累计时长/余数精度结算（`G07-03`），对磨合惩罚按 `min(remaining_minutes, deltaMinutes)` 计费衰减（`G07-04`）；`evaluateCommandHQModifiers` 对重损/非在役机娘副官停发加成（`G07-02`）。

### 4.2 机娘双轨数据模型与四步桥接闭环（`parsePipeline.ts` + `parseDomainAppliers.ts`）

`parsePipeline.ts`（L539–552）在合并 `<战况>` 的 `部队.机娘` 与 `<机娘档案>`（兼容别名 `机娘卷宗`）后，依次执行四步同步：
1. `syncDossierToForcesGirls`：将 `data.girls` 中的机娘同步回填至 `data.forces.girls`；
2. `bridgeGirlDossierFieldsFromGirlsBlock`：当 `<战况>` 部队机娘或顶层 `<机娘>` 块附带 `好感 / 服从 / 特质 / 型号` 时，自动桥接更新 `data.girls`（支持 `好感变化 / 服从变化` 增量计算与 `[0, 100]` 钳制）；
3. `syncChristenedGirlsToCodex`：将所有已赐名（`!unchristened`）机娘自动注册或更新至 `data.codex`（`kind: '机娘'`）；
4. `syncPendingGirls`：维护 `data.pending_girls` 待授名队列，完成赐名或 `rename_from` 更名后自动移除旧占位并合并档案。
- **未展开基地锁止守卫（`MCV-ZERO-BASE-01`）**：基地展开前强制保留 `unchristened = true`，防止提前解锁战地武装态。

## 6. 当前技术边界与待核查细节

1. **UI 副官指派前置校验与 AI `<事件>` 校验的宽严差异**：`applyAdjutantEventDeclaration` 强制拦截未解锁阵营与重损机娘，而中控 `models/operationEngine.ts` 的 `canStartOperation` 目前仅校验姓名非空与参谋槽上限（结算时 `evaluateCommandHQModifiers` 仍会拒绝给重损/非在役机娘发放加成）。
2. **同楼层 `<事件>` 副官指派与 `<阵营解锁>` 顺序**：`useParse.ts` 先执行 `applyAdjutantEventDeclaration` 后执行 `applyFactionUnlockSettlement`；同楼解锁新阵营时由 `<阵营解锁>` 自身的默认主责副官指派兜底。
3. **残缺卡片缺省名常量差异**：核心预设 `commandPresets.ts` 定义三阵营首发 MCV 机娘为 `白凌 / 喀秋莎 / 尤里卡`（标准解析器使用该映射回填），而 `floorCardParsers.ts` 的 `DEFAULT_FACTION_META` 在直接传入省略 `mcv_name` 的残缺卡片数据时的本地兜底常量为 `雅典娜 / 喀秋莎 / 天秤`。
