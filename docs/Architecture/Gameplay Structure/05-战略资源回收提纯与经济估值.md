> 静态核查：2026-10-28（基于 2026-10-14 初版与 2026-10-23 补记更新）。六柱三态非负约束、独立资源合并器（`resourceMerge.ts`）、资源面板双页签与快筛折叠、跨维暗网实物/情报交割、资金链三轨结算（`FD-51` `wallet_daily / resources_daily` 含欠料停机守卫）、回收厂解除精炼厂硬绑及纳米低阶优先实扣均已接通；仅单批次实物 L0–L3 进炉工期配方台与建造/生产原料代偿配方（`RECIPE-01`）仍属远期演进。

## 2. 三套账轨隔离与受控跨轨耦合

| 账轨 | 语义 | 边界与受控跨轨通道 |
|---|---|---|
| `economy.credits` | 系统内部纳米重构产能通用记账 | `<战况>` 非首楼裸改 `credits` 被 `disallowLegacyWarStatCredits` 拦截告警 |
| `economy.wallet` | 按世界货币名索引的本地钱袋 | 严禁按固定汇率直兑 `credits`；仅可经 `FD-51` 跨轨商路或任务结算受控流转 |
| `economy.resources` | 六柱实体库存（纳米、矿产、建材化工、燃油能源、军械弹药、维生后勤） | 仅经纳米排产/V2工程实扣、`FD-51` 商路流式消耗/产出、`<暗网>` 交割或任务奖励改写 |

### 独立资源解析器（`resourceMerge.ts`）

资源合并已从 `parseDomainAppliers.ts` 独立拆分为 `parse/resourceMerge.ts`：

- **非负约束与隔离（`G05-01`）**：Schema 六柱值统一为 `z.number().nonnegative().nullable()`；`mergeResourceRecord` 支持 `XX变化` 增量键（`Math.max(0, cur + d)`），对直写负值或非数字值执行键级 `quarantine` 隔离（`error: '资源库存不得为负'`），对数值回写 `null` 触发 R18 🟡 告警。
- **平铺纳米工料兼容**：`applyResources` 兼容 LLM 在 `<态势>.资源` 下直接平铺四类纳米工料及简称（如 `通用纳米`、`修复凝胶`）或 `XX变化` 增量键，自动归入 `economy.resources.nanites` 并同步镜像至 `economy.nanites`。

## 3. 进炉估值：设计基准与当前双路径承载

进炉设计以标准矿满载约 500 credits 作为 BME 锚点，加工深度分为 **L0 粗投、L1 粗拆分选、L2 纳米精拆、L3 湿法/火法提纯**（浅矿到 L3 约 ×1.3，混杂废料 ×1.7，富集料 ×2～2.5，复杂高值料 ×3；天然共生原矿仅 L3 获 15%/25%/40% 伴生增益且不双计入库；灵石等纯能量材料走独立转化线）。

当前运行时通过两条确定性路径承载其经济产出：
1. **建筑被动基载（`computeBuildingPassiveDailyCredits`）**：按在场运转的精炼厂、回收处理厂、油化设施及同基地 `矿石精炼器` `+25%` 乘区计入日流；
2. **`<暗网>` 实物投递交割（`tryDeductResource`）**：校验并实扣六柱库存，将估值 `credits` 入账。
而“选定单批次原矿/废料 → 选 L0–L3 档位 → 校验废液/算力 → 跑加工工期 → 产出”的独立车间配方引擎仍属远期扩展。

## 5. 资金链三轨结算、纳米低阶优先实扣与多元被动经济

### 5.1 资金链三轨积分与欠料停机守卫（`FD-51`）

`chainEngine.ts` 的 `settleChainsDeltaT`（L306–485）与 `settleFloor.ts`（L1071–1125）已将 `IncomeChain` 从纯 `credits` 扩展为 **`rate_daily`（系统资金）+ `wallet_daily`（本地外币）+ `resources_daily`（六柱实物消耗/产出）三轨同步积分**：

- 当链条配置了负向 `resources_daily`（消耗上游原矿/燃料）或负向 `wallet_daily`（采购支出）时，`settleChainsDeltaT` 先校验当前 `stockView` 库存/余额是否充足；
- **欠料/欠费停机守卫**：若上游六柱原料或本地外币不足以支付本轮消耗，链条自动转入 `distressed`、`eff=0` 并标注 `[上游原料/外币不足暂停]`，绝不扣穿库存；充足时真实增减 `economy.resources` 与 `economy.wallet`（原小类为 `null` 且净流入 `>0` 时自动解锁入库）。

### 5.2 纳米减时、先调度后预扣与低阶优先实扣

`twoStageAssemblyEngine.ts` 的 `settleWithTwoStage` / `advanceTwoStageProduction` 与 `settleFloor.ts` 已完成纳米预扣顺序及真实扣库闭环：

- **先调度后预扣（`G05-02`）与严苛升格门（`SIM-NANITE-01`）**：`settleWithTwoStage` 先且仅执行一次 `applyDispatchOrders`，随后仅对仍处于 `active` 且零进度的任务执行 `applyNaniteDeduction` 预扣并递减 `deductedSoFar`；`advanceTwoStageProduction` 开启 `strictNanitePromotionGate`，纳米不足时阻断升格。
- **低阶优先真实写回库存**：`settleFloor.ts`（L482–553）调用 `settleFloorHelpers.ts` 的 `deductNanitesStock`，按 `NANITE_DEDUCTION_PRIORITY`（`通用纳米工料 → 标准纳米工料 → 军工纳米工料 → 特种纳米工料 → 高精构造型纳米 → 高能纳米工料 → 机娘修复凝胶`，其余动态键殿后）从 `economy.resources.nanites` 真实分摊扣减。
- **工程 V1 与 V2 纳米口径区分**：工程 V1（`checkPhaseGates`）保持 D8b「纳米开工门是门槛不扣减」；工程 V2（`projectEngineV2Core.ts` 的 `startProjectV2` / `investModule`）调用 `deductEconomyNanites` 执行真实纳米扣减并生成实付回执（`ENG03-04`）。

### 5.3 多渠道被动经济与防双计守卫（`darknetEngine.ts`）

`computeBuildingPassiveDailyCredits`（L2150–2246）扫描运转且未断电基地的精炼（`矿石精炼厂`/`奴隶矿场` +5000、`巨型自动化矿业综合体` +80000）、独立回收（`废弃电子产品回收处理厂` +1200）、油气重化（`抽油机`/`科技钻油井` +800、`炼油厂` +1500、`化工合成厂` +1200、`合成燃料工坊` +1000）及同基地 `矿石精炼器` `+25%` 乘区，内置 `isCoveredByChain` 防双计守卫（已被有效主资金链 `deps.buildings` 绑定的建筑不重复计入被动基载，同时豁免小额走私/副产支线 `BUG-LIVE-06`），在 `tickDarknetAndPassiveEconomy` 与解析层 `syncEconomyChainDailySummary` 双端同步 `economy.channel_daily` 与 `economy.credits_daily`。
