# 02 · 科技研究与战略协议

> 静态核查：2026-10-28（基于 2026-10-14 初版演进更新）。双生主厅多阵营筛选、缺失前置跨厅直跳、11 槽非运转态过滤与先回检后积分、无基地战区算力汇总、9 座三阵营协议锚点、30 项默认协议非破坏合并、协议自动排程写通道及 11 槽科研建议均已接通；本次未运行真机。

## 1. 目标与双生主厅入口

玩家选择研发路线，协调 11 大科研工位与全局并行上限，利用算力缩短物理工期；战略协议则以发现、前序准入、点数与资金实验、保底突破形成另一条战略成长路径。

### 1.1 `ModalTechTree.vue` 双生主厅与多阵营门控

- **顶栏与多阵营筛选（CMD-UI-01）**：顶栏提供「科技树 / 战略协议」双厅切换、观察摘要芯片、三档视口尺寸切换（`wide` 加宽 / `full` 全屏 / `compact` 标准，持久化至 `localStorage['ra_tech_modal_size_v1']`），以及**多阵营筛选胶囊条（`通用 / 盟军 / 苏联 / 尤里`）**。
- **解锁门控与快照归一**：基于 `snapshot.command.unlocked_factions`（缺省 `['allied']`，支持 `isDebugUnlockAllFactionsActive()` 调试全开）过滤 `filteredResearches` 与 `filteredProtocols`，未解锁阵营胶囊显示 `🔒` 且禁用点击；组装 `activeSnapshot` 时调用 `ensureComputeFacilitiesInCatalog`（借助 `inferDefaultBuildingCompute` 自动补齐目录及基地建筑的默认名义算力：T3 院所/量子超算 `120 TFLOPS / 60 TOPS`，超算中心/各阵营 T2 实验室 `50 TFLOPS / 30 TOPS`），将建筑状态 `'正常'|'运行'|'运行中'|'在线'` 归一为 `'运转'`，并用 `filterDynamicCodexResearches` 剔除与系统目录重名的 `codex` 科技。

### 1.2 `PanelTech.vue` 科技厅与跨厅直跳

- **三栏总览 HUD**：展示阵营科技代际（`derivePanelFactionTiers`，含升级进度与下一代际条件）、11 大科研课题组看板（`slotBoard`：常驻展开 `slot.main / slot.faction / slot.mecha` 3 主线槽 + 可折叠 8 专科槽 + 游离在研项 `orphanActives`）、科研算力总览（`computeOverview`）。
- **筛选、排序与双视图**：支持 6 态筛选（`all / active / queued / ready / done / locked`）、3 种排序模式（`tactical` 作战推荐 / `tier` 代际 / `line` 领域归类 `TECH_LINE_PRIORITY_EXACT`）、2 种视图模式（`grid` 网格 / `accordion` 科技线手风琴）及领域药丸导航。
- **UX-08 缺失前置可点击直跳芯片（`MissingPrereqChip`）**：锁定科技卡展示结构化缺失前置芯片；点击 `protocol` 芯片触发 `@jump-to-protocol` 切至协议厅并高亮定位目标协议；点击 `tech` 芯片在科技厅内平滑滚动并高亮目标卡片 2200ms；点击 `building` 芯片调用 `openLookup` 打开建筑详情。
- **科研立项双通路**：科技卡本身保持只读详情；立项除来自 `DetailDrawer` 填框或对话下达 `<进度>` 声明（`研究|项目名|...`）外，`parsePipeline.ts`（PKG-D / FD-27）已支持 **`<排产计划>` 标签 `enqueue` 通路**（当 `kind === '研究'` 时经名称对齐与可信度校验，防重创建 `type: '研究', status: 'queued'` 入队）。

### 1.3 `PanelProtocol.vue` 协议厅与指令下达

## 2. 科研 11 槽、运转态门禁与先回检后积分

科研占用从 `queues` 中的研究事务派生。当前 11 槽注册表（`SLOT_REGISTRY`）为：

| 槽 ID | 覆盖方向 / 锚点提示 |
|---|---|
| `slot.main`（主建筑） | 建造厂 / MCV（支持 `deploy.capabilities` 含 `'research'` 的展开能力回退） |
| `slot.industry`（工业基础） | 矿石精炼厂 |
| `slot.defense`（防御辅助） | 兵营 |
| `slot.vehicle`（载具） | 陆、空、水面研究共槽；战车工厂 |
| `slot.infantry`（人员） | 兵营 |
| `slot.equipment`（人员装备） | 装备制造所 |
| `slot.agriculture`（农畜业） | 水培 / 生态副食设施 |
| `slot.environment`（环保） | 基础废物分拣站 |
| `slot.aerospace`（航天工业） | 航天发射中心 |
| `slot.faction`（阵营特色） | 对应阵营建造厂 / MCV（同样支持展开能力回退） |
| `slot.mecha`（机娘保障） | 机娘接口设施 |

- **非运转态严格过滤（`isResearchBuildingActive`）**：`researchSlots.ts`（L297–313）通过 `INACTIVE_RESEARCH_BUILDING_STATES` 排除 `'建造中'|'停机'|'受损'|'离线'|'被毁'|'战损'|'损毁'|'断电'|'瘫痪'|'摧毁'` 共 10 种状态——**受损、停机、断电、离线建筑在研究槽开通判定与 `deriveGlobalTechTier` 中均不再算在场**（特例兜底：零基地开局默认给 1 槽；无 `txn.base` 的旧档全局研究落入 `slot.main` 时，任一有效基地有运转中的 `超算中心` 也返回容量 `1`）。
- **全局并行门（含尤里院所扩展）**：计入 `deriveGlobalTechTier(bases)` 的基地须非失守/非废弃，T1=2、T2=4、T3 不限（仍受单槽容量 1 限制）。
  - `TECH_TIER_T2_ANCHORS`：`战斗实验室`、`红星实验设计局`（含综合体/苏联战斗实验室）、`基因测序与心灵谐振研究院`（含尤里作战/心灵研究实验室）。
  - `TECH_TIER_T3_ANCHORS`：`国家战略工程综合体`、`红星科学城`、`盟军联合科研与国家工程组织节点`、`量子超算中心`、`双螺旋生命工程与高维意识科学院`。
- **先回检后积分（`transactionEngine.ts`）**：`settleTransactions`（L450–530）已改为 **先做既成 `active` 的开槽/容量与全局并行上限回检，通过回检者才执行当楼 `Δt × eff` 积分**。失锚或超编项在消费当楼 `Δt` 之前即被 `demoteToQueued` 降格回 `queued`（保留已做工时，产出 `demoted` 事件），不会多吃当楼时间；同车道 `active` 项本楼跑满转 `settling` 且有剩余墙钟时间 `remWall > 0` 时，自动顺延给紧随其后的 `queued` 候列项（`BUG-R2-14`）。

## 3. 科研算力：名义总览与全战区预算回退

- **名义总览过滤非运转态**：`researchCompute.ts` 的 `aggregateCompute`（L95–128）已过滤 `废弃 / 失守` 基地且仅统计 `(b.state ?? '运转') === '运转'` 的建筑，受损、停机、建造中建筑不再进入名义供给。
- **单基地与无基地全战区算力预算**：
  - 显式绑定基地时，`computeBudgetForBase`（`settleFloorHelpers.ts` L421–432）先经 `resolveEffectiveBasePower` 融合副官电网加成与阵营磨合掉电修正，再对运转建筑求有效算力。
  - **无显式 `txn.base` 时不再归零（`FIX-P0-04`）**：`settleFloor.ts`（L429–434）调用 `computeBudgetForTheater`（`settleFloorHelpers.ts` L435–449），**自动汇总全战区所有非失守、非废弃基地的可用算力预算**。
- **双算力权重**：研究权重为 **TFLOPS 0.7 / TOPS 0.3**（`WEIGHT_SIMULATION`），满足比上限为 1，作用于两阶段推进（缺阶段比例时默认 50/50，`min_days_lock` 为总工期地板）。

## 4. 协议模型、9 座三阵营锚点与实验机制

存量协议定义、五态状态机（`undiscovered → locked → available → experimenting → active`，预留 `voided`）与旧档无损迁移已抽离至独立模块 `core/schemaMigration.ts`（由 `core/schema.ts` 重导出并在 `Schema.parse / safeParse` 入口自动执行），`protocols` 同时兼容 FD-30 协议线索对象。

### 4.1 双轴产点与苏/盟/尤三阵营 9 座核心建筑

`protocolAnchors.ts` 的 `PROTOCOL_ANCHOR_BUILDINGS` 收录 **9 座核心科研/算力建筑**：

1. **战地基础流**：`+0.10` 点/日。
2. **科研院所主轴（三阵营同系替代 + 跨阵营 50% 协同）**：
   - **苏联系**：T2 `红星实验设计局`（`+0.15`）→ T3 `红星科学城`（`+0.30`）；
   - **盟军系**：T2 `盟军战斗实验室`（`+0.15`）→ T3 `盟军联合科研与国家工程组织节点`（`+0.30`）；
   - **尤里系**：T2 `基因测序与心灵谐振研究院`（`+0.15`）→ T3 `双螺旋生命工程与高维意识科学院`（`+0.30`）；
   - **通用兜底**：仅当苏、盟、尤三系专属院所均不在场时，通用 `战斗实验室` 提供 `+0.15`；
   - **协同规则（`resolveProtocolPointBreakdown`）**：各阵营系内 T3 替代 T2（不叠加）；多阵营专属院所并存时，速率最高的一系按 `100%` 计入 `primaryInstituteRate`，**其余所有非零专属院所系均按 `PROTOCOL_CROSS_FACTION_SYNERGY_FACTOR = 0.5`（50%）折算累加至 `secondaryInstituteRate`**。
3. **算力副轴**：`超算中心`（`+0.10`）与 `量子超算中心`（`+0.25`，取高档不叠加）。

> **口径提示**：参谋部 `protocolDailyRateBonus` 加成在结算侧 `settleFloorPhases.ts`（L173–178）按乘法 `baseDailyRate * (1 + bonus)` 计算，而在面板侧 `PanelProtocol.vue`（L746–750）HUD 展示按加法 `baseRate + bonus` 计算。

## 5. 协议结算四步链与自动排程写通道闭环

```text
玩家点击协议厅排程/实验按钮 → protocolCommands 生成自然语言（要求 <事件> 回报协议排程/协议实验）
 → parseEventsAndPatches 解析发现 / 7种排程动作 / 实验声明
 → settleFloorProtocols 四步结算：
    步骤A：跨日产点 + 准入同步与在场自动启封
    步骤B：处理发现事件、排程事件（原地写 auto_queued / queue_order / hold）与手动实验
    步骤C：UTO 自动排程实验（正 Δt 下每楼最多候列首项一次，unlockedInStepB 防同楼重复）
    步骤D：归一与同楼快照落盘
```

原文档指出的“自动排程自然语言无落盘写通道”现已闭合：`buildProtocolScheduleCommand` 要求模型在 `<事件>` 输出 `协议排程` 声明，`parseEventsAndPatches.ts` 解析 `加入候列 / 移出候列 / 置顶 / 上移 / 下移 / 暂缓 / 恢复` 7 种动作，由 `settleFloorProtocols` 步骤 B 原地落盘 `auto_queued / queue_order (1..N) / hold`。
