# 00 · 共享底座与玩法运行链路

> 梳理日期：2026-10-28（基于 2026-10-14 初版演进更新）。本文是现有源码的架构说明，不替代原设计真源。
> 证据级别：静态调用链核查；本底座现同时覆盖传统 SillyTavern（Tavern Helper 角色脚本 iframe）与 TauriTavern（ABI v1 原生扩展 / 角色脚本双轨兼容）。本次没有执行真实宿主端到端操作；本文的“接通”仅指能在源码中追踪到调用，不代表真机通过。

## 1. 先建立正确的系统心智

本项目不是“点按钮即在本地扣钱造兵”的独立 RTS。它是 **聊天叙事驱动、程序约束结算、中控提供操作辅助与状态投影（辅以显式受控前端直写通道）** 的混合系统。

```text
世界书 / 有效目录 ──提供规则、资产定义、前置与参数──┐
                                                ↓
玩家查阅中控 → 生成指令文本填框 / 触发发送动作 / 开启即时调度直写
                                                ↓
     生成前馈：研究建议 / 战略态势与八维诊断 / 当前工程日程 / 委托摘要 + 预设提示词托管
                                                ↓
                       AI 叙事回复 + 结构化业务标签
                                                ↓
   解析声明(S1) → 结算(S2) → 对账(S3) → 工程与排产接缝(S4) → 守卫与过程量重放 → 本楼快照落盘(S6)
                                                ↓
       扫描最近有效 AI 楼 → 中控展示更新 + 楼层协议卡片双轨水合(ChatSurface / MutationObserver)
                                                ↓
       暂存档案受控入书 / 摘要自动确认 / 多阵营世界书自愈同步 / 管理工具人工审核与修复
```

这条链路有三个不能省略的边界：

1. **不同入口有明确分层的交互语义。**
   - **填框通道（`fillHostSendInput`）**：建造立项、工程指令、暗网/航天合同与多数楼层卡片快捷按钮写入 `#send_textarea`（失败时兜底 `/setinput`），由玩家确认发送；
   - **发送并触发生成通道（`sendAction`）**：日程托盘/AI 模式的调度动作、战略协议实验/排程等创建用户消息并 `/trigger` 正常生成；
   - **受控前端即时直写通道（`updateFloorVars`）**：日程 `instantMode`（默认开启）、建筑 `editMode`、PDA 情报采纳核销、数据流监控修复等显式调用 `updateFloorVars` 直接更新本楼变量，并在 `$timeline.opLog` 留痕供重解析幂等重放。
2. **AI 叙事不等于系统账本。** 需要正确的结构化标签和解析产物；规则引擎可能拒绝、隔离或告警。具体标签、判定门与例外见各玩法文档。
3. **引擎代码不等于宿主链路有效。** 有纯函数、有测试文件、有组件，仍需检查实际挂载和生产入口，再做真实宿主验收。

## 2. 四层责任划分与双宿主底座

| 层 | 职责 | 代表模块 | 不承担的责任 |
|---|---|---|---|
| 规则与资产定义 | 世界书内容、目录、参数、前置与动态定义 | 世界书、`useCatalog`、`catalogEffective`、`worldbookCatalogParser` | 文本规则存在不自动产生引擎能力 |
| 声明解析与结算 | 继承基线、解析标签、推进事务、对账并落盘 | `parsePipeline`、`useParse`、`settleFloor`、`settleFloorPhases` | 不负责界面视觉与玩家替代确认 |
| 中控操作与状态投影 | 查目录、看快照、拼装指令、双轨楼层卡水合 | `FloatingApp`、`ConsoleTopNav`、`ConsoleRadarScreen`、`ConsoleQuickActions`、`TagFilterBar`、11 个主 Modal、`TacticalPdaHost`、`storeAdapter`、`floorCardHydrator`（及 `ttChatSurfaceParticipant`） | 不绕过受控通道随意涂改业务账本 |
| 叙事资产、版本与宿主治理 | 暂存入档、补丁审核、摘要、预设托管、版本更新、备份恢复与双宿主桥接 | `expansionAutoFiler`、`girlAutoFiler`、`summaryRunner`、`presetPromptManager`、`cardUpdateEngine`、`saveBackupService`、`ttHostBridge`、`ttStorageAdapter`、`ttAgentDirector`、`ttSkillBundle` | 不替代生产、科研、经济结算 |

### 双宿主运行底座（SillyTavern + TauriTavern ABI v1）

- **双入口并存**：`index.ts` 作为长驻角色脚本入口；`ttExtensionEntry.ts` 导出幂等的 `activate() / deactivate() / isExtensionActive()` 作为 TauriTavern 原生扩展入口。
- **跨帧桥接与双宿主存储**：`host/ttHostBridge.ts` 是全工程唯一直接访问 `window.__TAURITAVERN__` 的网关（统一封装 `layout / chatSurface / extensionStore / worldInfo / agent / skill` 六大 API 与移动端 `applyMobileSurface`）；`host/ttStorageAdapter.ts`（`createDualHostStorage`）同步读写内存热缓存与 `localStorage`，在 TauriTavern 下异步落盘 `extensionStore` 并支持启动水合。
- **参谋部后台 Agent 与技能包**：`host/ttAgentDirector.ts` 幂等注册 `ghq-tactical-staff` Profile（封装科研建议、工程日程、战局简报与战术检定四类后台任务及 `legacy-fallback` 降级）；`host/ttSkillBundle.ts` 管理内置 `.ttskill` 条令技能包；`host/ttHostSimulator.ts` 提供带防覆盖真机守卫的高保真模拟器。

## 3. 消息快照、聊天元数据与视图状态

### 3.1 消息楼层是业务快照载体

`useParse.runParseFor` 从目标楼原文读取输入，向前找基线，调用 `parseMessageText`，随后进行结算和对账，最终写本楼消息变量中的 `stat_data`：

- **基线扫描与展示扫描分层**：`scanBaseline` 找既有 `stat_data` 基线；`floorScanner.ts` 的 `scanLatestValidFloor` 与新增的 `scanLatestFloorPair`（同时返回最新有效楼 `current` `#N` 与上一有效楼 `previous` `#N-1`）逐楼迁移并做 `Schema.safeParse`，跳过用户楼、隐藏楼、无数据或不合法的楼。
- **`#0` 楼开局防归零保护（`hydrateZeroFloorFromBoot`）**：当处于 `#0` 楼且 `$boot` 已保存开局选择时，自动从 `$boot` 水合 `#0` 楼 `stat_data`，防止 `scanBaseline(-1)` 返回空把开局资产洗白为默认值。
- **未开局锁死门控（`isPreLaunchLocked`）**：`useFloatingStore.ts` 在 `#0` 楼尚未完成开局确认前锁死除 `settings / dataflow / card-update` 外的战术弹窗，并通过跨帧 `postMessage`（`'ra-boot-state-changed'`）实时同步 `$boot.confirmed` 与阵营主题。

### 3.2 聊天级元数据账本不等于世界内资产

聊天域变量与消息楼层 `stat_data` 严格分层：
- `$parse`：保存解析幂等指纹（原文 `hash` + `swipe_id`）、隔离、告警与报告。
- `$timeline`（`timelineLedger.ts`）：记录分支档案世界书绑定、世界书变更日志 `wbJournal`、以及按 `(floorId, swipeId)` 分槽的**玩家交互过程量 `opLog`**（排产批准 `COMMIT_PLANNING`、时序裁决、YAML 修复、数据补丁裁决 `PATCH_DECISION`），供重解析时经 `replayFloorProcessOps` 幂等重放。
- `$boot`（开局状态与种子）、`$dlc`（DLC 覆盖层注册表）、`$promoted`（已提升独立私产书注册表）、`$archive`（动态正史索引）、`$save_schema`（`saveBackupService.ts` 维护的存档代数，当前 `CURRENT_SAVE_SCHEMA = 2`）。

### 3.3 中控视图与双 Teleport 宿主

- **只读 Store 适配器**：webpack 仅对中控入口把 `composables/store.ts` 精确 alias 到 `host/storeAdapter.ts`（深拷贝快照，防止本地视图交互污染源数据）。
- **双跨帧 Teleport 宿主（`host/modalHost.ts`）**：
  1. `OVERLAY_HOST_ID`（`tavernweave-tactical-modal-overlay`，`z-index: 10000`）：承载 `DetailDrawer` 与 **11 个主模态/面板**（`ModalTechTree`、`ModalMechaGirl`、`ModalArchive`、`ModalSchedule`、`ModalResources`、`ModalEngineering`、`ModalBuildings`、`PanelDataPatches`、`ModalSettings`、`ModalDataFlowInspector`、`ModalCardUpdate`），并由 `host/modalErrorGuard.ts`（`useModalErrorGuard`）在子树渲染抛错时自动回退收起遮罩。
  2. `HUD_HOST_ID`（`tavernweave-hud-host`，`z-index: 9995`）：常驻战术 HUD 伴生宿主，通过 `syncHudHostGeometry` 将物理包围盒精确贴合至 `TacticalPdaHost` 当前尺寸（纽扣 `44×44` / 展开 `320×440`），外部零遮挡酒馆界面。
- **三层顶栏与三环雷达屏**：`ConsoleTopNav.vue` 集成阵营铭牌/`PRE-LAUNCH`/`DEV`/PDA召回/新版升级胶囊、暴露度（`EL-0~EL-4`）与民心五阶双指标栏、以及 `档案 / 日程 / 资源 / 建筑` 四等宽主导航；`ConsoleRadarScreen.vue` 提供 MCV 原点 `(0,0)` 三环防务雷达圆盘与实时建筑光点投影（合并在建队列 `effectiveBuildings` 并支持退役基地折叠查阅 `CTRL-RETIRE-01`）。

## 4. 生产热路径：六阶段追踪与真实执行顺序

### 4.1 楼层观察者与世界书自愈（`host/floorObservers.ts`）

`installFloorObservers` 监听生成完成、`MESSAGE_SWIPED`（先执行 `reconcileSwipeWorldbookTransition`）、编辑、`MESSAGE_DELETED`（先执行 `reconcileDeletedFloorsAbove` 对账删楼水位线）与 `CHAT_CHANGED`（先执行 `ensureBranchWorldbookIsolation` + `finalizeBranchWorldbookCloneIfNeeded` 分支档案书克隆隔离）。`inFlight` 单飞锁按 `${chatKey ?? ''}#${messageId}` 隔离。

每次 `parseAndRefresh` 完成后自动串联：
1. `autoConfirmPendingSummariesIfEnabled`：默认开启时自动将 `pending_summaries` 归档写入聊天世界书并经 `updateFloorVars` 核销；
2. `syncMultiFactionWorldbooksOnFloorEvent`：从快照提取 `unlocked_factions`，经 `collectAndRestoreChatOwnWorldbooks` 自愈恢复当前聊天专属世界书，重绑多阵营四书，并通过 `syncEngineeringWorldbookEntriesInHost` 同步工程条目开关。

### 4.2 `useParse.runParseFor` 六阶段真实顺序（`S0_BASELINE` ~ `S6_COMMIT_FEED`）

1. **S0 基线与身份门**：校验 `expectChatId` 与 `$parse.done`（`hash + swipe_id`）幂等；扫描基线 `scanBaseline`（`#0` 楼走 `hydrateZeroFloorFromBoot`），预热一次有效目录快照 `catalogSnap`。
2. **S1 解析声明（`parseMessageText`）**：提取 `<战况>`、`<队列>`、`<部署>`、`<事件>`、`<工程>`、`<排产计划>`（`deferPlanningCommit: true` 延迟入队）、`<阵营解锁>`、`<航天合同>`、`<暗网>`、`<数据更新>`、`<摘要>`/`<中摘要>`/`<大摘要>` 等增量与声明。
3. **S2 结算前参谋/阵营预处理 + 主结算（`settleFloor`）**：
   - 先执行副官事件声明 `applyAdjutantEventDeclaration` 与阵营解锁结算 `applyFactionUnlockSettlement`（含唯一首发 MCV 防刷锁，`settleFloorPhases.ts`）；
   - 再调用 `settleFloor`（`settleFloor.ts` L367–1277），按序推进：① 解析三来源 `Δt` + 清理上楼残留终态队列 + 新建队列去重与工期回填；② 本楼新建零进度 `queued` 项 **0 分钟空闲产线预升格** + `settleWithTwoStage` 二阶段推进与纳米库存实扣（`S2i_NANITE_STOCK`）；③ 建造满进度转正 + **满工时系统主权自动完工交割 `autoSettleCompletedQueues`**（`S2d_BUILD_COMM`）；④ 双模切换与部署结算（`S2e_DEPLOY_MODE`）；⑤ 航天合同与入轨回款结算 `settleSpaceOperations`（`S2g_SPACE`）；⑥ 工程里程碑同步 `syncProjects` 与基地电网动态重算 `recomputeBasePowerFromCatalog`；⑦ 资金链三轨结算、电网断供钳制与天候视图 `settleChainsDeltaT`（`S2f_CHAINS_GRID`）；⑧ 跨维暗网与多元建筑被动现金流结算 `tickDarknetAndPassiveEconomy`（`S2h_DARKNET_ECON`）；⑨ 协议四步结算 `settleFloorProtocols`（`S2b_PROTOCOLS`）与游戏日历 `clock` 写入；⑩ 联席参谋部切片 `settleCommandHQSlice` 与暴露度/民心结算（`S2a_COMMAND`）；⑪ R26/R27 交叉校验与陈旧排产驳回清理。
4. **S3 生产对账与工程补同步（`reconcileProduction`）**：合并 `<生产>` 与操作完成声明执行三色对账（`autoSettleRemaining: true`），随后**立即补跑一次 `syncProjects` + `recomputeBasePowerFromCatalog`**，确保当楼竣工阶段可被同楼后续 `<工程>` 令立即感知。
5. **S4 尾置双接缝（`applyEngOrders` + `commitPlanningIntent`）**：依次结转本楼新 `<工程>` 令与 `<排产计划>` 意图，保证新立项/新排产以 `spent_minutes = 0` 入队，不倒吃本楼已流逝的 `Δt`。
6. **S5/S6 守卫复核、过程量重放与落盘**：写前复核聊天/Swipe 身份，执行 `$timeline` 过程量幂等重放 `replayFloorProcessOps` 与 0 分钟空闲升格 `promoteIdleQueuesAtZeroDelta`，写入本楼 `stat_data` 与 `$parse` 并刷新中控。

### 4.3 UTO 是演进接缝，不是已全面替换的主循环

`engines/settleFloor.ts` 导出 `orchestrateFloorTasks` 与 `tickTaskOrchestrationEquivalentToSettleFloor`；`useParse` 主热路径调用的 `settleFloor` 已接入 `LaneRegistryHub` 统一提供工位键、加速系数、局部并行上限与全局上限，最终推进仍调用 `settleWithTwoStage`。

## 6. 前馈注入与预设提示词托管（4 Runner + 1 Manager）

`index.ts` 在启动时挂载并在卸载时拆除：
1. `createAdvisoryRunner()`（`advisoryRunner.ts`）：注入 `redalert_research_advisory` 11 槽科研建议；
2. `createStrategicFeedforwardRunner()`（`advisoryRunner.ts`）：注入 `STRATEGIC_FEEDFORWARD_INJECT_ID` 战区全局态势与八维组合诊断；
3. `createScheduleRunner()`（`scheduleRunner.ts`）：注入《当前工程日程》前馈；
4. `createSummaryRunner()`（`summaryRunner.ts`）：在 `delegate_main` 模式下注入 `redalert_summary_delegation_feed` 委托主模型顺带输出 `<中摘要>` / `<大摘要>`；
5. `getSharedPresetPromptManager()`（`presetPromptManager.ts`）：自动关闭预设内冲突“摘要/总结”条目、插入 `rac_preset_cot_augment_v1`、在 TT Agent 模式下管理四阶段提示词，并注册跨角色卡自动还原守护脚本 `RAC_CONSOLE_GUARD`。
